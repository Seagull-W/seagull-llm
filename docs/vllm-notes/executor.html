1. get_class ​

python
@staticmethod
def get_class(vllm_config: VllmConfig) -> type["Executor"]:
    executor_class: type[Executor]
    parallel_config = vllm_config.parallel_config
    distributed_executor_backend = parallel_config.distributed_executor_backend
    # distributed_executor_backend must be set in VllmConfig.__post_init__
    if isinstance(distributed_executor_backend, type):
        if not issubclass(distributed_executor_backend, Executor):
            raise TypeError(
                "distributed_executor_backend must be a subclass of "
                f"Executor. Got {distributed_executor_backend}."
            )
        executor_class = distributed_executor_backend
    elif distributed_executor_backend == "ray":
        if envs.VLLM_USE_RAY_V2_EXECUTOR_BACKEND:
            from vllm.v1.executor.ray_executor_v2 import RayExecutorV2

            executor_class = RayExecutorV2
        else:
            from vllm.v1.executor.ray_executor import RayDistributedExecutor

            executor_class = RayDistributedExecutor
    elif distributed_executor_backend == "mp":
        from vllm.v1.executor.multiproc_executor import MultiprocExecutor

        executor_class = MultiprocExecutor
    elif distributed_executor_backend == "uni":
        from vllm.v1.executor.uniproc_executor import UniProcExecutor

        executor_class = UniProcExecutor
    elif distributed_executor_backend == "external_launcher":
        # TODO: make v1 scheduling deterministic
        # to support external launcher
        executor_class = ExecutorWithExternalLauncher
    elif isinstance(distributed_executor_backend, str):
        executor_class = resolve_obj_by_qualname(distributed_executor_backend)
        if not issubclass(executor_class, Executor):
            raise TypeError(
                "distributed_executor_backend must be a subclass of "
                f"Executor. Got {executor_class}."
            )
    else:
        raise ValueError(
            f"Unknown distributed executor backend: {distributed_executor_backend}"
        )
    return executor_class

3. roughly analysis ​

  1. 分布式通信基座（抽象核心） collective_rpc：这是唯一的抽象通信方法，也是所有子类必须实现的核心。它定义了“如何向所有 Worker 发送指令”。 为什么基类不实现它？ 因为在单进程（UniProcExecutor）中，它是直接本地函数调用；在多进程（MultiprocExecutor）中，它需要序列化数据并通过 ZMQ/Ray 发送。实现方式截然不同。

  2. 模型编译与显存准备（启动阶段） initialize_from_config：分配 KV Cache 显存 + 触发模型预热/编译（你刚问过的方法）。 determine_available_memory：询问每个 Worker 还有多少可用显存（用于动态调整批处理大小）。 get_kv_cache_specs：获取每个模型层对 KV Cache 的形状要求（用于计算显存分配方案）。

  3. 核心推理执行（运行阶段） execute_model：执行一次推理迭代（前向传播）。基类已实现标准逻辑：调用 collective_rpc("execute_model") 并只取第一个 Worker 的结果（因为 TP 下只有 Driver Worker 返回最终 Token）。 sample_tokens：专门用于推测解码（Speculative Decoding）的独立采样步骤。 take_draft_token_ids：获取草稿模型生成的候选 Token。 execute_dummy_batch：执行一次“假推理”（用于预热 CUDA Kernel 或填充显存以消除碎片）。

  4. 生命周期与设备管理（运维阶段） sleep / wake_up：卸载/恢复显存中的模型权重和 KV Cache，实现“显存腾挪”。 profile：启动/停止 PyTorch Profiler，用于性能调优。 check_health：检查 Worker 是否存活且响应正常（用于 Kubernetes 探针）。 shutdown：释放所有 Worker 的 GPU 资源并终止子进程。

  5. 高级特性支持（扩展阶段） LoRA 管理：add_lora、remove_lora、pin_lora、list_loras——动态加载/卸载 LoRA 适配器。 多模态缓存：reset_mm_cache、reset_encoder_cache——清理图像/视频特征缓存。

4.1 AsyncOutputFuture ​

python
class AsyncOutputFuture(Future):
    def __init__(self, async_output: AsyncModelRunnerOutput, single_value: bool):
        self.async_output = async_output
        self.single_value = single_value
        super().__init__()

    def result(self, timeout=None):
        if timeout is not None:
            raise RuntimeError("timeout not implemented")

        if not super().done():
            try:
                output = self.async_output.get_output()
                self.set_result(output if self.single_value else [output])
            except Exception as e:
                self.set_exception(e)
        return super().result()

4.1.1 AsyncModelRunnerOutput ​

它持有 GPU 计算产出的张量在显存中的位置，以及用于管理数据搬运的 CUDA 流（Stream）和事件（Event）。

当GPU计算流完成后，copy_stream流触发D2H复制，将显存数据从GPU复制到主机内存。

get_output方法用于获取复制完成的张量数据，当数据还未传输完成时，进行同步等待，阻塞线程直到DMA拷贝结束。最终返回一个填充了CPU数据的ModelRunnerOutput对象。

4.1.2 ModelRunnerOutput ​

见vllm/v1/outputs.py，内部有请求索引，每个请求生成的token id，生成token的对数概率，prompts的对数概率等。

4.1.3 Other ​

AsyncOutputFuture类是Future类的子类，用于异异步获取模型推理结果。

Future 是一个“空盒子”，专门用来存放将来才会出现的结果，并且自带“状态机”（Pending 进行中 / Finished 已完成 / Cancelled 已取消）。

重写了 .result() 方法。当 EngineCore 首次调用时，它才去调用 self.async_output.get_output()，拿到数据后调用 self.set_result(...)，将“空盒子”填满。

一旦填满，_state 变为 FINISHED。后续再调用 .result() 会直接返回缓存结果，不会再触发 get_output()。（super().done()==True）

4.3 collective_rpc ​

python
def collective_rpc(  # type: ignore[override]
    self,
    method: str | Callable,
    timeout: float | None = None,
    args: tuple = (),
    kwargs: dict | None = None,
    non_block: bool = False,
    single_value: bool = False,
) -> Any:
    if kwargs is None:
        kwargs = {}

    if not non_block:
        result = run_method(self.driver_worker, method, args, kwargs)
        if isinstance(result, AsyncModelRunnerOutput):
            result = result.get_output()
        return result if single_value else [result]

    try:
        result = run_method(self.driver_worker, method, args, kwargs)
        if isinstance(result, AsyncModelRunnerOutput):
            return AsyncOutputFuture(result, single_value)
        future = Future[Any]()
        future.set_result(result if single_value else [result])
    except Exception as e:
        future = Future[Any]()
        future.set_exception(e)
    return future

python
def run_method(
    obj: Any,
    method: str | bytes | Callable,
    args: tuple[Any, ...],
    kwargs: dict[str, Any],
) -> Any:
    """
    Run a method of an object with the given arguments and keyword arguments.
    If the method is string, it will be converted to a method using getattr.
    If the method is serialized bytes and will be deserialized using
    cloudpickle.
    If the method is a callable, it will be called directly.
    """
    if isinstance(method, bytes):
        func = partial(cloudpickle.loads(method), obj)
    elif isinstance(method, str):
        try:
            func = getattr(obj, method)
        except AttributeError:
            raise NotImplementedError(
                f"Method {method!r} is not implemented."
            ) from None
    else:
        func = partial(method, obj)  # type: ignore
    return func(*args, **kwargs)

4.5 ExecutorWithExternalLauncher ​

可以把 ExecutorWithExternalLauncher 理解为 vLLM 为了兼容 torchrun 生态而开的 “后门模式”：

  • 拓扑结构：N 个独立的 Python 进程（由外部启动），每个进程绑定一张 GPU，通过 torch.distributed 组成一个逻辑上的“世界组”。

  • 确定性调度（Deterministic Scheduling）：当调度确定时，所有引擎生成相同输出，无需同步状态。这意味着每个进程的调度器独立运行，因为输入完全一致且算法确定，它们会做出完全相同的调度决策，因此各自分到的批次也是相同的。这就避免了在每个 step() 后广播 SchedulerOutput 的巨大开销，显著提升了大规模 TP 推理的扩展性。

  • 适用场景：如果你在使用 Slurm 或 Kubernetes 启动多机多卡任务，且希望 vLLM 只作为一个“被动计算单元”被调度，那么这就是最适配的执行器。
