Echo Chamber：强化学习会放大哪些预训练行为？ ​

同样用 PPO 做 GSM8K，150M 模型逐渐把解答写成 Python 函数，1B 模型却转向自然语言。两者用过相同的预训练配方。作者沿训练过程同时追踪两件事：模型更常采用哪种解法，以及采用这种解法时能答对多少题。

COMMENT · 阅读手记

最大的特点是在受控预训练模型下探索RL的具体表现，预训练模型确实是后训练的重要混杂因素，当前的方法过度依赖（无奈之举）于不透明的模型。缺点也很明显，自行训练模型有很大的局限性，很难规模化，希望之后能有完全开源的中小模型。

为什么要从零预训练 ​

直接在现成基座上做强化学习（RL），可以测出后训练前后分数相差多少，却很难判断新出现的解法在预训练时出现过多少次。如果基座的训练配方不透明，即使两个模型采用同一种 RL 算法，它们之间的差异也可能来自预训练。

作者从零训练模型，把几种解答风格不同的公开数学数据集按已知比例混合，再用相同的数学题做后训练。这样，训练前就知道模型见过哪些格式，还能单独改变某一种数据的重复次数，观察后续 RL 会放大哪种行为。论文 §1

实验设置与三种解答格式 ​

作者用 OLMo 代码库训练了 150M 和 1B 两种规模的解码器模型。基础数学语料包括 FineMath-3+ 和 Proof-Pile-2 中的 Algebraic-Stack。三种指令数据以题目和解答直接拼接的形式混入语料。文中的 4× 表示将该数据集重复使用四遍。预训练采用 AdamW，峰值学习率为 0.001，权重衰减为 0.1，线性预热 5,000 步后按余弦曲线降至峰值的 10%。§2.1

三组数据都包含数学题，区别在于答案留下了不同的格式标记。下面按附录 B 的原题重排问答框，题面译为中文，解答保留用于识别格式的部分。

TinyGSM：把题目写进 Python 函数 ​

这组数据有 1,230 万对合成问答，来自 GSM8K 与 GSM-IC 的训练子集，代码解答由 GPT-3.5 生成。作者通过函数签名识别这种格式，执行代码取得数值，并另行记录文档字符串是否复述了原题。附录 B.1

题目
橙子每个 0.75 美元。Benjamin 带了 18 美元，结账时还差 9 美元，朋友替他补齐。他买了多少个橙子？
解答
def simple_math_problem() -> int:
    """橙子每个 0.75 美元，带了 18 美元，还差 9 美元。买了多少个？"""
    total_cost = 18 + 9
    result = total_cost / 0.75
    return result

执行结果为 36。

RL 微调与评测口径 ​

PPO 与 GRPO 使用可验证的 0/1 奖励，最终答案与标准答案匹配就得 1 分。另一种对照是专家迭代（EI）：每题采样 64 个解答，筛出答对的、去重，再用它们监督微调初始基座。以下主要分析 PPO，训练问题来自 GSM8K 训练集，图中成绩取自测试集。§2.2–3

读图时要区分某种格式占输出的比例与只看这种格式时的正确率。全体回答的三个指标也各有含义：本文的 pass@1 使用一次贪心解码；pass@64 看温度 0.7 下采样 64 次能否至少答对一次；majority@64 看这 64 次中最常见的答案是否正确。附录 B.4

PPO 如何改变解答格式 ​

在同时接触过三种指令数据的 150M 模型上，训练刚开始时三种格式都能采样到。一个 epoch 内，TinyGSM 风格的 Python 函数几乎占据全部输出。同期单次作答的正确率明显上升，但到训练末期，64 次采样至少答对一次的比例略有下降。§3.1，图 2

在同一基座上，把 KL 惩罚系数从 0.001 提到 0.01，策略偏离初始模型的代价变大。图 3 中仍有一部分回答采用自然语言，最终 pass@1 与图 2 接近，pass@64 也较稳定。附录 G 从另一个角度核对了格式偏好：不同格式起始 token 的平均概率同样发生了偏移。§3.1，图 3

改变数据配比后的反例 ​

图 4(a) 提供了一个反例。微调开始时，OpenMathInstruct1（OMI1）风格约占 62%，TinyGSM 约占 28%，模型却在第一个 epoch 内转向 TinyGSM。初始时更常生成的格式，并不一定会成为最后占主导的格式。§3.2

在图 4(b) 中，作者将预训练中 OMI1 的用量翻倍。初始生成比例和图 4(a) 相近，起初仍是 TinyGSM 风格的答案更准确，但 PPO 最终几乎只生成 OMI1 风格，整体成绩低于图 4(a)，并在训练末期继续下滑。作者将此视为一种失败模式。多数 150M 实验中，RL 确实偏向初始正确率较高的格式；这组对照说明，单看初始正确率也无法完全预测训练走向。图 4 及正文

同一种格式内的进步 ​

前两组结果留下一个问题：即使输出全部采用同一种格式，RL 还能让模型做对更多题吗？作者先将 TinyGSM 在预训练中分别重复 1、2、4、8 遍。图 5 左比较各次运行在 PPO 期间取得的最好成绩，右边则保留 pass@1 的训练曲线。重复次数最多的模型既取得最高的最终 pass@1，从起点到终点的提升也最大。§3.3，图 5

更直接的检验是把其他数据全部拿掉。作者只用 4× TinyGSM 从零预训练一个 150M 模型，连 FineMath-3+ 和 Algebraic-Stack 也移除。做 PPO 后，pass@1 仍然上升。随着训练进行，生成函数更常在文档字符串中复述题意，引号写法也更一致。在只有一种预训练来源时，模型仍能改进这一格式下的输出；图中观察到的书写习惯与准确率同步变化，尚不能据此断定引号本身提高了正确率。图 6

模型规模与格式偏好 ​

最后一个对照固定预训练配方，改变模型规模。图 7 的 1B 模型与图 2 的 150M 模型接触了同一混合数据。尽管 1B 模型起初的 TinyGSM 格式正确率更高，且自然语言占比最低，PPO 最后仍把自然语言推到了主导地位。其他配方中，1B 模型也可能偏向 OMI1 风格的代码。§3.4，图 7

作者推测，较大的模型更有能力用自然语言完成计算，较小的模型可能更依赖结构简单、可执行的代码。这里直接观察到的是格式偏好随规模改变；关于原因的解释仍是作者的推测。§3.4
