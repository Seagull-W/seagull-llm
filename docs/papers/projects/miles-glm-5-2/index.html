Miles GLM-5.2：终端 Agent 的大型异步 RL 参考运行 ​

资料快照：本组后训练项目资料整理截至 2026-10-11；文中的运行状态、访问结果和未核验项均以该次归档为准。

1. 研究对象、规模与版本 ​

对象是 Miles 团队公开的 GLM-5.2 744B-A40B 参考实验。2026-08-18 的作者工程文章报告 64 GB300，训练/rollout 各 32 卡，65k context、batch 64、100 rollout steps。它是具体模型上的训练实验；材料没有覆盖 GLM-5.2 基础模型自身的全部后训练。

本轮同时读取了当前 main 的 README、Python recipe和 Slurm launcher。抓取日及 hash 已保存，历史实验 SHA 尚未核验。文章中的推理 TP8 与当前默认 DP-attention 配置需要分别保留。

2. 数据 → 环境 → reward ​

训练任务来自 terminal-bench-2 checkout。数据生成器将任务整理为 JSONL，metadata.task_id 选择对应任务目录及镜像；评测需使用不相交的 held-out task set。每条 episode 在独立 Daytona sandbox 中执行终端任务，以任务的 tests/test.sh 评分。recipe 连接 agent function、reward hook 与 aborted-sample filter。README、recipe

依赖需要逐层准备：Miles/SGLang 运行镜像、OpenEnv checkout 的 editable 环境包、任务定义、模型的训练分片与 FP8 推理格式、Megatron disk-streaming checkpoint hooks、Daytona 配额。原运行的数据 manifest、全部题目和过滤后样本尚未取得；本轮未核验该实验另有 SFT 或偏好训练阶段。

4. 分布式布局与启动路径 ​

当前 README 为 16 节点×4 卡：8 个训练节点采用 TP2/CP4/PP4/EP8，8 个推理节点运行 FP8 DP-attention engines。训练 DP1 的 optimizer state 未按 DP 分片，依赖 node-local disk streaming。Slurm 负责节点和容器，Ray 负责进程资源；launcher 将实验参数交给 Python recipe。README、launcher

启动前需匹配 compute-fabric 地址、共享挂载、node-local scratch 和模型格式。launcher 明确指出：误用管理网地址可能让 Ray 启动静默卡住，worker 首次连接过早也可能失败，因此脚本会重试加入。模型预置本地磁盘用于减少 engine 重启时的 NFS 读取等待。
