3. 其他领域的差异 ​

General 必须配置 judge URL/key；默认模型名是脚本配置，不是证明生产 grader 使用同一模型。启动器将 reward 二值化阈值设为 1，开启 length penalty 与 infra sentinel；环境 setup3600s、trajectory1200s、reward timeout0 要结合实现解释。General 启动器

Cyber 默认 off-policy 阈值8、drop，启用 infra 从 group 剔除；environment setup900s、trajectory28800s。与 Code 的阈值2或 General 的时间预算不通用。Cyber 启动器

Visual 默认 temperature0.6/top-p0.95/top-k20，训练和评测 grader 参数分开；Music 则特意不指定这三项，以继承下层默认。给 Music 随手复制 Visual 采样参数会改变原参考实验。Visual、Music 环境

4. 复现推进顺序 ​

这是整理建议，不是已经跑过的结果：固定父仓库/submodule revision与镜像 → 获取 9B SFT 模型和目标领域数据 → 确认环境/grader 依赖 → resolved config 预检 → 参考正确答案/失败答案评分检查 → 单 group rollout 捕获 → 固定轨迹的单更新 → 保存/恢复短跑 → 小规模 benchmark → 扩并发与节点。

每一步应留下可审阅产物。数据、镜像、源码开放并不消除 GPU、Pod、grader API 和外部依赖的资源需求。
