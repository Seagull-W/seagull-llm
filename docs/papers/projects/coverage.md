## 2. 同一套全链路检查项

每份档案都检查：目标与模型起点 → 数据生产与切分 → 环境与 verifier → SFT/偏好/蒸馏阶段 → RL 算法与 loss 实现 → rollout、批次与权重版本 → 并行与调度 → 监控、性能与损失 → benchmark → 故障、修复与恢复 → checkpoint、发布与反馈。

未知项明确写出“本轮未核验”；项目未使用的阶段需有来源才能标为“不适用”。同一框架的当前默认值不能替代某项目的历史配置。档案篇幅不强行一致，但每个项目都保留自己的检索缺口。

## 4. 后续检索如何推进

每个项目独立沿官网、作者帖子和回复串、仓库、模型/数据卡、看板、Issue、PR、报告附录追踪；先取得该项目自己的完整路径，再做跨项目比较。检索顺序根据可访问入口和待核验问题安排，已在一个项目中找到某个环节的资料，不会结束对另一项目同一环节的搜索。

新项目满足证据条件时直接加入目录并建立档案，不设固定数量上限。框架的通用功能保存在工程专题；发现框架背后的具体运行时，以那次运行独立建档。
