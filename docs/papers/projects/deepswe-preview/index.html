资料快照：本组后训练项目资料整理截至 2026-10-11；文中的运行状态、访问结果和未核验项均以该次归档为准。

1. 对象、规模与版本 ​

对象为 2025-07 发布的 DeepSWE-Preview。作者说明以已有 Qwen3-32B 为起点，约 4,500 个 R2E-Gym 任务、64 H100、六天 RL；“RL only”指该项目的训练阶段。作者文章 它与 2026 年 DeepSWE benchmark 是不同对象。

本轮读取作者文章、rLLM SWE README、数据准备、训练脚本及评测指南。当前 main 的版本和历史 run 需要分别记录。

2. 数据、环境与反馈信号 ​

R2E-Gym 将代码任务与独立镜像连接，Agent 使用 Bash、搜索、编辑、提交工具，环境返回执行观察。作者过滤了与 SWE-Bench Verified 同仓库的训练任务；训练 reward 为受限时间内选定测试通过的 0/1 结果，训练测试限时 5 分钟，官方评测限时 30 分钟。作者文章

数据准备脚本注册 R2E-Gym 子集与 SWE-Bench Verified；没有预期 train/test 时会使用首个 split。复现需检查实际数据集内容、仓库交集和版本，不能只用 split 名称证明无污染。数据准备代码 完整原始训练任务清单及每题过滤记录尚未取得。

3. 算法与更新配置 ​

作者将配方称为 GRPO++，包含多轮 observation mask、clip high、无 KL/entropy loss、leave-one-out 与 compact filtering。后者屏蔽达到上下文、步数或时间边界的非正常完成轨迹；失败实验和消融有助于解释其选择。作者文章

4. 分布式与环境调度 ​

GPU 训练之外还有容器供给集群。作者记录大批并发容器使 Docker API/dockerd 崩溃，随后用 Kubernetes 分摊环境执行并预置镜像；这给出了实际故障—架构调整的链条。作者文章

README 的复现资源约束包括至少 64 GPU 和 512 个并发容器。训练进程、Kubernetes worker、镜像磁盘与评分任务分别需要容量规划；原始 Ray/Slurm 提交文件、GPU/CPU 节点完整拓扑和逐步利用率未核验。README

6. 报错、失败实验与恢复 ​

已找到 dockerd 过载、轨迹边界处理及不成功的 SFT/数据选择尝试等作者反馈入口。作者文章 接下来需要原始实验 ID、失败日志和对应曲线，才能精确比较这些尝试；不将“未改善”泛化为 SFT 或某数据集普遍无效。

当前脚本保存 cadence 可见，完整恢复机制、optimizer/scheduler/RNG/环境状态的保存以及原 run 重启事件尚未核验。save_freq=10 不能证明每种状态都可恢复。可先固定 rollout 做代码核对，但本轮未执行 GPU 实验。
