# agent 的账不该记在模型头上：固定模型后，harness 与环境各能改动什么

模型已经固定，agent 却仍在越权操作、反复查资料，或花了很多 token 也没有完成任务。下一步是改 harness、重组环境，还是换更强的模型？先看最终回答和总分，很难做这个决定：回答可能否认已经执行的动作，耗时很长的重试也可能被判作合理探索。

**我会先让实际动作、返回状态和逐次调用用量对齐，再按主导故障选择改动。** 规则在执行时被越过，先检查控制路径；多个任务反复获取同一批信息，再考虑环境表示；接口正常、资料可得后仍做不出判断，才把模型升级重新放回比较。这里的 harness 指组织上下文、工具调用与执行检查的脚手架，环境表示则决定资料以什么形式交给 agent。

这个排查顺序来自现有实验中的故障机制，是工程建议，不是几种改法在同一部署上的统一对照结论。判断单位至少是 model–harness；共享资料也能修改时，还要记上 environment 和运行预算。

## 先定位无效执行，再决定是否压缩 reasoning

判断是否该改 harness，先看失败是不是由接口制造的。《How Do AI Agents Waste Your Money?》给出了一组具体对照：同一 Kimi-K3、同一 reasoning effort 下，受测 harness 会诱发不同的动作与浪费结构。具体故障包括启动了错误的 Python 环境、暴露了运行时不接受的 timeout 参数，导致导入失败或重试；另一个“先凭记忆写出原项目修复，再放弃”的模式却跨 harness 出现，更像模型与任务共同造成的绕路。前者应修执行接口，后者则需要继续排查模型与任务。[§7.1–7.2](https://arxiv.org/html/2611.07238v1)

浪费率本身还会漏账。关闭网络后，agent 反复安装依赖、寻找替代访问路径，输出更多，测得的浪费比例却更低，因为裁判把许多重试视为局部合理的探索。任务已经难以继续时，局部文本仍可能“不可删”。harness 若能识别不可用能力、把约束明确交给模型，并在重试不再改变状态时停止，就能避免继续付费；这时应该减少的是无望的执行。[§7.3](https://arxiv.org/html/2611.07238v1)

要解释这种现象，需要区分两类成本。该研究将不同 provider 的完整轨迹统一表示，由 LLM 裁判标出可删片段，再映射回原轨迹统计 token：重复已知信息、重复获取未变的信息和无用铺垫属于严格浪费；尝试时合理、事后才知道没用的探索属于 detour。后一类在尝试时有理由继续，减少它需要更好的信息或决策。[§2](https://arxiv.org/html/2611.07238v1)

局部内容是否多余，可以通过删后恢复执行来检验。研究在指定位置删掉已标记的内容，恢复执行，检查任务结果和下一步动作是否变化。在线实验则只删当前上下文足以判断的复述与铺垫：先生成 reasoning，裁判标记并删除，再让模型基于压缩后的 reasoning 重新生成回复和工具动作，随后继续执行。[§4.1–4.4](https://arxiv.org/html/2611.07238v1)

| Kimi-K3 在线干预 | SWE-bench Verified：删去 reasoning / 成功率 | MCP-Atlas：删去 reasoning / 成功率 |
| --- | ---: | ---: |
| 不删除 | 0% / 89.0% | 0% / 65.0% |
| 删除复述与铺垫 | 41% / 89.5% | 46% / 62.3% |
| 删除全部 reasoning | 100% / 73.0% | 100% / 56.0% |

来源：[表 3](https://arxiv.org/html/2611.07238v1)。两项实验都保留先前轮次的 reasoning 供后续上下文使用，且 Kimi-K3 暴露完整推理文本。41%–46% 的分母是受干预的 reasoning，既不是全部输入输出，也不是总账单。生成这些片段的计算已经发生，在线裁判和重新生成动作还要付费；这项实验直接验证的是内容可删性，净节费还需要另算。

在线删减在 MCP-Atlas 上损失了 2.7 个百分点。在另一项恢复执行实验中，第一轮之后删除已标记内容，使 MCP-Atlas 成功率从 75.3% 降到 65.6%；较晚位置的干预影响较小。删减收益依赖任务、时点和上下文保留方式，把全部历史 reasoning 删除则明显更差。[表 1–3](https://arxiv.org/html/2611.07238v1)

## 要减少实际违规，检查必须赶在动作落地之前

如果故障是越权操作，决定收益的是检查发生在动作之前还是之后。零售银行模拟实验的设计正好暴露了这一点：**环境不会替 agent 拦住违规动作。** 改变账户状态的工具总会执行成功；越权退款一旦被调用，就算已经发生。评分器读两轮中的实际工具执行记录和发给客户的消息，用确定性规则分别记录违规与过度拒答；两者都没有才算正确案例。这里的过度拒答也包括漏掉必须执行的动作，例如没有升级处理旧索赔。正确案例率和违规率都按这套模拟手册定义，衡量合成场景中的行为。[§3.1、§3.5、§6](https://arxiv.org/html/2611.06116v1)

银行实验用了四个 open-weight 模型、五种 harness 和 156 条案例，共 3120 条两轮 episode。156 条不是 156 个独立业务场景，而是 39 个基本变体，各做两种措辞与两种压力条件。11 个规则族改写自消费者信贷、支付、投资者保护、数据保护和反洗钱规定；银行、客户和账户都是合成的。四个模型以温度 0、固定 seed、关闭 reasoning 的方式运行。[§3.1–3.4](https://arxiv.org/html/2611.06116v1)

五种 harness 改的是具体的信息和控制路径：pipeline 先替模型查齐身份、账户与筛查结果，再让它输出结构化动作清单；基础工具循环把完整手册放进 system prompt，允许模型逐步调用工具；检索版移除完整手册，每次搜索只按关键词重叠返回两节；记忆版加入 80 条良性客户历史；reviewer 版则让同一个模型先检查每个状态改变调用和客户消息，被拦下的动作不会执行。[§3.3](https://arxiv.org/html/2611.06116v1)

| harness | 四模型池化的正确案例率，每种 harness 624 条 episode | qwen3.8-flash-next，每种 harness 156 条 |
| --- | ---: | ---: |
| 预取信息的 pipeline | 90.5% | 91.7% |
| 完整手册＋工具循环 | 88.8% | 89.7% |
| 只能检索规则的循环 | 87.3% | 82.1% |
| 加入长程良性记忆 | 88.5% | 88.5% |
| 加入同模型 reviewer | 92.1% | 93.6% |

同一 qwen3.8-flash-next 在 reviewer 下是四个模型里最合规的，换成只能检索规则的 harness 后却成了最不合规的；相邻模型的置信区间有重叠，排名本身不够精确。[表 1–2](https://arxiv.org/html/2611.06116v1)

来源：[表 1](https://arxiv.org/html/2611.06116v1)。池化范围是 87.3%–92.1%，相差 4.8 个百分点；固定 Qwen 后的范围是 82.1%–93.6%，相差 11.5 个百分点。部署时要看所选模型自己的变化：deepseek-v4.1-flash 的 harness 差异检验为 p=0.92，未检出差异；Qwen 的组内检验为 p<0.001。跨模型的 model × harness 交互项为 p=0.07，证据仍是提示性的，而非已确立的显著交互。[§4.1](https://arxiv.org/html/2611.06116v1)

动作前的检查确实改变了违规结果。相对完整手册的基础循环，同模型 reviewer 在四模型池化、每种 harness 624 条 episode 的对照中，把违规率从 **9.6% 降到 6.4%**，减少 3.2 个百分点，约为原违规的三分之一。过度拒答率为 1.6%→1.4%，没有检出增加；但输入 token 约为原来的 **1.8 倍**。论文所说没有出现的“代价”指误拒代价，不是推理费用。部署方得到的是一个有计算开销的合规控制，是否划算取决于违规损失和调用规模。[§4.2](https://arxiv.org/html/2611.06116v1)

它也有很清楚的失效点。撤回信贷需要计算日期窗口，基础循环与 reviewer 的正确率同为 66.7%；另一类涉及十三个月时限的未授权交易，reviewer 却把正确率从 68.8% 提到 87.5%。因此，共享模型的第二次检查能纠正部分执行决策，却不一定纠正双方共有的日期计算错误。五种受测 harness 都没有解决这类规则。若要继续改执行控制，可以把日期和累计限额写成确定性工具或执行门禁；这是尚未在该实验中测试的改动。[§4.3、§5](https://arxiv.org/html/2611.06116v1)

检查的效果还必须从实际动作验收。287 条有违规的 episode 中，两个 LLM 裁判一致认为 **26.1%** 同时含有否认已执行动作的客户消息。典型轨迹是先调用 `process_withdrawal`，后来又告诉客户期限已过、无法办理。这个比例来自探索性分析，并有作者对 100 条 episode 的盲检；预设的第二轮客户话术可能诱发否认，精确比例不宜外推。但已经执行的操作不会因为最后一句拒答而消失。合规评估若只看对话，就会奖励一部分真正失败的部署。[§4.4、§6](https://arxiv.org/html/2611.06116v1)

## 执行路径正常后，共享资料的表示仍能减少重复工作

执行控制正常后，如果时间仍花在找入口、逐条拉取和解析同一批资料上，下一处可改的是信息的表示。EnvOpt 把环境分成底层信息和信息的表示。同一份企业资料，可以留在需要反复查询的接口后面，也可以整理成文件索引、数据库或可直接阅读的摘要。这里的 stationary environment 指许多任务共享相同或相似的资料与结构，不要求每次任务的记录完全相同。在 AutomationBench 中，优化产物可以是一段转换程序：每个新任务开始时通过原有 API 读取这个任务的世界，把记录转换成紧凑表示，再交给固定的 agent。[EnvOpt，§1–2、附录 B.3](https://arxiv.org/pdf/2611.07372v1)

重组表示让目标 agent 少做获取资料与从噪声中定位资料的工作。EnvOpt 的成功改动包括：提前整理邮件正文与 ID、提供操作接口速查表、把表格转成可读文本、用 SQLite 索引数据表与源文件。其 token 分解中，最明显的输入节省来自环境返回内容，输出侧也减少了工具调用。[§4.1、§4.3](https://arxiv.org/pdf/2611.07372v1)

AutomationBench 的 600 个公开任务被划成 200 个测试任务、96 个验证任务，其余组成优化任务池；每步从任务池取 20 个任务，第 5 步停止（验证集分数此时开始饱和）。下表按论文表 1 的口径，将执行端记为 AutomationBench 官方 harness，测试结果对三次运行取平均；成本列是该测试集的美元成本，不是单任务单价。[§3、表 1、附录表 4](https://arxiv.org/pdf/2611.07372v1)

| 固定模型与对照 | 通过率 | 测试成本（美元） | 相对于本行起点的变化 |
| --- | ---: | ---: | --- |
| Haiku 4.5：原环境→EnvOpt | 2.33%→16.67% | 42.36→11.55 | +14.34 个百分点；成本 −72.7% |
| Opus 5：原环境→同一 EnvOpt 环境 | 33.83%→35.17% | 236.18→75.26 | +1.34 个百分点；成本 −68.1% |
| Haiku 4.5：Meta-Harness→再加 EnvOpt | 7.00%→18.17% | 75.33→12.47 | +11.17 个百分点；成本再降 83.4% |

来源：[表 1、表 4](https://arxiv.org/pdf/2611.07372v1)。第一行是优化所针对的模型，第二行是迁移，第三行以已优化的 harness 为起点。72.7% 与 83.4% 的分母不同，不能叠加；Haiku 的通过率大幅提高后仍只有 16.67%，环境优化没有把它变成高可靠部署。Meta-Harness 在这里只是 EnvOpt 实验里的对照，数据均来自同一篇论文。

环境重组的收益有多少来自新增工具，可以用消融区分。EnvOpt 会新增工具端点，因此 harness 与环境在工程实现上有交界。它的消融把优化后的工具放回原环境：Haiku 4.5 的通过率为 6.33%，成本 15.75 美元；完整环境改造则为 16.67%、11.55 美元。Opus 5 的两者通过率同为 35.17%，成本却是 100.37 与 75.26 美元。环境重组在这些条件下提供了工具改造以外的收益，收益落在正确率还是费用上，又随模型而变。[§4.4、表 2](https://arxiv.org/pdf/2611.07372v1)

这条优化路径仍依赖验证：**研究 agent 在单步优化时看不到训练任务的 verifier 或参考答案，整条优化流程仍使用带 verifier 的验证集。** 每步结束后，只要成本变坏，或通过率下降超过容忍度，就停止并退回前一步。研究 agent 自己用答案长度、关键词等代理检查质量曾损害留出表现；这些代理不能替代验证。[§2、算法 1、§4.6](https://arxiv.org/pdf/2611.07372v1)

环境变换也能制造新成本。把全部数据库列值塞进一个大文件，反而让 agent 继续探索；搜索返回更多无关文件，会减少搜索 token 却增加阅读 token；一个按分号切 SQL 的程序漏掉了引号内的分号，使目标 agent 反复修补被转换层破坏的查询。环境优化成立的前提是仍保留任务需要的信息和操作语义，且改造后的访问路径确实减少了总工作量。[§4.2、§4.6](https://arxiv.org/pdf/2611.07372v1)

运行成本节省还要覆盖改造投入。72.7% 只计目标 agent 的运行费用。AutomationBench 的离线优化报告为 **150.10 美元、6.6 小时**，包含研究 agent 发起的目标 agent 运行。对真实部署，更合适的判断是：未来任务累计节省的调用费用，能否覆盖离线优化、环境更新与维护。资料长期复用时容易摊薄一次性投入；资料和访问权限频繁改变时，旧索引、预取和转换程序需要重新验证。这是根据方法前提作出的部署推论。[§4.5、表 3](https://arxiv.org/pdf/2611.07372v1)

## 改造是否值得，要把搜索投入与运行预算一起比较

确定了要修哪类故障后，还要决定值得花多少资源搜索改法。HarnessFlow 给出自动搜索的例子：它把完整 harness 代码作为候选，用 MCTS 式策略选择要继续修改的版本，让 coding agent 结合旧轨迹和组件库提出改动。在固定 GPT-5.4-mini、medium reasoning、相同工具访问和任务限额下，每个基准尝试 15 个候选，搜索与最终测试使用不相交的任务集，每项评估重复五次。六个基准的官方指标均值从初始 harness 的 58.59% 升到 69.48%，增加 10.89 个百分点。[HarnessFlow，§3–4、表 1](https://arxiv.org/html/2611.06254v1)

这个均值汇总了任务成功率、WebShop 得分、代码解决率等不同指标。以 SWE-bench Verified 为例，100 道验证题用于搜索、200 道测试题用于最终评价，测试解决率为 67.10%→75.40%；同一次实验的单任务输入输出计价从 0.181 美元降至 0.172 美元。后者排除了搜索成本。是否值得做这类搜索，还要另计离线试错投入。[表 1、附录 C、表 8](https://arxiv.org/html/2611.06254v1)

另一种选择是限制可接受的改动。CLEO 在调查分析领域固定 GLM-5.1，从极小的文件工具循环开始，只接受同时提高表现、通用且可审计的改动。240 道留出问题上，CLEO 为 **83.8%**，开箱 Claude Code SDK 为 **85.0%**，差 1.2 个百分点，约三道题；但延迟为 **114 秒对 76 秒**。小 harness 接近了正确率，但延迟更高。[CLEO，§2–3、表 1](https://arxiv.org/html/2611.03434v1)

这两种优化方式选择了不同目标：一边搜索能提高基准得分的完整 harness，另一边给新增能力设置审计与简洁性门槛。模型、任务和评价器也不同，结果不足以替部署方决定复杂或极简哪种更优。新增组件是否保留，要看它相对当前组合增加了多少正确完成、减少了哪类违规，以及增加了多少运行和维护成本。

搜索改法和升级模型，都需要在相同运行预算下比较。`Pass@(K,T)` 同时记录尝试 K 条轨迹、每条最多 T 次交互时至少成功一次的概率。《What Does Multi-Turn Reinforcement Learning Really Improve in LLM Agents?》在 DeepCoder-MT、BFCL、InterCode-SQL 和 FrozenLake 上固定 K=8、改变 T，观察到多轮 RL 的优势在紧预算下缩小，部分条件下反转。因此，同一 model–harness–environment 的分数，也要附带交互上限、采样次数和 reasoning 设置；否则所谓能力增益可能是更长恢复路径得到的结果。[2611.06483v1，§2.2、§3.2、图 3](https://arxiv.org/html/2611.06483v1)

## 按主导故障动手，接口修好后再比较模型

落到自己的系统，先让实际动作、返回状态和逐次调用用量对应起来，再按主导故障做第一项行为改动：

| 轨迹里的主要问题 | 优先改动 | 何时重新比较模型 |
| --- | --- | --- |
| 固定规则被越过，或日期、累计额度反复算错 | 在状态改变前执行确定性检查；无法编码的规则再测 reviewer 的收益和误拒 | 所需判断无法可靠编码，且完整规则、正确工具与检查后仍失败 |
| 多个任务反复找同一批资料、解析相同文件 | 重组共享环境，建立保留原信息的索引或转换层；用留出任务验证 | 资料已可直接取得，错误仍主要发生在理解、推断或决策 |
| 导入错误、参数不兼容、无状态变化的反复重试 | 修工具契约、执行环境选择与停止条件 | 接口正常、预算充足后，仍找不到有效动作 |

这个排查顺序成立的条件是：当前失败确实发生在可修复的接口或信息路径上。完整规则、正确工具与执行检查已经到位，错误仍集中在理解、推断或决策时，就应重新比较模型；共享的计算错误也值得单独测试确定性工具。前面的实验中，有模型未检出 harness 收益，环境改造后的弱模型通过率也仍低于强模型。先定位缺口，是为了让下一次比较有明确问题。

部署比较需要并列保留三笔账：任务正确完成、实际违规与必要动作遗漏、费用与时延。运行费用要包含失败任务与重试，离线搜索和环境维护另列投入。
