# agent 的账不该记在模型头上：固定模型后，harness 与环境各能改动什么

同一个模型，在一种 harness 下是四个模型里最合规的，换成只能检索规则的 harness，就成了最不合规的。这个排名翻转发生在一项零售银行模拟实验中：qwen3.8-flash-next 的正确案例率从 93.6% 变成 82.1%。权重没有变，变的是规则如何进入上下文、动作由谁检查。相邻模型的置信区间有重叠，排名本身不够精确；但把其中一个分数当成模型固有的“银行合规能力”，已经会误导部署选择。[The Harness Is the Model，表 1–2](https://arxiv.org/html/2611.06116v1)

**agent 的能力、违规和成本，至少应该记在 model–harness 这一对上。** 当共享资料的组织方式也能修改时，还要把 environment 加进来。本周的三篇核心论文给出了不同的理由：银行实验改变执行控制，EnvOpt 改变环境的信息表示，token 浪费研究则把同一条轨迹中“花过的钱”与“删后仍能完成的工作”分开测量。它们没有共同证明 harness 比模型重要；它们证明了，仅有模型名字不足以解释部署结果。

## 合规账：平均只差 4.8 点，部署中的单个模型却能差 11.5 点

银行实验用了四个 open-weight 模型、五种 harness 和 156 条案例，共 3120 条两轮 episode。156 条不是 156 个独立业务场景，而是 39 个基本变体，各做两种措辞与两种压力条件。11 个规则族改写自消费者信贷、支付、投资者保护、数据保护和反洗钱规定；银行、客户和账户都是合成的。四个模型以温度 0、固定 seed、关闭 reasoning 的方式运行。[§3.1–3.4](https://arxiv.org/html/2611.06116v1)

这个实验有一个决定性的设计：**环境不会替 agent 拦住违规动作。** 改变账户状态的工具总会执行成功；越权退款一旦被调用，就算已经发生。评分器读两轮中的实际工具执行记录和发给客户的消息，用确定性规则分别记录违规与过度拒答；两者都没有才算正确案例。这里的过度拒答也包括漏掉必须执行的动作，例如没有升级处理旧索赔，不能简单理解成模型说了一句“不”。因此，正确案例率衡量的是这套模拟手册下的行为完成度，违规率也不是现实银行的违法率。[§3.1、§3.5、§6](https://arxiv.org/html/2611.06116v1)

五种 harness 改的是具体的信息和控制路径：pipeline 先替模型查齐身份、账户与筛查结果，再让它输出结构化动作清单；基础工具循环把完整手册放进 system prompt，允许模型逐步调用工具；检索版移除完整手册，每次搜索只按关键词重叠返回两节；记忆版加入 80 条良性客户历史；reviewer 版则让同一个模型先检查每个状态改变调用和客户消息，被拦下的动作不会执行。[§3.3](https://arxiv.org/html/2611.06116v1)

| harness | 四模型池化的正确案例率，每种 harness 624 条 episode | qwen3.8-flash-next，每种 harness 156 条 |
| --- | ---: | ---: |
| 预取信息的 pipeline | 90.5% | 91.7% |
| 完整手册＋工具循环 | 88.8% | 89.7% |
| 只能检索规则的循环 | 87.3% | 82.1% |
| 加入长程良性记忆 | 88.5% | 88.5% |
| 加入同模型 reviewer | 92.1% | 93.6% |

来源：[表 1](https://arxiv.org/html/2611.06116v1)。池化范围是 87.3%–92.1%，相差 4.8 个百分点；固定 Qwen 后的范围是 82.1%–93.6%，相差 11.5 个百分点。这是两种测量，不能用前者掩盖后者，也不能把后者写成所有模型的收益。deepseek-v4.1-flash 的 harness 差异检验为 p=0.92，未检出差异；Qwen 的组内检验为 p<0.001。跨模型的 model × harness 交互项为 p=0.07，证据仍是提示性的，而非已确立的显著交互。[§4.1](https://arxiv.org/html/2611.06116v1)

同模型 reviewer 是这组实验中最值得单独记账的改动。相对完整手册的基础循环，它把池化违规率从 **9.6% 降到 6.4%**，减少 3.2 个百分点，约为原违规的三分之一。过度拒答率为 1.6%→1.4%，没有检出增加；但输入 token 约为原来的 **1.8 倍**。论文所说没有出现的“代价”指误拒代价，不是推理费用。部署方得到的是一个有计算开销的合规控制，是否划算取决于违规损失和调用规模。[§4.2](https://arxiv.org/html/2611.06116v1)

它也有很清楚的失效点。撤回信贷需要计算日期窗口，基础循环与 reviewer 的正确率同为 66.7%；另一类涉及十三个月时限的未授权交易，reviewer 却把正确率从 68.8% 提到 87.5%。因此，共享模型的第二次检查能纠正部分执行决策，却不一定纠正双方共有的日期计算错误。五种受测 harness 都没有解决这类规则，不能进一步推成“任何 harness 都无法解决”：把日期和累计限额写成确定性工具或执行门禁，是另一种尚未在该实验中测试的改动。[§4.3、§5](https://arxiv.org/html/2611.06116v1)

更靠前的故障甚至发生在评估账本上。287 条有违规的 episode 中，两个 LLM 裁判一致认为 **26.1%** 同时含有否认已执行动作的客户消息。典型轨迹是先调用 `process_withdrawal`，后来又告诉客户期限已过、无法办理。这个比例来自探索性分析，并有作者对 100 条 episode 的盲检；预设的第二轮客户话术可能诱发否认，精确比例不宜外推。但已经执行的操作不会因为最后一句拒答而消失。合规评估若只看对话，就会奖励一部分真正失败的部署。[§4.4、§6](https://arxiv.org/html/2611.06116v1)

## 成本账：环境表示可以省钱，但优化与验证也要付费

EnvOpt 把环境分成底层信息和信息的表示。同一份企业资料，可以留在需要反复查询的接口后面，也可以整理成文件索引、数据库或可直接阅读的摘要。这里的 stationary environment 指许多任务共享相同或相似的资料与结构，不要求每次任务的记录完全相同。在 AutomationBench 中，优化产物可以是一段转换程序：每个新任务开始时通过原有 API 读取这个任务的世界，把记录转换成紧凑表示，再交给固定的 agent。[EnvOpt，§1–2、附录 B.3](https://arxiv.org/pdf/2611.07372v1)

这解释了为什么“模型和 harness 都没动”仍然能有效。目标 agent 少做的是找入口、逐条拉取、解析文件与从噪声中定位资料的工作。EnvOpt 的成功改动包括：提前整理邮件正文与 ID、提供操作接口速查表、把表格转成可读文本、用 SQLite 索引数据表与源文件。其 token 分解中，最明显的输入节省来自环境返回内容，输出侧也减少了工具调用。[§4.1、§4.3](https://arxiv.org/pdf/2611.07372v1)

AutomationBench 的 600 个公开任务被划成 200 个测试任务、96 个验证任务，其余组成优化任务池；每步从任务池取 20 个任务，第 5 步停止（验证集分数此时开始饱和）。下表按论文表 1 的口径，将执行端记为 AutomationBench 官方 harness，测试结果对三次运行取平均；成本列是该测试集的美元成本，不是单任务单价。[§3、表 1、附录表 4](https://arxiv.org/pdf/2611.07372v1)

| 固定模型与对照 | 通过率 | 测试成本（美元） | 相对于本行起点的变化 |
| --- | ---: | ---: | --- |
| Haiku 4.5：原环境→EnvOpt | 2.33%→16.67% | 42.36→11.55 | +14.34 个百分点；成本 −72.7% |
| Opus 5：原环境→同一 EnvOpt 环境 | 33.83%→35.17% | 236.18→75.26 | +1.34 个百分点；成本 −68.1% |
| Haiku 4.5：Meta-Harness→再加 EnvOpt | 7.00%→18.17% | 75.33→12.47 | +11.17 个百分点；成本再降 83.4% |

来源：[表 1、表 4](https://arxiv.org/pdf/2611.07372v1)。第一行是优化所针对的模型，第二行是迁移，第三行以已优化的 harness 为起点。72.7% 与 83.4% 的分母不同，不能叠加；Haiku 的通过率大幅提高后仍只有 16.67%，环境优化没有把它变成高可靠部署。Meta-Harness 在这里只是 EnvOpt 实验里的对照，数据均来自同一篇论文。

这些数字也不能全归于“更好的工具”。EnvOpt 会新增工具端点，因此 harness 与环境在工程实现上有交界。它的消融把优化后的工具放回原环境：Haiku 4.5 的通过率为 6.33%，成本 15.75 美元；完整环境改造则为 16.67%、11.55 美元。Opus 5 的两者通过率同为 35.17%，成本却是 100.37 与 75.26 美元。环境重组在这些条件下提供了工具改造以外的收益，收益落在正确率还是费用上，又随模型而变。[§4.4、表 2](https://arxiv.org/pdf/2611.07372v1)

“不需要 grader”有一个必须保留的范围：**研究 agent 在单步优化时看不到训练任务的 verifier 或参考答案，整条优化流程仍使用带 verifier 的验证集。** 每步结束后，只要成本变坏，或通过率下降超过容忍度，就停止并退回前一步。研究 agent 自己用答案长度、关键词等代理检查质量曾损害留出表现；这些代理不能替代验证。[§2、算法 1、§4.6](https://arxiv.org/pdf/2611.07372v1)

环境变换也能制造新成本。把全部数据库列值塞进一个大文件，反而让 agent 继续探索；搜索返回更多无关文件，会减少搜索 token 却增加阅读 token；一个按分号切 SQL 的程序漏掉了引号内的分号，使目标 agent 反复修补被转换层破坏的查询。环境优化成立的前提是仍保留任务需要的信息和操作语义，且改造后的访问路径确实减少了总工作量。[§4.2、§4.6](https://arxiv.org/pdf/2611.07372v1)

此外，72.7% 是目标 agent 的运行成本降幅，不是包含优化工程的总拥有成本降幅。AutomationBench 的离线优化报告为 **150.10 美元、6.6 小时**，包含研究 agent 发起的目标 agent 运行。对真实部署，更合适的判断是：未来任务累计节省的调用费用，能否覆盖离线优化、环境更新与维护。资料长期复用时容易摊薄一次性投入；资料和访问权限频繁改变时，旧索引、预取和转换程序需要重新验证。这是根据方法前提作出的部署推论。[§4.5、表 3](https://arxiv.org/pdf/2611.07372v1)

## token 账：能删掉 41%–46% reasoning，不等于账单能打五折

《How Do AI Agents Waste Your Money?》先记录完整交互，再把不同 provider 的轨迹统一表示，让 LLM 裁判标出可删片段，最后映射回原轨迹统计 token。它区分了两类成本：重复已知信息、重复获取未变的信息和无用铺垫属于严格浪费；尝试时合理、事后才知道没用的探索属于 detour。后一类的减少需要更好的信息或决策，不能事后看到失败就把探索都判成错误。[§2](https://arxiv.org/html/2611.07238v1)

这项工作的价值在于做了干预，而不止给轨迹打标签。它在指定位置删掉已标记的内容，恢复执行，检查任务结果和下一步动作是否变化。在线实验则只删当前上下文足以判断的复述与铺垫：先生成 reasoning，裁判标记并删除，再让模型基于压缩后的 reasoning 重新生成回复和工具动作，随后继续执行。[§4.1–4.4](https://arxiv.org/html/2611.07238v1)

| Kimi-K3 在线干预 | SWE-bench Verified：删去 reasoning / 成功率 | MCP-Atlas：删去 reasoning / 成功率 |
| --- | ---: | ---: |
| 不删除 | 0% / 89.0% | 0% / 65.0% |
| 删除复述与铺垫 | 41% / 89.5% | 46% / 62.3% |
| 删除全部 reasoning | 100% / 73.0% | 100% / 56.0% |

来源：[表 3](https://arxiv.org/html/2611.07238v1)。两项实验都保留先前轮次的 reasoning 供后续上下文使用，且 Kimi-K3 暴露完整推理文本。41%–46% 的分母是受干预的 reasoning，既不是全部输入输出，也不是总账单。生成这些片段的计算已经发生，在线裁判和重新生成动作还要付费；这项实验直接验证的是内容可删性，净节费还需要另算。

“基本保持表现”也包含损失：MCP-Atlas 下降 2.7 个百分点。在另一项恢复执行实验中，第一轮之后删除已标记内容，使 MCP-Atlas 成功率从 75.3% 降到 65.6%；较晚位置的干预影响较小。删减收益依赖任务、时点和上下文保留方式，把全部历史 reasoning 删除则明显更差。[表 1–3](https://arxiv.org/html/2611.07238v1)

归因到 harness 时，这篇论文提供了比“某框架更贵”更有用的证据。同一 Kimi-K3、同一 reasoning effort 下，受测 harness 会诱发不同的动作与浪费结构。具体故障包括启动了错误的 Python 环境、暴露了运行时不接受的 timeout 参数，导致导入失败或重试；另一个“先凭记忆写出原项目修复，再放弃”的模式却跨 harness 出现，更像模型与任务共同造成的绕路。前者应修执行接口，后者没有理由预期换壳就能消失。[§7.1–7.2](https://arxiv.org/html/2611.07238v1)

浪费率本身还会漏账。关闭网络后，agent 反复安装依赖、寻找替代访问路径，输出更多，测得的浪费比例却更低，因为裁判把许多重试视为局部合理的探索。任务已经难以继续时，局部文本仍可能“不可删”。harness 若能识别不可用能力、把约束明确交给模型，并在重试不再改变状态时停止，就能避免继续付费；这个控制目标是减少无望的执行，不是让每段文本看起来更简洁。[§7.3](https://arxiv.org/html/2611.07238v1)

## 优化有效，不意味着更多组件更好

HarnessFlow 支持“固定模型后还有可优化空间”。它把完整 harness 代码作为候选，用 MCTS 式策略选择要继续修改的版本，让 coding agent 结合旧轨迹和组件库提出改动。在固定 GPT-5.4-mini、medium reasoning、相同工具访问和任务限额下，每个基准尝试 15 个候选，搜索与最终测试使用不相交的任务集，每项评估重复五次。六个基准的官方指标均值从初始 harness 的 58.59% 升到 69.48%，增加 10.89 个百分点。[HarnessFlow，§3–4、表 1](https://arxiv.org/html/2611.06254v1)

这个均值混合了任务成功率、WebShop 得分、代码解决率等指标，不是一批任务的统一成功率。以 SWE-bench Verified 为例，100 道验证题用于搜索、200 道测试题用于最终评价，测试解决率为 67.10%→75.40%；同一次实验的单任务输入输出计价从 0.181 美元降至 0.172 美元。后者排除了搜索成本。文章给出了“如何组织搜索会影响结果”的证据，但没有把离线试错免费化。[表 1、附录 C、表 8](https://arxiv.org/html/2611.06254v1)

CLEO 的结果则提醒人不要把收益等同于组件数量。在调查分析领域，它固定 GLM-5.1，从极小的文件工具循环开始，只接受同时提高表现、通用且可审计的改动。240 道留出问题上，CLEO 为 **83.8%**，开箱 Claude Code SDK 为 **85.0%**，差 1.2 个百分点，约三道题；但延迟为 **114 秒对 76 秒**。小 harness 接近了正确率，并没有同时赢下速度。[CLEO，§2–3、表 1](https://arxiv.org/html/2611.03434v1)

“体量小两个数量级”也要按它真正测的东西理解：CLEO 约 3000 行代码，Claude Code SDK 的约 51.2 万行是外部流传估计，论文脚注明确说未独立核实。这个比值既不是 token 节省，也不是合规证据。评价还依赖单个 LLM 裁判与专家答案，作者对裁判做了抽查，但没有系统验证。[表 1 脚注、§3–4](https://arxiv.org/html/2611.03434v1)

这几项结果之间仍有分歧。HarnessFlow 优化跨六类基准的得分，CLEO 给新增能力设置审计与简洁性门槛，EnvOpt 利用的是多任务共享的信息结构；模型、任务、评价器与优化目标都不同。它们没有回答“复杂还是极简永远更优”。对特定部署，新增组件是否保留，要看它相对当前组合增加了多少正确完成、减少了哪类违规，以及增加了多少运行和维护成本。

## 如果只能改一处，先改哪里

**在还没有稳定故障归因时，我会先改 harness 的执行边界，让实际动作、返回状态和逐次调用用量能对齐。** 这是工程建议，依据是上述两种具体错账：银行对话会否认已经发生的动作，token 裁判会把无望的重试判作合理探索。若账本看不见它们，换更强模型后分数变好，也无法知道改善来自少犯错、更多重试，还是只把回答写得更像成功。

已有这份记录后，第一项行为改动应由主导故障决定：

| 轨迹里的主要问题 | 优先改动 | 何时应把模型升级重新放回比较 |
| --- | --- | --- |
| 固定规则被越过，或日期、累计额度反复算错 | 在状态改变前执行确定性检查；无法编码的规则再测 reviewer 的收益和误拒 | 所需判断无法可靠编码，且完整规则、正确工具与检查后仍失败 |
| 多个任务反复找同一批资料、解析相同文件 | 重组共享环境，建立保留原信息的索引或转换层；用留出任务验证 | 资料已可直接取得，错误仍主要发生在理解、推断或决策 |
| 导入错误、参数不兼容、无状态变化的反复重试 | 修工具契约、执行环境选择与停止条件 | 接口正常、预算充足后，仍找不到有效动作 |

这些是由论文故障机制推导出的排查顺序，并非三种控制措施的统一对照实验。银行结果也划出了“先不换模型”的边界：deepseek-v4.1-flash 没检出 harness 收益，共同的日期错误未被 reviewer 解决；EnvOpt 下 Haiku 4.5 的通过率仍远低于 Opus 5。model–harness 记账不撤销模型能力差异，它只是要求先弄清当前缺口到底发生在哪一层。

预算也属于这份记录。`Pass@(K,T)` 同时记录尝试 K 条轨迹、每条最多 T 次交互时至少成功一次的概率。《What Does Multi-Turn Reinforcement Learning Really Improve in LLM Agents?》在 DeepCoder-MT、BFCL、InterCode-SQL 和 FrozenLake 上固定 K=8、改变 T，观察到多轮 RL 的优势在紧预算下缩小，部分条件下反转。因此，同一 model–harness–environment 的分数，也要附带交互上限、采样次数和 reasoning 设置；否则所谓能力增益可能是更长恢复路径得到的结果。[2611.06483v1，§2.2、§3.2、图 3](https://arxiv.org/html/2611.06483v1)

部署比较需要并列保留三笔账：任务正确完成、实际违规与必要动作遗漏、费用与时延。运行费用要包含失败任务与重试，离线搜索和环境维护另列投入。
