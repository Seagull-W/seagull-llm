# 解读 Anthropic 的 agent 记忆：经验怎样留到下次会话

一个 agent 花了很久才弄清某个任务的规则，换一次会话，却又得重新摸索。保留历史记录能让经历不至于消失，但下一次能否找到有用经验、分清猜测与验证过的规则，仍是另一道难题。记忆要解决的，正是怎样把这次探索的收获带到下次任务里。

Anthropic 探索的共同手法是分层保存，再用离线计算整理：会话转写留下经历，笔记挑出当时认为重要的内容，知识表示把零散内容组织起来，最上层只把少量信息带入新会话。会话内的记录负责及时捕获，称为 dreaming 的后台整理负责回看、纠错和重组；这些内容随后又参与新的任务。

机制与实验依据来自 Lance Martin 的 [《The components of agent memory》](https://www.anthropic.com/research/components-of-agent-memory)正文及图注数字。一篇读者转来的中文解读提供了“易变事实／隐性规则”“四层金字塔”和“顶层做目录、底层做仓库”这几个讲法；它们只是说法，适用范围仍由原文的机制与实验限定。

## 跨会话留下的是经验，各层保存不同程度的加工结果

这里的 agent 记忆有明确边界：它是 agent 从任务和交互中获得、保存下来、供后续会话读取的经验知识。权重更新改变模型参数；上下文学习发生在当前对话里；上下文压缩把旧轮次替换成摘要，让任务得以在新的上下文窗口继续。这几种过程都不在原文所界定的跨会话记忆范围内。

会话转写（transcript）可以先把经历留下来。它保存了先前发生过什么，后续可以检索，也可以回看它来核对笔记。记忆笔记（memory notes）则已经经过一次选择：Claude 可以给显著事件打标记，或者把它们写入跨会话保留的文件目录。这里的“显著性”是对未来用途的判断。记下一条规则，意味着预测未来还会遇到同类情况；记下一个已验证事实，意味着预测后来可以直接依赖它。

这层取舍常被概括为“易变事实”与“隐性规则”：前者随环境变化，重新观察就能取得；后者要靠探索才知道，不记下来就会丢失。按这个分法，记忆应当少存重复、易过期的观察，多留探索所得。不过原文保留的内容也包括当前目标、下一步计划和已验证事实，所以这个分类更适合解释信息的复用价值，不能收窄成“长期记忆只允许写规则”。

把这四层排成一座金字塔，各层的区别就在于信息怎样加工、怎样进入下一次会话。

| 层次 | 保存什么 | 怎样供后续任务使用 |
| --- | --- | --- |
| 第一层：会话转写 | 原始交互与执行记录 | 检索经历，并为核对笔记提供依据 |
| 第二层：记忆笔记 | 当时挑出的事实、猜测、规则、目标和计划 | 按需读取；其中的猜测还需要验证 |
| 第三层：整理后的表示 | 相互链接、可持续修订的知识组织，例如 wiki | 帮助定位内容、连接分散信息 |
| 第四层：注入上下文 | 少量重要信息与索引入口 | 新会话开始时自动可见，再沿入口寻找细节 |

Dreaming 在这些层之间工作：它可以拿转写校正笔记，建立或修订表示，也可以把重要内容提到注入层。因而，这座金字塔不仅有从下往上的提炼，还包含回到记录核验、把细节移回下层的维护过程。[原文图 1](https://www.anthropic.com/research/components-of-agent-memory)

## 笔记回到作答并经过验证，才形成学习闭环

写下失败原因，只完成了学习的一部分。完整闭环还包括提出解释、检验解释、保存验证依据，再让后续作答使用这些规则。记忆目录是否存在，与模型能否走完这条链，是两件不同的事。

CL-Bench 1.0 的数据库任务把这一区别显露出来：Claude 连续回答需要查数据库的问题，每次作答后会得到正确解答，并有机会写入记忆。实验使用 Claude Managed Agents，每道题从新会话开始；有记忆的条件下，可检索的记忆目录跨会话保留。下表均为这一个 database task 的 **mean reward**，对照是 stateless 基线与提供持久记忆目录，数值来自[原文图 3](https://www.anthropic.com/research/components-of-agent-memory)。

| 模型 | Stateless 基线 | 有记忆目录 | 原文观察到的记忆行为 |
| --- | ---: | ---: | --- |
| Sonnet 4.6 | 0.330 | 0.364 | 为错误提出解释，但笔记散落着未经检验的猜测 |
| Opus 4.7 | 0.383 | 0.700 | 合并为参考文档，区分已检查与尚未确认的事实 |
| Sonnet 5 | 0.306 | 0.610 | 评分器检查后标记已确认答案，答错后写入纠正 |
| Opus 5 | 0.564 | 0.828 | 记录规则、规则成立的依据、既往答案及已发现的陷阱，形成闭环 |
| Opus 5.5 | 0.655 | 0.838 | 同样保存经过验证、可用于后续问题的规则 |
| Sonnet 5.5 | 0.644 | 0.833 | 同样形成验证与复用的闭环 |

原文在这些模型的笔记中观察到的一个差别，是能否从“可能是这样”走到“已经检查过，因此以后可以这样答”。后两个模型的无记忆基线比 Opus 5 更高，但有记忆时的得分与它接近。这组结果把记忆的作用具体落到了跨题复用上。

### 只让记失败，反而削弱了记忆收益

在同一数据库任务上，研究者逐项测试了限制记忆内容的规则。相对于不施加这类限制的记忆条件，“只记录失败”使记忆带来的 mean reward 增益发生负向变化：Opus 5 为 **−0.234**，Opus 4.7 为 **−0.150**，Sonnet 4.6 为 **−0.020**。[原文图 5 右](https://www.anthropic.com/research/components-of-agent-memory)

从闭环所需的信息看，失败是起点，已确认的答案、成功的验证以及规则成立的依据也都参与后续学习。只准记失败，可能限制这些内容被保留下来。这是对结果的机制性解释；实验直接显示的是，“只记失败”这条限制削弱了受测较强模型的记忆收益。

### 提示补的是读取和验证这两步

Sonnet 4.6 的问题还包括不常读取已有笔记，以及不检验自己提出的解释。研究者提示它在回答前先读记忆，再明确测试假设，同一任务的 mean reward 从有记忆时的 **0.364** 提高到 **0.641**。较新模型已能更主动地完成这些动作；原文记录，Sonnet 5 无需额外提示便会在作答前读取记忆。

两者改的不是同一件事：一种补上读取与验证的动作，另一种限制能留下什么内容。原文据此强调，说清记忆用来做什么，把显著性的判断留给模型。在这些实验中，较强模型仅获知记忆目录可用，就能从中取得明显收益；额外提示的价值取决于模型尚缺哪一步能力。[原文图 5 左](https://www.anthropic.com/research/components-of-agent-memory)

## 离线回看能把错误笔记送回经历中校正

在线写笔记时，Claude 正在处理当前任务，既可能误读观察，也可能把暂时的解释过早写成结论。下一次会话又可能直接相信这份笔记。Dreaming 把一部分计算放到交互间隙或后台，让 Claude 回看已有记录，检查笔记与实际经历能否对上。这也是 sleep-time compute 在这里的含义：利用交互之外的计算时间整理可供未来读取的内容。

Pokémon Red 的月见山（Mt. Moon）案例展示了错误如何延续。山洞入口在地图西侧，出口在东侧，入口附近有一个跳下后无法直接返回的单向台阶。Claude 错把入口旁的宝可梦中心记在东侧，于是走出中心就认定自己已经穿过月见山。随后它跳下台阶，回到了来路。导航工具没有显示这次落差，Claude 又把结果解释成“向西走过头”，继续相信原来的方位判断。

研究者让 Claude 对含有错误方位的记忆目录执行 dreaming。Claude 将笔记与会话转写比对，找出错误并改写；有了修正后的笔记，它重新进入山洞，最终抵达华蓝市（Cerulean City）。在图 8 展示的运行中，带 dreaming 的条件在累计第 **1,935 个动作**抵达目标；未经修正的原始记忆条件和无记忆条件都没有抵达。未经修正的那次运行中，Claude 曾 **3 次**跌回同一条来路，随后转回山前的城市，运行结束时仍未完成目标。

这次纠错的关键，是把笔记里的方位判断重新放到此前行动记录中检查。转写提供核对经历的依据，笔记承载的是从经历中作出的判断；两者分层保留，为这次推翻错误判断提供了条件。[原文图 6–8](https://www.anthropic.com/research/components-of-agent-memory)

## 知识表示能连接分散信息，但组织与维护都有成本

除了校正已有笔记，离线计算还可以处理“材料越来越多，怎样找得到”的问题。Dreaming 可以从已有记录或任务材料构建 wiki：Claude 为某个主题编写页面，把页面相互链接，并在后续整理中添加、修改、去重、核对来源。它让 agent 有一张可沿着行走的知识地图；后来的会话接着已有页面工作，不必每次重新组织材料。

### 整理后的地图与原始搜索可以互补

Anthropic 用 Stainless 的约 **35 万份内部文件、约 420M token** 测试这种表示，并建立了 **25 个问题**的评估集。Opus 5 agents 在连续的 dreaming 会话中探索文件、维护链接页面，通过共享日志协调工作。下表中的比例都是这组问题上**判分标准的满足比例**；整理规模从 **2 轮、2M dreaming token** 增至 **128 轮、128M dreaming token**。

| 回答问题时可用的资源 | 整理 2 轮后 | 整理 128 轮后 |
| --- | ---: | ---: |
| 仅 wiki | 13% | 48% |
| wiki 与搜索工具 | 54% | 61% |

同一评估中，仅使用搜索工具的得分为 **53%**。成熟后的 wiki 单独作答仍低于搜索，组合使用则得分最高；原文还报告，组合方式相对仅搜索每个问题节省约 **20,000 token**。这个节省发生在回答问题时，而维护表示已经消耗了前述 dreaming token，因此它本身并不构成端到端成本下降的证明。[原文图 10](https://www.anthropic.com/research/components-of-agent-memory)

### 需要跨文档组织的任务，更能体现表示的作用

另一项并购材料测试包含 **24 条判分项**，多数需要整合多份文档，其中 **9 条**还需要判断或算术。针对其中需要跨文档整合、判断或计算的判分项，查询 wiki 时得分为 **87%**，仅搜索为 **73%**。相比之下，Harvey LAB 的另一项法律简报任务有 **57 条判分项**，多数可直接从单份文档检索；wiki 相对搜索没有显示出明确收益。前一类任务需要把分散材料连接起来，后一类任务的主要信息已经能直接取出。[原文图 11](https://www.anthropic.com/research/components-of-agent-memory)

表示也未必让材料更小。在图 12 的另一项 LAB 任务里，原始语料是 **10 份文档、115 KB**，生成的 wiki 达到 **203 KB**，是语料的 **1.77 倍**。细节被大量重述后，知识地图本身也会变成一份庞大的材料。这里的边界很具体：建立结构不自动等于有效抽象，也不自动节省读取成本。[原文图 12](https://www.anthropic.com/research/components-of-agent-memory)

### 表示要围绕目标整理，还要修补会话之间留下的缺口

表示是否可靠，也取决于整理时保住了什么。一项模拟公司收购的 LAB 任务按合同条款给法律简报评分。初始指令只要求建立 wiki，没有说明条款的关键地位；多个 agent 同时写共享条款表，既摘要得不好，又相互覆盖。依据这份 wiki 生成的简报只覆盖了 **57 条事实中的 41 条，即 72%**。

研究者让 Claude 反思失败、修改整理指令并重建 wiki。修改后，每份合同由单个 agent 编写独立页面，逐字引用条款。基于改进表示生成的简报覆盖了同一任务的 **57/57 条事实，达到 100%**。这次提升伴随重要内容保存方式和协作写入结构的共同改变。[原文图 14](https://www.anthropic.com/research/components-of-agent-memory)

单次会话还可能留下局部看不见的结构缺口，例如先写了链接，却没有创建目标页。原文图 15 的 LAB 任务中，第二轮 dreaming 找到 **9 条**指向不存在页面的链接，把它们改指描述同一文档的已有页面，并新增 **3 个页面**，其中包括索引。离线整理由此不只处理内容真假，还能检查不同会话写出的页面能否实际连接起来。[原文图 15](https://www.anthropic.com/research/components-of-agent-memory)

## 开局注入少量入口，细节仍留在可检索的下层

即使已经有了可查的知识组织，agent 也可能不知道自己该查什么。第四层通过预先注入解决这个入口问题：dreaming 可以把重要笔记向上提，由运行框架在每次新会话开始时放进上下文。这样，Claude 无需先想到搜索，就能看到相关信息。

但注入会持续占用上下文，错误内容也可能被带进每次会话；加载进去，更不保证模型会照着执行。原文援引 Claude Code 文档指出，更长的指令文件会降低指令遵循。因此，顶层要保持小，维护时可以把细节移到下层，只留下链接。

Claude Code 的 auto memory 就是这样做的：每次仅加载 `MEMORY.md` 的**前 200 行或 25 KB**，由这个头部展示已知内容及其存放位置。这里的数字描述该实现的加载限额；限额服务于控制注入量、保留导航作用，并非从上述实验推导出的通用最优阈值。该注入层由 Claude 在会话内维护，和 dreaming 可以承担的离线维护有相近目的，却是不同的执行时机。

“顶层做目录，底层做仓库”概括的就是这种分工：入口让模型知道已有经验在哪里，按需读取再把细节带入当前任务。[原文图 13](https://www.anthropic.com/research/components-of-agent-memory)

## 写入时机、记忆保鲜和计算成本仍没有统一答案

**何时写入**，取决于及时性与当前任务之间的取舍。在线记录能在显著事件发生时捕获细节，马上供后续轮次或会话使用，也会分走模型正在执行任务的注意力。离线整理把工作推到后台，但整理结果未必赶得上下一次使用。两种方式怎样配合，仍是设计中的开放问题。

**怎样保鲜**，比定期清理文件更复杂。笔记可能从一开始就错，也可能随着环境改变而失效。Dreaming 可以核对与修正，但持续检查全部记忆未必实际可行。原文提出的探索方向包括，把计算集中在更容易变化的信息上，或者根据记忆被访问的频率调整整理节奏；访问频率在这里是调度依据的候选，并不是已经验证的置信度衰减或自动淘汰机制。

**计算成本由哪个环节承担**，也不能只看单次回答。直接检索转写可以作为记忆基础；维护额外表示则要支付创建、核验和更新的计算。按这条机制理解，离线整理是在为未来访问预付一部分成本，能否摊薄，要看之后是否反复用到、是否少做了搜索，以及环境变化是否迫使它频繁重建。这是成本分布的解释，现有实验尚未给出覆盖不同任务的统一最优安排。[原文结语](https://www.anthropic.com/research/components-of-agent-memory)
