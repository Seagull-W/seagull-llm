# Anthropic 的 agent 记忆：经验如何经整理进入下次会话

一个 agent 花了很久才弄清某个任务的规则，换一次会话，却又得重新摸索。保留历史记录能让经历不至于消失，但下一次能否找到有用经验、分清猜测与验证过的规则，仍是另一道难题。记忆要解决的，正是怎样把这次探索的收获带到下次任务里。

Anthropic 的《The components of agent memory》从记忆笔记出发，讨论 agent 怎样选择值得保存的经验，以及称为 dreaming 的离线整理能做什么。会话转写保留经历，笔记记录当时提炼的内容；dreaming 可以回看转写来纠错，也可以构建 wiki 等表示来连接分散信息，还可以选出少量内容，在新会话开始时注入上下文。这些组成部分分别处理留存、选择、组织和访问的问题。

下文的机制与实验依据来自 Lance Martin 的[原文正文及图注数字](https://www.anthropic.com/research/components-of-agent-memory)，沿记忆笔记、dreaming 的几项作用和上下文注入展开。读者转来的中文解读把这些内容概括为“四层金字塔”。原文确实谈到记忆层级及把笔记提升到注入层，但已保存的正文没有把全部组件定义成固定的四层金字塔；这个图式属于解读者的归纳。

## 会话转写保留经历，记忆笔记选择值得复用的内容

这里的 agent 记忆有明确边界：它是 agent 从任务和交互中获得、保存下来、供后续会话读取的经验知识。权重更新改变模型参数；上下文学习发生在当前对话里；上下文压缩把旧轮次替换成摘要，让任务得以在新的上下文窗口继续。这几种过程都不在原文所界定的跨会话记忆范围内。

会话转写（transcript）可以先把经历留下来。它保存了先前发生过什么，后续可以检索，也可以回看它来核对笔记。记忆笔记（memory notes）则已经经过一次选择：Claude 可以给显著事件打标记，或者把它们写入跨会话保留的文件目录。这里的“显著性”是对未来用途的判断。记下一条规则，意味着预测未来还会遇到同类情况；记下一个已验证事实，意味着预测后来可以直接依赖它。

原文用 Pokémon 的记录行为说明这种选择：当前金钱和位置可以每轮从屏幕读取，反复保存会增加冗余与过期内容；策略、计划和经过检验的规则则需要 Claude 自己探索，并写下来才能留到以后。中文解读将其命名为“易变事实／隐性规则”，进一步提出“只记隐性规则，不记易变事实”。原文明确支持前述具体取舍，却没有提出这条普遍禁令：它认可的笔记内容还包括当前目标、下一步计划和已验证事实。判断依据是未来任务可能需要什么，而这些内容会随任务变化。[原文 Memory notes 与 Claude has learned to judge salience](https://www.anthropic.com/research/components-of-agent-memory)

转写与笔记因此承担不同工作：转写留下可回查的经历，笔记让后续会话更快取得被选出的经验。笔记也可能保存未经检验的猜测，后续是否读取、验证和修正它们，决定了保存内容能否转化为学习收益。

## 笔记回到作答并经过验证，才形成学习闭环

写下失败原因后，学习闭环还需要提出解释、检验解释、保存验证依据，再让后续作答使用这些规则。

CL-Bench 1.0 的数据库任务展示了模型完成这条链的程度：Claude 连续回答需要查数据库的问题，每次作答后会得到正确解答，并有机会写入记忆。实验使用 Claude Managed Agents，每道题从新会话开始；有记忆的条件下，可检索的记忆目录跨会话保留。下表均为这一个 database task 的 **mean reward**，对照是 stateless 基线与提供持久记忆目录，数值来自[原文图 3](https://www.anthropic.com/research/components-of-agent-memory)。

| 模型 | Stateless 基线 | 有记忆目录 | 原文观察到的记忆行为 |
| --- | ---: | ---: | --- |
| Sonnet 4.6 | 0.330 | 0.364 | 为错误提出解释，但笔记散落着未经检验的猜测 |
| Opus 4.7 | 0.383 | 0.700 | 合并为参考文档，区分已检查与尚未确认的事实 |
| Sonnet 5 | 0.306 | 0.610 | 评分器检查后标记已确认答案，答错后写入纠正 |
| Opus 5 | 0.564 | 0.828 | 记录规则、规则成立的依据、既往答案及已发现的陷阱，形成闭环 |
| Opus 5.5 | 0.655 | 0.838 | 同样保存经过验证、可用于后续问题的规则 |
| Sonnet 5.5 | 0.644 | 0.833 | 同样形成验证与复用的闭环 |

原文在这些模型的笔记中观察到的一个差别，是能否从“可能是这样”走到“已经检查过，因此以后可以这样答”。后两个模型的无记忆基线比 Opus 5 更高，但有记忆时的得分与它接近。这组结果把记忆的作用具体落到了跨题复用上。

### 只让记失败，反而削弱了记忆收益

在同一数据库任务上，研究者逐项测试了限制记忆内容的规则。相对于不施加这类限制的记忆条件，“只记录失败”使记忆带来的 mean reward 增益发生负向变化：Opus 5 为 **−0.234**，Opus 4.7 为 **−0.150**，Sonnet 4.6 为 **−0.020**。[原文图 5 右](https://www.anthropic.com/research/components-of-agent-memory)

从闭环所需的信息看，失败是起点，已确认的答案、成功的验证以及规则成立的依据也都参与后续学习。只准记失败，可能限制这些内容被保留下来。这是对结果的机制性解释；实验直接显示的是，“只记失败”这条限制削弱了受测较强模型的记忆收益。

### 提示补的是读取和验证这两步

Sonnet 4.6 的问题还包括不常读取已有笔记，以及不检验自己提出的解释。研究者提示它在回答前先读记忆，再明确测试假设，同一任务的 mean reward 从有记忆时的 **0.364** 提高到 **0.641**。较新模型已能更主动地完成这些动作；原文记录，Sonnet 5 无需额外提示便会在作答前读取记忆。

提示读取与验证，补上的是使用笔记的动作；“只记失败”限制的则是可保存的内容。原文据此强调，说清记忆用来做什么，把显著性的判断留给模型。在这些实验中，较强模型仅获知记忆目录可用，就能从中取得明显收益；额外提示的价值取决于模型尚缺哪一步能力。[原文图 5 左](https://www.anthropic.com/research/components-of-agent-memory)

## Dreaming 回看转写，校正笔记中的判断

在线写笔记时，Claude 正在处理当前任务，既可能误读观察，也可能把暂时的解释过早写成结论。下一次会话又可能直接相信这份笔记。Dreaming 把一部分计算放到交互间隙或后台，让 Claude 回看已有记录，检查笔记与实际经历能否对上。这也是 sleep-time compute 在这里的含义：利用交互之外的计算时间整理可供未来读取的内容。

Pokémon Red 的月见山（Mt. Moon）案例展示了错误如何延续。山洞入口在地图西侧，出口在东侧，入口附近有一个跳下后无法直接返回的单向台阶。Claude 错把入口旁的宝可梦中心记在东侧，于是走出中心就认定自己已经穿过月见山。随后它跳下台阶，回到了来路。导航工具没有显示这次落差，Claude 又把结果解释成“向西走过头”，继续相信原来的方位判断。

研究者让 Claude 对含有错误方位的记忆目录执行 dreaming。Claude 将笔记与会话转写比对，找出错误并改写；有了修正后的笔记，它重新进入山洞，最终抵达华蓝市（Cerulean City）。在图 8 展示的运行中，带 dreaming 的条件在累计第 **1,935 个动作**抵达目标；未经修正的原始记忆条件和无记忆条件都没有抵达。未经修正的那次运行中，Claude 曾 **3 次**跌回同一条来路，随后转回山前的城市，运行结束时仍未完成目标。

比对的一边是笔记中的方位断言——“宝可梦中心在东侧”“月见山已经走完”；另一边是会话转写里实际执行的动作序列及工具返回所记录的观察。按原文叙述，离开中心、跳下台阶、回到来路这一过程，与仍在西侧入口附近的情况相符，和“已经穿山到东侧”的判断冲突。把这些前后相连的经历放在一起，才有机会发现笔记把所处位置解释错了；导航工具单次没有显示落差，也就不足以支持“只是向西走过头”的解释。

原文明确报告 Claude 对照转写发现并改写了错误，以上展开的是依据其案例叙述还原的核验逻辑。已有材料没有列出完整动作轨迹、逐条工具返回或 dreaming 的推理记录，因此无法进一步指认究竟哪一条返回触发了纠错。转写在这里提供回查经历的依据，笔记则保存从经历作出的判断；保留两者，才使重新检验这个判断成为可能。[原文图 6–8](https://www.anthropic.com/research/components-of-agent-memory)

## Dreaming 构建和维护表示，连接分散信息

除了校正已有笔记，离线计算还可以处理“材料越来越多，怎样找得到”的问题。Dreaming 可以从已有记录或任务材料构建 wiki：Claude 为某个主题编写页面，把页面相互链接，并在后续整理中添加、修改、去重、核对来源。它让 agent 有一张可沿着行走的知识地图；后来的会话接着已有页面工作，不必每次重新组织材料。

### 整理后的地图与原始搜索可以互补

Anthropic 用 Stainless 的约 **35 万份内部文件、约 420M token** 测试这种表示，并建立了 **25 个问题**的评估集。Opus 5 agents 在连续的 dreaming 会话中探索文件、维护链接页面，通过共享日志协调工作。下表中的比例都是这组问题上**判分标准的满足比例**；整理规模从 **2 轮、2M dreaming token** 增至 **128 轮、128M dreaming token**。

| 回答问题时可用的资源 | 整理 2 轮后 | 整理 128 轮后 |
| --- | ---: | ---: |
| 仅 wiki | 13% | 48% |
| wiki 与搜索工具 | 54% | 61% |

同一评估中，仅使用搜索工具的得分为 **53%**。成熟后的 wiki 单独作答仍低于搜索，组合使用则得分最高；原文还报告，组合方式相对仅搜索每个问题节省约 **20,000 token**。这个数字统计的是回答问题时的 token 节省。按 wiki 的作用理解，页面预先汇集了相关内容，链接提供查找入口，作答时因而可以减少为寻找和拼接同一信息而反复检索、打开和阅读原始文件；搜索工具仍可补充 wiki 尚未覆盖的材料。这是对节省来源的机制解释，原文没有把 20,000 token 进一步拆成各类检索、阅读或推理用量。创建和维护 wiki 的 dreaming token 另计，所以上述节省不能直接视为包含维护开销后的净节省。[原文图 10](https://www.anthropic.com/research/components-of-agent-memory)

### 需要跨文档组织的任务，更能体现表示的作用

另一项并购材料测试包含 **24 条判分项**，多数需要整合多份文档，其中 **9 条**还需要判断或算术。针对其中需要跨文档整合、判断或计算的判分项，查询 wiki 时得分为 **87%**，仅搜索为 **73%**。相比之下，Harvey LAB 的另一项法律简报任务有 **57 条判分项**，多数可直接从单份文档检索；wiki 相对搜索没有显示出明确收益。前一类任务需要把分散材料连接起来，后一类任务的主要信息已经能直接取出。[原文图 11](https://www.anthropic.com/research/components-of-agent-memory)

表示也可能让材料更大。在图 12 的另一项 LAB 任务里，原始语料是 **10 份文档、115 KB**，生成的 wiki 达到 **203 KB**，是语料的 **1.77 倍**。细节被大量重述后，知识地图本身也成了一份庞大的材料：页数涨了，抽象没有发生，读它比读原文更贵。[原文图 12](https://www.anthropic.com/research/components-of-agent-memory)

### 表示要围绕目标整理，还要修补会话之间留下的缺口

表示是否可靠，也取决于整理时保住了什么。一项模拟公司收购的 LAB 任务按合同条款给法律简报评分。初始指令只要求建立 wiki，没有说明条款的关键地位；多个 agent 同时写共享条款表，既摘要得不好，又相互覆盖。依据这份 wiki 生成的简报只覆盖了 **57 条事实中的 41 条，即 72%**。

研究者让 Claude 反思失败、修改整理指令并重建 wiki。修改后，每份合同由单个 agent 编写独立页面，逐字引用条款。基于改进表示生成的简报覆盖了同一任务的 **57/57 条事实，达到 100%**。这次提升伴随重要内容保存方式和协作写入结构的共同改变。[原文图 14](https://www.anthropic.com/research/components-of-agent-memory)

单次会话还可能留下局部看不见的结构缺口，例如先写了链接，却没有创建目标页。原文图 15 的 LAB 任务中，第二轮 dreaming 找到 **9 条**指向不存在页面的链接，把它们改指描述同一文档的已有页面，并新增 **3 个页面**，其中包括索引。离线整理由此不只处理内容真假，还能检查不同会话写出的页面能否实际连接起来。[原文图 15](https://www.anthropic.com/research/components-of-agent-memory)

## 上下文注入让新会话看见重要信息与检索入口

即使已经有了可查的知识组织，agent 也可能不知道自己该查什么。上下文注入解决这个入口问题：dreaming 可以选出重要笔记，由运行框架在每次新会话开始时放进上下文。这样，Claude 无需先想到搜索，就能看到相关信息。

但注入会持续占用上下文，错误内容也可能被带进每次会话；加载进去，更不保证模型会照着执行。原文援引 Claude Code 文档指出，更长的指令文件会降低指令遵循。因此，注入的内容要保持精简，维护时可以把细节留在按需读取的文件中，在注入内容里留下链接。

Claude Code 的 auto memory 就是这样做的：每次仅加载 `MEMORY.md` 的**前 200 行或 25 KB**，由这个头部展示已知内容及其存放位置。这个限额服务两件事：控制注入量，保留导航作用。它属于该实现的选择，其他系统按各自的上下文预算另定。该注入层由 Claude 在会话内维护，和 dreaming 可以承担的离线维护有相近目的，却是不同的执行时机。

中文解读用“顶层做目录，底层做仓库”概括这种分工。原文明确支持的是：注入内容保持较小、细节移出并留下链接，以及 Claude Code 用 `MEMORY.md` 头部充当索引。把这一做法概括成通用口号是解读者的表达；原文的注入内容也可以包括重要笔记本身。入口让模型知道已有经验在哪里，按需读取再把其余细节带入当前任务。[原文图 13](https://www.anthropic.com/research/components-of-agent-memory)

## 写入时机、记忆保鲜和计算成本仍没有统一答案

**何时写入**，取决于及时性与当前任务之间的取舍。在线记录能在显著事件发生时捕获细节，马上供后续轮次或会话使用，也会分走模型正在执行任务的注意力。离线整理把工作推到后台，代价是整理结果可能无法立即供正在进行的任务使用。两种方式怎样配合，仍是设计中的开放问题。

**怎样保鲜**，比定期清理文件更复杂。笔记可能从一开始就错，也可能随着环境改变而失效。Dreaming 可以核对与修正；若持续检查全部记忆，读取与核验的开销会随记忆量增长。原文提出的探索方向是，把计算集中在更容易变化的信息上，或者根据记忆被访问的频率调整整理节奏；访问频率在这里只是调度依据的候选，原文没有给出按置信度衰减或自动淘汰记忆的机制。

**计算成本由哪个环节承担**，要看整条链。直接检索转写可以作为记忆基础；维护额外表示则要支付创建、核验和更新的计算。按这条机制理解，离线整理是在为未来访问预付一部分成本，能否摊薄，要看之后是否反复用到、是否少做了搜索，以及环境变化是否迫使它频繁重建。这是成本分布的解释，现有实验尚未给出覆盖不同任务的统一最优安排。[原文结语](https://www.anthropic.com/research/components-of-agent-memory)
