# 小模型的强化学习结论，能推到几百 B 吗

在小模型上做强化学习，最值得带到大模型上的结论，是**什么条件下学习信号会消失、优化会失稳、预算会被浪费**。某个奖励函数最好、某种算法排名第一、RL 只能锐化已有能力，这些判断的迁移性反而弱得多：它们同时取决于基座已经会什么、训练让它尝试什么，以及评测把什么算作进步。

这一区别已经有直接证据。Think2SQL 在同一家族的模型之间观察到奖励配方偏好变化；ScaleRL 发现小预算领先的训练方案可能在长训练中落后；万亿参数的 Ring 系列则把训练与推理引擎的概率偏差变成了必须处理的稳定性问题。参数增大后，原来的瓶颈可能减轻，也可能换成另一种瓶颈。[Think2SQL，§4.2](https://www.eurecom.fr/publication/8640/download/data-publi-8640.pdf)；[ScaleRL，§3–5](https://arxiv.org/html/2510.13786v1)；[Ring-1T，§2.3–2.4](https://arxiv.org/html/2510.18855v2)

截至 2026 年 10 月，不能再把证据边界写成“公开研究只到小模型，百 B、千 B 几乎没有曲线”。万亿参数的训练动态、稳定性消融以及跨规模比较已经出现。真正缺的是：**在统一的初始化、数据、评测和成本口径下，从小模型一直覆盖到万亿参数、并验证预测误差的联合 scaling law。** 现有工作提供了若干可连接的实验切面，尚未给出这样一张完整地图。

## 先确定要外推的究竟是什么

这里的“泛化”首先指实验结论跨模型规模是否成立；它与模型对新题目的泛化不同。小模型在域外测试上提升，说明这次训练有域外收益，却不自动证明训练配方对大模型也有收益。蒸馏则是第三件事：把大模型产生的行为教给小模型，并不等于证明小模型上的 RL 实验能够预测大模型。

还有一个更容易影响判断的尺度问题：稠密模型的参数量与 MoE 的总参数量不能直接排在一条计算成本轴上。

| 模型或实验对象 | 参数口径 | 这项证据回答什么 |
| --- | --- | --- |
| Think2SQL 的 Qwen3 | 4B、8B、14B 稠密模型 | 同一家族、同一 SQL 训练任务中，奖励和 advantage 配方是否随规模变化 |
| ScaleRL 的 Scout | 109B 总参数、17B 激活参数、16 个专家 | 一套 RL 配方能否在更大的 MoE 上稳定延长，并预测同一模型更高预算的表现 |
| DeepSeek-R1 的基础架构 | 671B 总参数、每 token 激活 37B | 大规模 RL 的可行性、行为变化及蒸馏结果 |
| Ring-Zero 的两个基座 | 104B 总参数／7.4B 激活；1T 总参数／63B 激活 | 同一报告的训练配置下，模型规模如何改变学习速度和最终表现 |

参数与实验对象分别见 [Think2SQL §4](https://www.eurecom.fr/publication/8640/download/data-publi-8640.pdf)、[Meta 官方 Scout 模型卡](https://huggingface.co/meta-llama/Llama-4-Scout-17B-16E)、[DeepSeek-R1 附录 A.1](https://arxiv.org/html/2501.12948v2)、[Ring-Zero §4.1](https://arxiv.org/html/2607.12395v2)。ScaleRL 写的“17B×16”不是把 17B 乘以 16 得到总参数；其中共享层、激活路径和专家数的含义不同。

总参数关系到权重存储、专家容量和通信，激活参数更接近每个 token 的主要算术工作量；实际成本还受注意力、序列长度和硬件利用率影响。一个总参数超过百 B、激活参数不足 10B 的模型，不能简单归入“相当于百 B 稠密模型”，也不能据此当作普通小模型。

下表为本文对跨规模证据的综合判断。

| 要迁移的结论 | 现有证据支持的程度 | 常见失效方式 |
| --- | --- | --- |
| 奖励需要提供可区分的学习信号；训练与采样策略偏差需要控制 | 可以作为跨规模的机制假设，已有大小模型实例 | 具体问题强度改变，同一种修正不再充分 |
| 某个奖励、归一化、裁剪阈值或 rollout 组大小最优 | 只能随条件迁移，不能直接复制最优值 | 小模型所需的引导变成大模型可利用的代理目标；效率排名随预算反转 |
| RL 主要自蒸馏，或 RL 扩大能力边界 | 必须绑定任务、训练阶段和有限采样口径 | 在容易的题上测到分布锐化，在更难题族或不同反馈下测到能力扩展 |
| 训练计算增加带来可预测收益 | 固定设置内已有验证 | 换模型、数据分布或系统后，原曲线参数和成本单位都改变 |

## 配方为何会在小模型区间内翻转

### SQL 的稠密奖励，既能提供台阶，也能制造捷径

Think2SQL 对 Qwen3 的 4B、8B、14B 做了约 **20,000 GPU 小时的整体实验研究**；其 RL 设置使用 H100 80GB，训练任务为 BIRD，优化采用去掉 dynamic sampling 的 DAPO。域外评测包含 Spider 及其变体、EHRSQL。这里的两万小时是研究总量，不是一个模型的一次训练预算。[Think2SQL，§4–4.1](https://www.eurecom.fr/publication/8640/download/data-publi-8640.pdf)

SQL 提供了一个很清楚的奖励稀疏性例子：查询可能能执行，返回的行也大致正确，只是多了一列。若奖励只检查最终结果是否完全一致，这次尝试仍然得零分。Think2SQL 的稠密奖励用结果中的单元格精确率、召回率、元组数量关系提供部分分数，让不完美的尝试之间也有好坏之分。

其中的 gated reward 还加了一层门槛：不能执行的查询得零；**能够执行、输出格式合规且结果质量很低的查询，获得 0.1 的底分**；质量较高时采用结果质量分。因而“可执行即给底分”只是简写，格式条件和低质量区间也是定义的一部分。[Think2SQL，§3.4，式 3](https://www.eurecom.fr/publication/8640/download/data-publi-8640.pdf)

在 Qwen3-4B、BIRD-Train 上训练并以 BIRD-Dev 的 refined execution accuracy 评测时，论文表 2 报告：稀疏奖励为 **54.5±0.7**，标准部分分奖励为 **55.8±0.1**，带底分的 gated reward 为 **59.6±0.3**；数值是百分制执行准确率，误差为三次评测的标准差。这个 refined 指标保留重复行计数并允许等价的列顺序变化，不能与任意论文中的原版 EX 直接混比。[Think2SQL，§3.1、§4.1，表 2](https://www.eurecom.fr/publication/8640/download/data-publi-8640.pdf)

但规模增大后，底分不再持续占优。论文在其配方比较中为 4B 选择 gated reward 加组内归一化，为 8B 和 14B 选择稀疏奖励加 batch scaling；在 14B 设置下，标准部分分奖励乃至稀疏奖励开始超过带底分的方案。论文将此解释为大模型更可能利用稠密代理信号形成次优捷径。**性能交叉是实验观察，“通过奖励捷径导致交叉”是机制解释**，两者的证据强度不同。[Think2SQL，§4.2，图 3](https://www.eurecom.fr/publication/8640/download/data-publi-8640.pdf)

这里有两个都叫 scaling、却完全不同的操作。Think2SQL 的 **batch scaling 是在训练批次范围内做 reward／advantage 的归一化**，相对的是 group scaling 和不做方差归一化；它不是增加批次中的题数或轨迹数。把这篇文章概括为“14B 应当用更大的 batch”，就把归一化范围误读成了数据规模。

这组结果也没有支持“模型越大，奖励就越稀疏越好”这样的单调规律。它支持的判断更具体：当模型已经能够较频繁地产生接近正确的 SQL，奖励中的低质量底分可能失去引导价值，而准确的结果区分变得更重要。把这条判断带到数百 B 时，应检查该模型在目标任务上的初始成功率和奖励分布，而不是按参数量直接删掉稠密奖励。

### 初始能力比参数门槛更接近原因

因果推断实验提供了另一种失效形态。《Generalization of RLVR Using Causal Reasoning as a Testbed》使用 Qwen2.5-Instruct 的 3B–32B 模型，输入因果图、机制参数和查询，输出概率分布。RLVR 在关联和干预查询上，对至少 7B 的模型通常比 SFT 更能泛化；3B 在训练前后都缺乏相应的推理能力。可是，同层级的反事实查询上，RLVR 在研究中的各个规模都不如 SFT。论文中的 SFT 直接学习答案分布，RLVR 则生成推理链后再回答，这也使比较同时包含了输出与监督方式的差别。[因果推理研究，§2、§4，图 3–4](https://arxiv.org/html/2512.20760v2)

因此，这里的“7B”是任务与模型家族中的经验分界，不是 RL 的普适起跑线。增加参数可能使模型跨过能形成有效尝试的门槛，但遇到另一类查询，原来的门槛就不够用了。对小模型的失败，首先要区分：模型有没有产生可用解法的先验，奖励能否区分进步，以及优化有没有利用信号。只观察最终分数不涨，无法知道哪一层失败。

Aletheia 又说明，跨过门槛后，重要组件的顺序也会改变。这项研究训练的是**代码验证器**：给候选程序排序、选出正确程序，并非直接训练代码生成器。其主要模型初始化来自 DeepSeek-R1-Distill-Qwen 系列，规模为 **1.5B、7B、14B**；比较思考轨迹、负样本、在线采样三个组件，并分别以 best-of-N 选择准确率和排序相关性衡量用途。[Aletheia，§2–3](https://arxiv.org/html/2601.12186v4)

在该设置中，小验证器最依赖 on-policy 学习，较大验证器更依赖思考轨迹；负样本对选出第一名的帮助相对稳定，对排序质量和大模型训练稳定性的意义则更明显。额外推理采样可以缩小部分差距，却没有在所测预算中消除训练配方的差距。另一方面，按成本比较时，较大的离线验证器又能成为有竞争力的选择。这意味着“完整 GRPO 配方分数最高”和“在线训练最划算”本来就是不同判断。[Aletheia，§3.1–4](https://arxiv.org/html/2601.12186v4)

这里的“大模型”仍只是这项实验中的 14B。它足以反驳“小模型上最重要的组件必然一直最重要”，却不足以给数百 B 生成器指定训练配方。

## RL 到底在锐化，还是在学新能力

### pass@1 的增益，并不能独自回答这个问题

Adaptive Guidance 把训练后新增的正确答案分成两类：基座多次采样本来就能答对、训练后单次能答对，称为自蒸馏；基座多次采样仍未答对、训练后单次答对，称为能力增益。这个分解有用，但其中“不会”由一个有限的采样实验定义。

具体而言，其主要分析从 **Qwen2.5 的 0.5B、3B、7B、32B、72B** 出发，进行 **256 步 GRPO**；初始可达集合按 **pass@16、温度 1** 划分，训练后单次表现使用 **温度 0**。研究涉及数学、科学与代码训练数据，摘要报告的 **超过 50 万题**是研究数据范围，而非这次能力分解所用测试集的题数。[Adaptive Guidance，§2.1、§3.1](https://arxiv.org/html/2506.13923v2)

在这个口径和训练区间内，自蒸馏是所有所测规模的主要进步来源；3B、7B 的自蒸馏收益较大，32B、72B 较小，0.5B 的能力增益在相对意义上较突出。较大模型开始时未解题集合就更小，所以“涨得少”同时包含了可提升空间变少的影响。论文的分解还单列了原本正确、训练后错误的回退项；新增解题数不能直接等同于净准确率提升。[Adaptive Guidance，§2.1、§3.1.2](https://arxiv.org/html/2506.13923v2)

它提出的 Guide-GRPO 则在一组无提示 rollout 全失败时加入提示，再纠正带提示采样与无提示目标之间的分布差别。论文表 2 的 **32B、8K 上下文**比较中，七个数学基准的宏平均 greedy pass@1 从普通 GRPO 的 **52.87%** 提高到 **56.26%**，即 **3.39 个百分点**；这是两种训练方法的比较，不是从未训练基座到 Guide 的总收益，也不是每个基准都提高了这个数。[Adaptive Guidance，§3.2，表 2](https://arxiv.org/html/2506.13923v2)

这些结果支持“在该分布上，很多 RL 收益来自让已有解法更容易被输出”。它们没有证明模型的可学习能力等于初始化时某个 pass@k 集合。参数更新会在题目之间共享结构，提示和部分奖励又会改变探索所能利用的信息。

### 空间规划的反例是真实分歧，但不是“无限采样”的证明

Ariadne 用可控迷宫研究视觉语言模型。其主要实验是 Qwen2.5-VL-7B-Instruct，另外测试 3B、4B、8B 的视觉模型。训练只包含较短路线，评测加入更长路线；奖励不仅看终点成功，还根据**正确动作前缀**提供稠密反馈，并配合难度课程。因此，它与只用最终答案对错的数学 RLVR，在可用监督信息上已经不同。[Does RLVR Extend Reasoning Boundaries?，§3–4](https://arxiv.org/html/2511.00710v4)

该论文表 1 中，主要的 **7B 视觉模型**在六步迷宫上的基座 **pass@1024 为 0.0%**，RLVR 版本为 **41.0%**；七步对应 **0.0% 与 14.0%**。训练路线长度不超过五步，评测温度为 **1.0**。更远的八至十步区域，两者在该表中仍为零。这是超出训练路线长度的有效边界扩展，同时有清楚的远域失效边界。[Ariadne，§4.1–4.3，表 1](https://arxiv.org/html/2511.00710v4)

原文有将此表述为“无论采样预算如何都不能成功”的措辞，但实验只覆盖有限预算。**pass@1024 没有观察到成功，不等于数学上证明成功概率为零**；零值还受到题目集合和报告精度的限制。准确的结论是：在已经测试的采样范围内，RL 后的策略解出了基座没有展示过的题族。

这与 Adaptive Guidance 的结果存在张力，却不构成同一实验上的互相否定。前者测结构化空间任务、使用动作前缀奖励和课程，后者在数学等任务上以 pass@16 定义初始可达集合；一个重点观察困难题族的覆盖扩展，一个量化整体新增正确答案的来源比例。整体进步主要来自自蒸馏，与局部困难题族出现扩展，可以同时发生。尚未解决的是：在相同奖励信息、训练预算和采样口径下，两类任务的差异还剩多少。

跨规模结果同样需要按基准区分：Ariadne 在 MapBench 上强调较小的 3B、4B 模型改善明显，但在 ReasonMap 的长问题上，论文描述的是各规模相对收益大致稳定。因此，“小模型相对增益更大”也不适合当作整个空间规划实验的统一规律。[Ariadne，§4.4，表 3、5](https://arxiv.org/html/2511.00710v4)

也不能据此把领域分成“数学只锐化，空间规划才扩展”。Ring-Zero 在万亿参数模型的数学训练中报告：早期 **pass@1024** 上升，随后趋于平台，而 **pass@1** 继续提高；论文将其解释为先发现、后锐化。这个阶段结构是该训练运行的观察，不是所有 RL 的必经顺序。它提示的是，训练到哪里再做能力分析，会影响结论。[Ring-Zero，§5.2，图 10](https://arxiv.org/html/2607.12395v2)

### 家族差异甚至会让错误奖励也“有效”

Spurious Rewards 给出了足够尖锐的对照。在 **Qwen2.5-Math-7B、MATH-500、300 步 RLVR** 的设置下，相对基座的准确率增益为：随机奖励 **21.4 个百分点**、真实答案奖励 **29.1 个百分点**、特定错误标签奖励 **24.1 个百分点**。其中随机奖励以概率 0.5 赋值为 1；错误标签来自基座多数投票得到、但与正确答案不一致的具体答案，并不是奖励所有错误。评测 pass@1 使用温度 0，图中训练末值采用论文的平滑口径。[Spurious Rewards，§2，图 1–2，附录 A.4–A.6](https://arxiv.org/html/2506.10947v2)

这并不是“Qwen 都能从噪声获益”。论文在普通 Qwen2.5、OLMo2、Llama3 上观察到的收益很小甚至为负；Qwen2.5-Math 的预训练先验尤其关键。其分析把 GRPO 裁剪偏置与高先验行为的放大联系起来，案例之一是没有实际执行代码、却以代码形式展开推理的行为。[Spurious Rewards，§3–5](https://arxiv.org/html/2506.10947v2)

对跨规模研究而言，这个对照说明：仅凭“小模型训练后涨了分”，甚至不能确定改进来自奖励中想提供的信息。若小模型恰有容易被放大的先验，而大模型换了预训练、指令微调或蒸馏方式，所谓规模趋势可能首先是初始化趋势。

DeepSeek-R1 的蒸馏实验也应放在这个位置。其直接对照是在 Qwen2.5-32B 上，报告来自 R1 的蒸馏优于文中直接 RL 的结果。这说明外部优质轨迹能比该模型自行探索更有效地提供解法，不能单独证明小模型具有不可突破的容量上限。它还是一次不同信息来源、不同训练过程的比较，而不是固定先验后只改变参数量的实验。[DeepSeek-R1，附录 F.1](https://arxiv.org/html/2501.12948v2)

## 训练计算扩大后，为什么短跑赢家可能落后

ScaleRL 的价值在于把“训练更久后会怎样”变成了可以检验的预测问题。其研究总投入超过 **400,000 NVIDIA GB200 GPU 小时**，主要受控消融在 8B 稠密模型上进行；图 1 报告 8B 的单次长运行约 **100,000 GPU 小时**，Scout MoE 的长运行约 **50,000 GPU 小时**。研究总投入已经包含这些运行，不能相加成新的总预算。[ScaleRL，§1，图 1，附录 A.3](https://arxiv.org/html/2510.13786v1)

它拟合的是固定模型、训练数据与配方下，计算量和验证正确率之间的饱和曲线：

$$
R(C)=R_0+\frac{A-R_0}{1+(C_{\mathrm{mid}}/C)^B}.
$$

其中，$A$ 是拟合的渐近正确率，$C_{\mathrm{mid}}$ 决定收益走到中点需要多少计算，$B$ 控制曲线陡峭程度。对数计算轴上呈 S 形，意味着早期、中期和接近饱和时，同样的预算倍增可以产生很不一样的收益。这里的渐近线是**当前模型、数据和训练方案的拟合参数**，不是模型所有可能训练方式的能力上限。[ScaleRL，§2.1，式 1](https://arxiv.org/html/2510.13786v1)

这项预测的评测口径也很明确：从 Polaris-53K 留出 **1,000 道同分布题**，每题生成 **16 次**，取平均成功率 **mean@16**，每 **100 个训练步**评测一次。mean@16 衡量一次采样平均能有多好；pass@16 衡量十六次中至少一次成功的覆盖率，二者不能互换。8B 长运行的拟合利用最高约 **50,000 GPU 小时**内的数据预测到 **100,000**；Scout 图中以约 **16,000**以内的数据外推到约 **45,000 GPU 小时**的评测点。它验证的是**各模型自己的较低预算轨迹能否预测较高预算轨迹**，不是拿 8B 的拟合参数直接预测 Scout。[ScaleRL，图 1，§2.1](https://arxiv.org/html/2510.13786v1)

论文的消融支持两类不同影响。损失聚合、advantage 归一化、所测课程与异步离策略调度，主要改变计算效率；损失类型、某些裁剪设置、批次大小和生成长度，则可能改变拟合的最终水平。于是“这些细节都不改变渐近线”并不准确：**离策略调度方式与损失函数不是同一个开关**，而 DAPO 上裁剪阈值的变化在文中就改变了拟合渐近值。[ScaleRL，§3–5，附录 A.17](https://arxiv.org/html/2510.13786v1)

对小预算实验，这造成两种具体误判。其一，较快上升但较低的饱和曲线，会暂时领先较慢上升、最终更高的曲线；其二，一个尚未进入失稳区间的方案看起来很好，长训练后却因熵、截断率或策略偏差积累而崩溃。ScaleRL 的一些初步方案在延长训练后出现失稳，只有稳定运行才有可解释的饱和外推。用更复杂的曲线拟合，不能替代稳定性本身。

因此，小模型上一次短跑的领先，最多支持该预算下的优势。若要主张可扩展，至少要看多个预算点、在更长运行上检验预测，并将同分布验证与域外基准分开。ScaleRL 也观察到小批次的同分布分数仍增长时，下游表现已经停滞；验证分数的拟合成功不是所有任务都继续受益的保证。[ScaleRL，§3、§5，附录 A.15](https://arxiv.org/html/2510.13786v1)

## rollout 数据量不是一个可以随便合并的数字

增加训练计算，可能是重复使用同一题库、每题多生成几条轨迹、每批增加更多不同题、生成更长答案，或者让同一批轨迹参与更多次更新。这些操作的统计作用不同。下面是记账关系，不是从论文拟合出的 scaling law：

- **题库的独立问题数**决定训练能覆盖哪些情形；重复做题不会自动增加任务覆盖面。
- **每批不同 prompt 数**决定一次更新看见多少类问题，影响梯度与任务覆盖的波动。
- **每题 rollout 数 $G$**影响发现成功解法的机会，以及组内相对优势的估计。
- **轨迹长度**影响搜索深度、截断、奖励成本与 token 总量。
- **更新次数与样本复用**影响优化量，也影响采样策略和当前策略之间的距离。

在理想化的独立采样、二元奖励条件下，若一道题单次成功概率为 $p$，一组 $G$ 条轨迹同时含有成功和失败的概率为：

$$
P_{\mathrm{mixed}}=1-p^G-(1-p)^G.
$$

这是直接的概率计算。对于只按组内相对奖励计算优势、且没有其他训练信号的更新，全对或全错的组都没有答案质量上的组内对比。若 $p$ 很小，增加 $G$ 可以提高发现成功轨迹的机会；若模型变强、原题几乎全会，继续在这些题上增采样，又会遇到全对组。相同题库、相同 $G$ 在大小模型上提供的有效学习信号因而不同。模型规模改变了数据的有效难度，而数据有效难度又改变 rollout 的边际收益。

但增加 $G$ 同时消耗预算。ScaleRL 的基础设置是 **48 个 prompt × 每题 16 条生成＝768 条完成轨迹／更新**；在固定总轨迹批次的实验中，它改变每题生成数为 **8、16、24、32**，同时反向调整 prompt 数，所拟合曲线变化不大。这个结论只适用于该中等批次区间和重新分配方式，不能改写成“增加 rollout 没用”。同一研究另外增加整体批次时，观察到了更高的拟合最终水平。[ScaleRL，§2、§5，附录 A.13](https://arxiv.org/html/2510.13786v1)

Ring-Zero 则给出了另一种预算口径的交叉：它在 **104B 总参数、7.4B 激活的 flash 模型第一阶段 RL** 上消融每题 **8、16、32** 条 rollout，32 条按训练步看收敛最快，8 条按墙钟时间看最快，最终采用 16 条作为折中。这项组大小消融不是在 1T 模型上完成的，不能因为文章标题写着 trillion-scale 就把所有实验都归到万亿模型。[Ring-Zero，§4.4.5，图 9](https://arxiv.org/html/2607.12395v2)

独立题数也不能由 rollout 总数替代。Think2SQL 在 Qwen3-4B、gated reward 加组内归一化的实验中，将梯度更新预算保持在约 **565 次**，比较数据子采样与重复训练。使用约一半数据时，Spider 变体与 EHRSQL 的按题数加权 EX 为 **72.2**，全量为 **71.4**；但 BIRD-Dev 对应为 **58.4 与 59.6**。更少题目对域外集合略有好处，同时对训练目标域有损失。原文将域外变化解释为隐式正则化，这仍是针对该分布的解释，不是数据越少越好的规律。[Think2SQL，§4.4，图 5](https://www.eurecom.fr/publication/8640/download/data-publi-8640.pdf)

实际 GPU 小时还混合了系统效率。ScaleRL 的预算来自 GB200，Think2SQL 的 RL 使用 H100，Ring-Zero 使用 H200；这些时间不能不经换算就放在同一成本曲线上。即使硬件相同，SQL 执行、代码验证、长轨迹拖尾、权重同步和异步等待也会改变有效吞吐。训练步效率、token 效率与墙钟效率，应各自有分母。

## 算法机制能迁移，算法名和超参不能代替证据

DAPO 的常见数字是 Qwen2.5-32B 在 AIME 2024 上从 **30 到 50**。原文表 1 中，这指 naive GRPO 与逐步加入过长处理、上裁剪调整、token-level loss、dynamic sampling 后的完整 DAPO 的 **avg@32 百分制成绩**；评测温度 **1.0**、top-p **0.7**。avg@32 是重复采样平均表现，不是三十二次中只要答对一次就算对。它是整套训练修改的收益，不能全归给某一个裁剪公式。[DAPO，§4.1–4.2，表 1](https://arxiv.org/html/2503.14476v2)

GSPO 把重要性比率改为基于整条响应、经过长度归一化的序列级量，让奖励与更新的粒度更一致。其 Qwen3 实验展示了稳定性和效率优势，尤其关注 MoE 路由带来的训练困难。但 ScaleRL 的另一套环境给出了必须并排保留的结果：原 GSPO 的 **$10^{-4}$ 量级**裁剪配置在其 **8B** 实验里表现不佳，改到 **$10^{-3}$ 量级**后更好；图 20 的上／下阈值包含 **0.004／0.003** 和 **0.005／0.003**，不是唯一一个“正确 clip＝0.004”。[GSPO，§3–5](https://arxiv.org/html/2507.18071v2)；[ScaleRL，附录 A.17.3，图 20](https://arxiv.org/html/2510.13786v1)

而且，ScaleRL 并未止于“重调后 GSPO 就稳定”：它报告某些 GSPO 运行中途发散，8B 有时可从检查点恢复，Scout 上反复恢复仍未解决，最终更推荐其环境下的 CISPO。**GSPO 在 Qwen3 上稳定与它在 ScaleRL 的 Scout 上失稳，都是原文报告的事实。** 数据、序列长度、异步程度、实现与数值路径没有统一，现有材料不足以将差异单独归因于参数量。[ScaleRL，附录 A.17.4](https://arxiv.org/html/2510.13786v1)

所以，算法层也没有天然的跨规模保证。相对可靠的是机制诊断：序列越长，token 级误差如何累积；rollout 越陈旧，策略比率如何变化；MoE 路由和不同推理内核怎样引入概率偏差。解决同一机制的设计有迁移价值，但“某算法是更好的默认值”仍需在目标系统中验证。

## 数百 B 到一千 B，已有证据改变了什么

Ring-1T 在 **1T 总参数、约 50B 激活参数**上报告了训练与推理不一致的问题。其 IcePop 先在 **16.8B 总参数、0.75B 激活参数**的 Ring-mini-2.0 上比较，再在 Ring-1T 上展示：原始 GRPO 训练中梯度范数与引擎概率差异增长，加入修正后稳定性改善。这个案例确实把小计算路径上的机制分析接到了万亿参数系统；不过，大模型部分是训练动态比较，没有因此得到一条从小模型预算预测万亿模型分数的统一曲线。[Ring-1T，§2.4.1，图 5–6](https://arxiv.org/html/2510.18855v2)

同报告的 rollout 分段调度在其比较设置中把 rollout 阶段每步速度提高约 **2.5 倍**，端到端每步约 **1.5 倍**，同时保持接近的奖励和基准表现。两个加速比有不同分母，不能相乘。它展示了大规模 RL 的另一条 scaling 路线：不改变模型参数，也不增加轨迹信息，而是让相同预算完成更多有效工作。[Ring-1T，§2.4.2，图 7–8](https://arxiv.org/html/2510.18855v2)

Ring-Zero 更直接比较了 **104B／7.4B 激活**和 **1T／63B 激活**的 Ling-2.5 基座。在论文称为相同训练配置的比较中，第一阶段的 1T 模型约 **3,600 步**时，在 AIME 2024／2025 上分别为 **89.06%／83.28%**；较小模型训练约 **5,200 步**后对应 **71.72%／63.54%**。该报告的数学评测采用 **64 次重复的平均 pass@1、温度 0.6**。这里引用的是 §5.1 的训练比较点；其中较小模型的 AIME 2024 数值与主表的 71.2% 不一致，差异原因未明，不能用二者混合推导精确的规模收益。[Ring-Zero，§4.1、§5.1，图 10](https://arxiv.org/html/2607.12395v2)

这支持“大模型在该运行中更快学到更高表现”，却尚不能回答“固定 RL FLOPs，选哪一个更划算”。两者激活参数、基座能力不同，每步成本不同；训练还伴随长度课程和难度变化。较少步数达到较高成绩，是学习效率证据，不能直接等同于计算最优性。

两份万亿报告也并非互相印证所有配方。Ring-1T 的推理 RL 配方没有 KL 惩罚；Ring-Zero 在第一阶段强调 KL 与训练／推理比率修正的稳定作用，且其稳定性比较中 IcePop 仍可能延迟后失稳。后者经过自蒸馏再进入下一阶段时，又采用不同的损失归约并移除 KL。数据、初始化、训练阶段与算法同时改变，因此“万亿参数必须保留 KL”或“万亿参数可以去掉 KL”都超出了证据。[Ring-1T，§2.3.4](https://arxiv.org/html/2510.18855v2)；[Ring-Zero，§4.1、§4.4.2](https://arxiv.org/html/2607.12395v2)

公开证据由此形成了三种强度：ScaleRL 提供固定设置内的预算外推验证；Ring-1T 提供大系统上的机制与工程消融；Ring-Zero 提供更大参数范围的训练动态和跨规模比较。它们共同否定“百 B、千 B 无从讨论”，但仍未把模型参数、独立题数、rollout token 和训练计算统一到可迁移的最优分配公式里。

## 小模型研究怎样才能对大模型有用

如果实验预算主要落在 1.5B–14B，最有价值的研究结果应当包括“为什么在这里有效”。这能把一次配方搜索变成目标模型可以重新检验的假设。

**第一，按能力状态而不只是按参数分组。** 训练前测同一题集的单次正确率、有限 pass@k、全对与全错组比例，以及格式、执行和推理错误。若一个方法只改善全错组特别多的模型，它更像是在解决冷启动；若强基座仍从中获益，则需要找另一种解释。因果推理的能力门槛、Think2SQL 的底分交叉、Spurious Rewards 的家族差异，都要求这一层诊断。

**第二，给“可扩展”一个预算上的检验。** 保留多个训练检查点，用较低预算预测后续运行，并同时报告梯度更新、生成 token、GPU 型号与小时数。若曲线还未显现饱和，拟合渐近线的不确定性应当留下。若下游成绩停滞而训练奖励继续增长，应分析数据覆盖与奖励代理，而不是继续把奖励曲线当成能力曲线。

**第三，把 rollout 数和新题数分开比较。** 固定总轨迹数、固定总生成 token、固定墙钟预算，会给出不同的最优分配。特别是模型变强后，原训练集可能大量变成全对组；此时更难且可靠的新题，可能比对旧题继续加采样更重要。这是从组内信号机制得到的推断，仍需目标模型上的等预算实验验证。

**第四，跨到大模型时重新检查数值与分布偏差。** 小模型同一引擎同步训练中看不见的问题，可能在大规模 MoE、异步 rollout 和长序列里成为主导因素。应观察实际采样引擎与训练引擎的 log-prob 差异、策略滞后、截断率和奖励失效，而不能只确认算法名与小模型相同。

对数百 B 到千 B 的外推，最缺的仍是联合受控证据：同一家族、可比较的初始化，分别改变参数规模、独立问题覆盖和生成预算，既按样本数比较，也按真实计算成本比较；能力评测则保持验证器、温度和 pass@k 定义一致。这个缺口使我们可以判断**哪些机制值得带过去验证**，却还不能从一张小模型排行榜预测大模型的最优配方、最终上限或投入产出比。
