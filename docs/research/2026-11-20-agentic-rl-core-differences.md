# Agentic RL 相对于一般大模型 RL，核心差异在哪里？

同样是训练模型回答“这部小说的作者出生在哪个省？”，可以把问题和预先检索的资料一次性交给模型，也可以让模型先查作者，看到检索结果后再决定查谁的出生地、怎样缩小查询范围、何时提交答案。两种设置都可以在最后按答案是否正确给分，也都可以用 PPO 或 GRPO。核心差异出现在**训练轨迹的生成过程**。在后一种设置里，策略的动作决定它会获得什么观察，观察又成为下一次决策的输入。强化学习于是可以优化模型如何获取和利用信息，以及何时结束交互。[Search-R1，§§3.1–3.4](https://arxiv.org/html/2503.09516v5#S3)

这里把“一般大模型 RL”具体限定为**固定输入、生成途中无外部观察的后训练**。输入可以包括预取资料，也可以因样本而异。“Agentic RL”在本文中指训练数据来自策略与外部环境的交互轨迹，环境观察能够影响同一任务中的后续动作。以下以在线采样说明机制。综述用整条回复作为一个任务级动作来描述固定输入的情形，用多步决策过程来描述交互情形。两边都可以继续把生成拆到 token 级。这里的“单轮”按外部交互数来理解，一条单轮回复仍然可以包含很长的自回归推理。[综述，§§2.1–2.4](https://arxiv.org/html/2509.02547v5#S2) · [Turn-PPO，§§2.1–2.3](https://aclanthology.org/2026.findings-eacl.328.pdf)

## 一次查询如何改变训练轨迹

仍以这道问答题为例。这是说明性对照，两边采用同一题目和同一终局判分规则。固定输入的策略从题目和已给资料生成完整回复。即使模型在回复中写出两条查询，训练环境也不会执行它们。交互式策略先生成关于小说作者的查询。检索系统返回作者姓名后，策略才生成关于那个人的第二次查询。如果第一轮返回的是同名作品，策略还可以根据这一观察改查作品的出版年份。前一轮选择会改变后一轮遇到的情境。即使检索索引固定、同一查询每次都返回同样的结果，换一个查询也会改变后续观察。Search-R1 就在训练时执行查询，把检索段落插回上下文，再恢复生成，直到模型提交答案或触及动作预算。[Search-R1，§3.2 算法 1、§4.3](https://arxiv.org/html/2503.09516v5#S3.SS2)

用回合记号写，令 $h_t$ 表示模型本轮实际看到的上下文，$a_t$ 是其生成的本轮动作。策略按 $\pi_	heta(a_t\mid h_t)$ 采样，若动作触发工具，环境返回观察 $o_{t+1}$，运行时据此构造下一轮的上下文 $h_{t+1}$。完整历史可以直接拼接，也可以重组或压缩。固定输入生成同样会随 token 增加而改变上下文，但新增内容来自自身的生成前缀。交互轨迹还包含环境产生的内容，且模型看到的片段可能只覆盖环境状态的一部分。[综述，§§2.2–2.4](https://arxiv.org/html/2509.02547v5#S2) · [Agent Lightning，§§3.2.2、3.3.2](https://arxiv.org/html/2508.03680v1#S3)

这个区分直接进入策略更新。若环境响应机制保持固定，一条已发生轨迹的概率由模型动作和环境转移共同决定。在同一轨迹上比较新旧策略时，环境部分在概率比里相消，动作的概率比由模型生成的 token 给出。Search-R1 的 PPO 和 GRPO 因此保留检索文本作为后续生成的条件，同时将它排除在策略损失直接计分的位置之外。发起查询和读完结果后作答都由模型生成，两处的生成 token 都参与更新。查询策略改变后，下一批轨迹也可能看到不同的文档。[Search-R1，§3.1 式（2）–（3）、附录 A](https://arxiv.org/html/2503.09516v5#S3.SS1)

## 观察给模型看，奖励给优化器用

第一次检索返回的作者姓名是**观察**，因为它供模型决定下一步查什么。答案是否正确是**任务奖励**，因为它进入训练目标。假如系统还评估第一轮是否找到了正确作者，并把这个分数用于优化，那才增加了一项过程奖励。观察和奖励可以来自同一个事件，也可以分开提供。Search-R1 每次检索都给模型看结果，整条轨迹的任务奖励却只看最终答案的精确匹配。论文同时研究了 PPO 和 GRPO，说明多轮训练可以沿用这两类更新方法。[Search-R1，§§3.1–3.4、§5.1](https://arxiv.org/html/2503.09516v5#S3)

反过来，DeepSeekMath 的过程监督 GRPO 先从固定数学题采样多份完整解答，再用过程奖励模型给各推理步骤评分。它归一化步骤分数，把位置不早于某个 token 的步骤分数相加，作为该 token 的优势。于是同一条解答前后可以收到不同的训练信号，生成过程仍按固定题目和自身前缀推进。这里的“过程”指分数对应解答的哪个位置，评分可以在采样完成后进行。两篇论文合起来说明，**是否有中途观察**与**任务奖励落在哪些位置**是两个设计维度。[DeepSeekMath，§§4.1.2–4.1.3](https://arxiv.org/html/2402.03300v3#S4.SS1)

## 同一个终局分数，怎样传给前面的动作？

假设一条成功的轨迹先查对了作者，中途又做了一次多余检索，最后答对。同题另一条轨迹因为认错作者而答错。仅凭这两个终局分数，可以比较两条完整轨迹的表现。至于成功轨迹中哪次检索真正有用，要看优势估计利用了什么信息。

- **整条轨迹共用一个优势。** 把结果监督版 GRPO 用于多轮轨迹时，对同一题的多条轨迹计算组内相对分数，再将每条轨迹的优势赋给它所有参与更新的生成 token。成功轨迹中的有效查询、多余查询和最终答案因此共享一个优势系数，各 token 的实际更新还取决于自己的概率比和梯度。在多次采样中，好查询可以因更经常出现在高回报轨迹中而获得强化。但同一条轨迹里的有效查询和多余查询得不到不同的优势系数。若一组轨迹全部答错，终局分数连组内尝试也区分不开，即使有些轨迹已经找对了作者。[DeepSeekMath，§4.1.2](https://arxiv.org/html/2402.03300v3#S4.SS1.SSS2) · [Turn-PPO，§2.4、图 1](https://aclanthology.org/2026.findings-eacl.328.pdf#page=3)
- **用 critic 区分动作前后的情境。** 以回合为单位，$V(h_t)$ 估计从本轮上下文出发、继续执行策略的预期回报。以不加 KL 塑形、只给终局奖励的设置为例，中途的即时奖励 $r_t=0$，但 TD 残差 $\delta_t=r_t+\gamma V(h_{t+1})-V(h_t)$ 仍可非零，其中 $\gamma$ 是折扣因子。若检索结果澄清了作者身份，下一轮的预计回报可能上升，这个变化就进入本轮的优势估计。GAE 再按 $\gamma\lambda$ 衰减汇入后续残差，$\lambda$ 控制后续残差的权重；抵达终局时，后继价值取零。价值差反映的是一次实际转移及 critic 的估计，其中也可能包含检索运气和估计误差。[Turn-PPO，§§2.3–2.4](https://aclanthology.org/2026.findings-eacl.328.pdf#page=4)

PPO 可以在 token 或回合上估计优势。Token-PPO 在生成前缀上估值，一次推进可能只多出一个模型 token，也可能在回合交界处接入一整段工具观察。Turn-PPO 把整段模型回复视为一个动作，在回复前、已读入本轮提示或观察的位置估值，同轮生成 token 共享该轮优势。论文的 actor 还把一轮内的 token 概率比相乘，在整轮上做 PPO 裁剪。这样，**估值的时间步和裁剪的单位都变了**。如果使用相同的逐步折扣，按 token 和按回合计时也会让奖励衰减不同，较长的回复在 token 时间轴上会跨过更多步。[Turn-PPO，§§2.2–2.4、表 1](https://aclanthology.org/2026.findings-eacl.328.pdf#page=5)

Turn-PPO 的原论文在 WebShop 和 Sokoban 上比较了轨迹级组相对优势的 GRPO、Token-PPO 和 Turn-PPO。表 2 的五种任务和模型组合中，Turn-PPO 的平均奖励均高于 Token-PPO。GRPO 在两种 WebShop 配置上完成训练，在启用长推理的 Qwen3-1.7B WebShop 配置和两种 Sokoban 配置上训练失败。两种 PPO 同时改变了价值估计、优势和裁剪的粒度，表 2 衡量的是整套改动的表现。[Turn-PPO，§§3.1–3.4、表 2、图 3](https://aclanthology.org/2026.findings-eacl.328.pdf#page=7)

还可以只改变**训练样本的组织方式**。Agent Lightning 把每次模型调用记录成该次的实际输入、输出和分配所得的分数，再交给单轮优化器。论文中的 LightningRL 先把同一个终局回报赋给该任务轨迹中的每次调用，再由单轮算法处理调用里的 token。对于会重写提示或压缩上下文的工作流，按次记录能让训练使用当时实际输入模型的上下文。把轨迹拆到调用级，并不要求每次调用获得不同的分数。[Agent Lightning，§§3.2.2、3.3.2、图 3](https://arxiv.org/html/2508.03680v1#S3.SS3)

## Rollout 怎样采到这样的轨迹？

交互让采样器在运行时间上也有了回合边界。模型生成查询，运行时解析并发出请求，这条轨迹要等到检索结果才能继续。若整批轨迹在每一轮统一等待，慢请求会拖住已经拿到结果的轨迹。AgentFly 在采样内部让各条轨迹独立推进，工具调用采用非阻塞执行。等待检索的轨迹可以暂挂，已取得观察的轨迹可以继续生成。对有状态环境，后续行动还要回到对应的环境实例。训练端需要的记录随目标函数而变，例如按 token 更新时要识别动作位置，按回合估值时要找回模型在行动前实际看到的上下文。Search-R1 的连续序列加掩码和 Agent Lightning 的逐调用记录是两种具体表示。[AgentFly，§§2.1–2.4](https://arxiv.org/html/2507.14897v1#S2) · [Search-R1，§§3.1–3.2](https://arxiv.org/html/2503.09516v5#S3) · [Agent Lightning，§§3.2.2、3.4](https://arxiv.org/html/2508.03680v1#S3)

**各条轨迹并发等待工具**与**采样和参数更新并行**是两个调度层次。前者可以让整批继续使用同一版策略。后者若允许训练器在未完成的采样期间发布权重，训练批就可能含较旧策略的数据，单条轨迹甚至可以由不同版本生成。AReaL 的论文在单步数学和代码任务中已经遇到这一问题，因此限制采样数据的陈旧程度，并在 PPO 目标里区分实际采样的行为策略和用于裁剪的近端策略。它还用单元测试给已生成的代码打分，测试结果在这套流程里进入奖励，未进入同题下一次生成。这也说明，调用外部执行器或采用异步采样都可以出现在固定输入的训练里。[AReaL，§§4.1–5.2、附录 E](https://arxiv.org/html/2505.24298v5#S4)

回到开头的问答题，固定输入训练优化的是给定题目与资料后的生成行为，交互式训练还把**选择下一次取证动作及根据结果调整行为**纳入优化。终局分数可以保持相同，决定学习信号如何回到查询动作的是信用估计，决定训练器能否拿到正确条件和动作记录的是 rollout 系统。本文的同题对照用于解释这一因果链。Search-R1 的真实问答实验比较了包含不同检索能力和训练方式的系统，交互本身对效果的独立贡献仍需要控制信息访问和预算的对照。[Search-R1，§§4.2–4.4、表 2](https://arxiv.org/html/2503.09516v5#S4)
