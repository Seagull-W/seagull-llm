0.5B–3B 小模型预训练：过度训练边界、退火配方、深窄架构与蒸馏取舍 ​

把百亿参数大模型的预训练经验直接缩放到 3B 以下，会在三个地方失灵：词表吃掉两成以上参数预算、固定配方拉长训练诱发微调退化、盲目挂大教师做蒸馏反而跑输硬标签。近两年端侧模型实现越级表现，靠的是把数据量推向 4T–36T（数千至上万 tokens/参数）的同时，用末期退火承接高密度推理语料、用绑定词表与深窄结构榨干参数容量、按“有无现成同族教师”切换剪枝蒸馏与从头预训练。

Q1 · 缩放律与算力分配M = D/N 边界

固定网页配方的有效上限在 ~2,000×；突破 6,000×–10,000× 必须靠分阶段换挡。

OLMo-1B 训到 3T（~3,000×）微调后反比 2.3T 跌 2%–3%[1]；工业界推到 11T–36T（SmolLM2 / Qwen3）均依赖后期切入合成推理数据与学习率退火[2][6]。

Q2 · 数据过滤、合成与退火最后 10% 定胜负

网页分类器负责打底，真正撬动数学与代码飞跃的是最后 10% 步数的线性退火。

SmolLM2-1.7B 前 10T 恒定学习率阶段 GSM8K 仅到 10.0%，最后 1T 退火注入 FineMath4+ 与 Stack-Edu 后直接跳至 32.6%（+22.6 pp）[2]。

Q3 · 架构设计取舍深窄 + 绑词表

3B 以下“架构无关论”不成立：必须绑定输入输出词表，把省下的参数换成 30–54 层深度。

MobileLLM 证实等参数下 32 层比 5 层阅读问答翻倍（14.5 vs 7.8）；GQA（3:1–4:1）与紧邻块共享在不涨体积下继续提分，且 Qwen3 明确以 4B 为词表绑定分界线[3][6]。

Q4 · 从头训 vs 蒸馏 vs 剪枝看有无现成教师

只训单个小模型且无现成教师时，从头训练必胜；有同族大模型时，“剪宽不剪深 + 纯 Logit KLD”省 40 倍数据。

Apple 缩放律证明计入教师预训练算力时蒸馏恒输从头训[4]；NVIDIA Minitron 证明 15B→8B→4B 迭代剪宽配纯 KLD 比等算力从头训高 +18.1 pp MMLU[5]。

一、过度训练的双重边界：推理账把数据推向 10T+，微调敏感度却在 2.5T 设卡 ​

核心判断：Chinchilla 的 M = D/N ≈ 20 只优化单次预训练算力；一旦计入端侧高频推理开销，把 0.5B–3B 模型喂到 2T–18T tokens（M ≈ 2,000–15,000）在经济学上完全划算。但用单一网页分布硬拉长度存在隐蔽上限：模型参数的扰动敏感度随步数单调累积，过了拐点后“基座越训越强、微调后反而越差”。

小模型敢于“过度训练（Over-training）”，底气来自 Gadre 等对 0.011B–6.9B 模型的重参数化缩放律验证[7]。将总训练算力记为 C = 6ND、词元参数比记为 M = D/N，验证集交叉熵严格服从平行对数幂律：

C4 实测拟合 （RedPajama 为 ）：直到 M = 640，斜率 始终不变，仅由 支付边际算力折损[7]。固定参数量 N 时，每把预训练数据翻倍，推理端延迟与显存完全不变，下游 17 项任务平均错误率仍按指数规律可预测地下降。正因如此，SmolLM2-135M / 360M / 1.7B 分别训到 2T / 4T / 11T，Qwen2.5-1.5B 训到 18T，Qwen3-0.6B / 1.7B 更共享了 36T tokens 语料池[2][6]。

然而，Springer 等（2025）指出了此前被基座榜单掩盖的第二重边界——灾难性过度训练（Catastrophic Overtraining）[1]。真正的部署模型都要经过 SFT、多模态对齐或 RL；当预训练在同一分布上推进过久，参数对后续权重更新的渐进敏感度（Progressive Sensitivity）会超过基座自身的增益速度。

二、数据配方：网页双分类器打底，最后 10% 退火注入合成与推理语料定胜负 ​

核心判断：小模型容量有限、对噪声极度敏感，数据配方的收益分两层兑现：① 稳定期（前 85%–90% 步数）不能迷信单一“教育分”分类器，混配问答风格网页能补齐常识短板；② 退火期（最后 10%–20% 步数）学习率线性归零时，集中上采样精筛数学/代码与合成教科书，能用 1T 预算跑出前面 10T 都拿不到的推理跃迁。

在网页过滤环节，SmolLM2 的 350B 受控消融揭开了一个常被忽视的偏差：同样是用模型分类器清洗 Common Crawl，分类器的打分偏好直接决定了小模型长出哪类能力[2]。

FineWeb-Edu（Llama-3-70B 教育打分，1.3T）强于学科知识

偏好教材与结构化讲解。单训 350B 时 MMLU 达 37.5、ARC 达 57.5，但日常语境与常识偏弱（HellaSwag 60.1，CommonsenseQA 仅 36.2）[2]。

DCLM（OpenHermes + ELI5 fastText，3.8T）强于常识推理

偏好真实问答与口语推演。单训 350B 时 HellaSwag 升至 62.3、CommonsenseQA 升至 40.1，但 ARC 跌至 53.5。按 60/40 混配后两头兼得（ARC 56.0 + HellaSwag 62.2）[2]。

真正拉开现代 0.5B–3B 模型代差的，是专用精筛/合成语料与 WSD（Warmup-Stable-Decay）退火阶段的耦合。高质量推理语料总量往往只有百亿级（如 FineMath4+ 仅 10B tokens、Stack-Edu 125B、合成教科书 Cosmopedia v2 30B）；若从第 0 步就均匀撒进 11T 大池子，要么占比不到 0.1% 被网页噪声淹没，要么重复几十轮触发过拟合（Muennighoff 4–5 轮上限）[2]。SmolLM2 与 Qwen3（S2 推理加速衰减阶段 5T）一致采用了“前期雪藏、中期试水、退火重仓”的节奏[2][6]。

一个关键的规模反例：多阶段课表并非越小越灵。Hugging Face 在训练更小的 SmolLM2-135M (2T) 与 360M (4T) 时重新跑了全长消融，发现亚十亿模型容量太窄，取消多阶段切换、从头到尾全程喂入高纯度混合语料（经 FW-Edu 二次过滤的 DCLM + Stack-Edu + FineMath + Cosmopedia，配 20% WSD 退火）反而效果最佳[2]。同时，用 15 个语言专属分类器清洗出的 Stack-Edu 在缩减 57%–84% 代码体积后，使 Python HumanEval 从 20.7 → 25.6、C++ 从 16.7 → 24.8[2]——对小模型而言，删掉低信息密度代码比堆总词元重要得多。

三、架构取舍：回收“词表税”，把预算全部换成深窄层数与片上复用 ​

核心判断：Kaplan 提出的“固定总参数下深宽比无关紧要”在 3B 以下完全失效。小模型头号结构包袱是输入输出词表矩阵吃掉了 20%–40%+ 参数；高性价比标准解是：词表控制在 32k–64k + 强制绑定输入输出 Embedding + GQA（3:1–4:1）+ SwiGLU，再将省出的全部参数投入 30–54 层深而窄的骨干中。

为什么大模型不在乎词表共享，一到 0.5B–3B 就成了生死线？设隐藏维 d = 512、词表 V = 32,000，输入词嵌入与输出 LM Head 各占 16.4M 参数，两块合起来占掉 125M 模型超过 23% 的权重；倘若照搬大模型流行的 128k–152k 多语种大词表且不共享（如 d = 1536、V = 151,936），仅输入输出两张表就要吞掉 4.67 亿参数——还没排一层 Transformer，一个 0.5B 模型就已经爆仓了！而在 70B 模型中，词表占比仅 0.7%[3]。这正是为什么 Qwen3 架构表精确以 4B 划界：0.6B / 1.7B / 4B 全部开启 Tie Embedding = Yes，到了 8B / 14B / 32B 才解绑[6]；SmolLM2 亦专门定制了紧凑的 49,152 词表并绑定权重[2]。

四、三条路线正面对决：从头预训练、Logit 蒸馏与结构化剪枝谁更占优？ ​

核心判断：“蒸馏一定比从头训好”是错觉。Apple 蒸馏缩放律与 NVIDIA Minitron 拼出了完整真相：① 没有现成教师、只造单个端侧模型时，直接从头预训练在任意算力预算下都优于“先训大教师再蒸馏”；② 已有现成强教师时，蒸馏在中低数据预算下大幅领先，但大教师不能强过头（容量鸿沟）且超长预算下会被从头训练追平；③ 若手里已有同词表同族大模型（如 8B/15B），“结构化剪宽 + 纯 Forward-KL Logit 蒸馏”能省下高达 40 倍重训数据并大幅碾压等算力从头训。

剪宽不剪深（Width over Depth）：Minitron 表 10 将 15B 压到 ~8B 时，纯宽度剪枝（裁 MLP 神经元、注意力头与通道，7.74B）重训后验证损失为 2.049，显著击败参数反而更多的纯深度剪层（9.39B，损失 2.155–2.177）以及深宽混剪（7.91B，损失 2.062，重训 200 步后即被纯剪宽反超）[5]。

纯 Forward-KL 最优 + 后训练接在线强弱蒸馏：Minitron 表 15 显示单用 Llogits(KLD) 困惑度最优（8.720），混入硬标签 CE 退至 8.791，改用 Reverse-KL 恶化至 9.008（Apple 表 7 同样证实 Forward-KL 2.42 优于 Reverse-KL 2.70）[4][5]；在不大幅删层时，加中间隐藏层对齐损失并无额外收益（Minitron 表 18：MMLU 58.0 vs 58.3）[5]。进入后训练推理阶段后，Qwen3（表 21）证明用 Off-policy + On-policy 强到弱蒸馏仅耗 1/10 GPU 小时（1,800 vs 17,920）即可把 AIME’24 推至 74.4%，反超直接 RL 的 67.6%[6]。

首选路线 迭代结构化剪宽 + 纯 Logit KLD 重训
直接拿已完成多阶段退火的最终基座，用 1024 条校准样本单次前向估激活重要性（Batch L2 + Seq Mean），保留层深、裁剪通道/MLP/头[5]。
数据与算力账 仅需原模型 <3%–10% 数据（90B–1T）
跨度超 50% 参数时分两跳（如 15B→8B→4B 或 8B→3B→1B），每步重训均用高质量退火段语料与纯 Forward-KL（τ=1）。
必避陷阱 严禁只剪枝+普通 CE 重训；严禁拦腰砍半层数
不加教师软分布会导致 MMLU 跌回随机猜测；砍层深虽零样本略好看，重训 200 步后即输给剪宽。
首选路线 深窄绑定架构 + 从头 WSD 超训与末期退火
词表定在 32k–64k 并绑定输入输出 Embedding，采用 30–54 层深窄比例 + SwiGLU + GQA(3:1~4:1)，不花算力先训临时教师[3][4]。
数据与算力账 预算配至 2T–11T+ tokens（M ≈ 3,000–10,000×）
<0.5B 全程喂高纯度混合数据；1B–3B 前 90% 用双分类器网页+基础代码打底，最后 10% 线性退火重仓精筛推理与合成教材[2]。
必避陷阱 警惕单一网页分布硬训过 2,500× 诱发微调退化
必须监控“微调后检查点”而非仅看 Base 指标，并在退火与 SFT 阶段收紧学习率以抑制参数敏感度遗忘[1]。
首选路线 匹配尺度的现成过训练教师 Logit 蒸馏
处于 Apple 蓝红相图左侧深蓝区：直接用同词表或对齐后的现成教师提供高覆盖率 Forward-KL 信号，收敛速度远快于硬标签[4]。
教师选择铁律 选“小而充分过训练”的教师，而非巨型未训透教师
学生损失只认教师损失 LT；参数更小但充分过训练的教师（如 4B–8B）能以低得多的推理开销提供同等 LT 且避开容量鸿沟[4]。
后训练衔接 接两阶段强到弱蒸馏（Off-policy → On-policy）
后训练阶段用在线策略 Logit 对齐替代昂贵的小模型从头 RL，可以十倍算力优势获得更高数学与代码推理分[6]。
实验口径、评测差异与未核实边界说明（按需展开）

1. 参数口径差异：Apple《Distillation Scaling Laws》全文以非词表参数记 N，而 MobileLLM、SmolLM2 与 Minitron 主表默认报告含词表总参数量（Minitron-4B 非词表参数为 2.6B，落入本文核心关注的 ≤3B 骨干区间）。

2. 跨工作榜单不可直接横比绝对分：SmolLM2 的 MMLU 进展采用显式四选一生成格式（MCF），Qwen3 的 GSM8K/MATH 采用 4-shot CoT 评测，MobileLLM 聚焦 8 项零样本常识推理与 TQA/RACE。本文所有结论均严格取自各论文内部控制变量消融表。

3. 待进一步实证的空白：公开文献中尚缺少在 ≥10T 词元与 ≥50B 合成推理退火条件下，对同一 1B–3B 架构完全等总算力横评“从头 WSD 超训 vs 同族 8B 剪宽蒸馏”的端到端开源对照。
