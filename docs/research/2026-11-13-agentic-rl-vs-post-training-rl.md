# Agentic RL 与一般后训练 RL：从回答评分到交互轨迹

**Agentic RL 把外部环境反馈接入后续决策：模型此前的行动，参与决定它下一次会看到什么、还能做什么。** 这让训练能够覆盖查资料、操作软件、依据执行反馈修正行动，也让一次成败穿过模型与环境的多重依赖。[Landscape，§2](https://arxiv.org/html/2509.02547v5#S2)

## 决策边界与信用分配，构成两条比较轴

Agentic RL 本身也可用于后训练。本文把它与常见的单轮后训练 RL 比较，后者取“给定 prompt，生成完整回答，再评分”的设置。偏好对齐中，InstructGPT 先做监督微调，再用人工比较训练奖励模型，最后用 PPO 优化回答；可验证奖励 RL（RLVR）则由规则检查正确性，例如 DeepSeek-R1-Zero 的答案与格式奖励配合 GRPO。两者的评分依据不同，交互边界相同。原始 DPO 直接在离线偏好对上优化策略，省去独立奖励模型和在线 RL 循环，是同一偏好优化问题的另一种训练方法。[InstructGPT，§3](https://arxiv.org/pdf/2203.02155)；[R1，§2.2](https://arxiv.org/html/2501.12948v1#S2.SS2)；[DPO，§4](https://arxiv.org/html/2305.18290v3#S4)

把整条回答视为动作，单轮训练就是上下文 bandit：策略先看到题目这个“上下文”，选出一条回答，获得评分，本轮任务结束；它无需根据执行后返回的观测再选下一次动作。这也可写成回合长度为一的退化马尔可夫决策过程（MDP）。若把回答展开到 token，前缀又可作为状态，逐 token 生成仍构成序列决策；“单步”指任务与环境交互的粒度，并不表示内部只有一次选择。[RLOO，§2.1–2.3](https://arxiv.org/html/2402.14740v1#S2)

在网页、文件系统等任务里，模型只看到截图、查询结果或读出的文件，完整环境状态还包含未观察的信息。因此可用部分可观测马尔可夫决策过程（POMDP）描述：策略依据已有观测与行动历史决策，环境执行后产生下一次观测。[OSWorld，§2.1–2.4](https://arxiv.org/html/2404.07972v2#S2)

据此，需要把两条轴分开。第一条是**环境交互轴**：生成过程中是否执行外部动作，并让环境状态转移产生的观测进入后续决策。这里的“外部观测”由检索器、程序或界面返回，即使最终表示成文本，也不是策略自回归采样出的 token。第二条是**优化跨度与信用粒度轴**：目标覆盖一条回答还是多次调用，奖励放在哪些位置，又按整段、调用或 token 估计优势。这条轴内部，奖励位置和信用粒度仍是不同选择；终局奖励也可以用于逐 token 信用估计。下面的表按这些选择展开，而不把奖励密度作为两类任务的分界。

| 比较层次 | 本文的单轮后训练基线 | 多轮 agentic RL |
| --- | --- | --- |
| 环境交互：状态与观测 | prompt 与已生成前缀；生成中没有新的外部观测 | 环境状态与可见观测分开，行动与观测历史用于决策 |
| 环境交互：动作与转移 | token 接续形成完整回答；提交后本轮结束 | 输出经执行触发环境转移，返回观测后继续决策 |
| 优化跨度 | 覆盖一条回答，可展开到 token 或推理步骤 | 覆盖多次模型调用，各次调用又可展开到 token |
| 奖励位置 | 可仅给终局评分，也可对回答内部步骤评分 | 可仅给终局评分，也可对中间行动或子目标评分 |
| 信用分配粒度 | 可共享整段回报，也可估计前缀条件下的逐 token 优势 | 既有跨调用归属，也有调用内的 token 归属；实现可以作粗粒度简化 |

这两条轴可以交叉。单轮回答即使加入推理步骤的过程监督或步级奖励，只要生成中没有引入外部观测，仍处于表的左侧；过程标签如何转成 RL 奖励，是另一个设计问题。反过来，Search-R1 多轮调用检索器，却只按最终答案给任务奖励，位于“外部交互＋终局奖励”这一组合。[Search-R1，§3.1、§3.4](https://arxiv.org/html/2503.09516v5#S3) 这些组合说明，交互结构决定策略能利用什么反馈，奖励与信用设计决定反馈怎样进入更新。

任务目标可以在保持这些区别的前提下写成：

$$
J_{\mathrm{answer}}(\theta)=\mathbb{E}_{x\sim D,\,y\sim\pi_\theta(\cdot\mid x)}[R_{\mathrm{answer}}(x,y)],\qquad
J_{\mathrm{agent}}(\theta)=\mathbb{E}_{\tau\sim\pi_\theta,P}\left[R_{\mathrm{agent}}(\tau)\right],\quad
R_{\mathrm{agent}}(\tau)=\sum_{t=0}^{T-1}\gamma^t r_t.
$$

这里，$D$ 为题目分布，$x$ 为题目，$y$ 为参数是 $\theta$ 的策略 $\pi_\theta$ 生成的回答；$R_{\mathrm{answer}}$ 可以是终局评分，也可以汇总回答内部的步骤奖励。$\tau$ 是策略与环境转移 $P$ 共同产生的轨迹，$T$ 是交互长度，$r_t$ 是第 $t$ 次交互的奖励，$\gamma$ 控制远期奖励的权重，有限回合可取一。只在最后一步令 $r_t$ 非零，就得到多轮任务的终局奖励设置。两式都只展示任务回报，实际优化还可加入 KL 约束；它们没有指定优势必须按什么粒度估计。结构上的变化在于右式的采样还依赖外部环境 $P$：一次查询即使没有立即得分，也可能因改变观测、改善后续决策而有价值。[Landscape，§2](https://arxiv.org/html/2509.02547v5#S2)；[Agent Lightning，§3.2](https://arxiv.org/html/2508.03680v1#S3.SS2)

## 动作执行以后，下一次输入也变了

沿环境交互轴看，关键变化发生在输出被执行之后。单轮模型输出一段代码，测试器可以在结束后为它打分；多轮模型则可以运行代码、看到报错、再修改。前者优化一次提交，后者还学习何时测试、如何利用报错及何时停止。执行反馈进入了策略的下一次输入。

这些动作在模型端仍可用 token 表示，区别发生在执行语义。自由文本用于解释与推理，结构化调用经解析后触发查询、写文件或点击。复合动作还可由一串原始动作组成，并递归嵌套；因此一次模型输出、一次工具调用和一个环境原子动作，可能对应不同的计数单位。[Landscape，§2.3](https://arxiv.org/html/2509.02547v5#S2.SS3)

Search-R1 给出了信息获取型循环：模型生成 `<search>` 查询，运行器暂停生成并调用检索器，将结果放回上下文，模型再决定继续搜索还是回答。搜索语料可以固定，轨迹里的可见信息仍随查询而变。训练数据因而交错包含“模型生成”和“外界返回”两类 token；其策略损失屏蔽检索内容，只优化模型生成的部分。[Search-R1，§3.1–3.3](https://arxiv.org/html/2503.09516v5#S3)

工程上，由动作语义产生了新的有效性条件：调用必须能解析，参数必须能执行，返回结果要与对应动作对齐。格式错误会改变下一步可获得的信息，环境超时则可能中断整条轨迹。[Agent Lightning，§3.4](https://arxiv.org/html/2508.03680v1#S3.SS4)

## 奖励出现在哪里，与功劳归给谁，是两件事

动作决定了下一次可见的信息，训练还要规定这些行动怎样获得回报。在本文的单轮基线中，任务奖励通常是回答结束时的一个标量，它也可以汇总正确性、格式等多个分量。沿第二条轴，单轮可以对回答内部的推理步骤评分；多轮则还可以对跨调用的子目标评分，例如任务完成时给终局奖励，达到子目标时给步级奖励，其余步骤为零。只保留终局评分，早期行动通过最终结果获得学习信号；加入中间评分，可以让部分进展成为学习信号，同时把“什么算进展”的判断写进了目标。若某项子奖励可以反复领取，策略就可能靠重复操作累积回报。因而组合奖励还包含触发次数、权重与终止条件：这些设置会改变什么行为更值得学习。[R1，§2.2.2](https://arxiv.org/html/2501.12948v1#S2.SS2.SSS2)；[Environment Scaling，§4](https://arxiv.org/html/2511.09586v3#S4)

奖励密度是设计选择。这里涉及的 RLOO，全称 REINFORCE Leave-One-Out（留一法）：对同一输入采样多个输出，更新其中一个输出时，用其余输出的平均回报作为基线，从该输出的回报中减去；这使更新比较的是它相对同组样本的表现，无需另学价值网络。[RLOO，§2.3](https://arxiv.org/html/2402.14740v1#S2.SS3)

Search-R1 的多轮搜索只用最终答案的精确匹配奖励。[Search-R1，§3.4](https://arxiv.org/html/2503.09516v5#S3.SS4) 《Practitioner's Guide》在 TextWorld 的 tw-simple、Qwen-7B、3000 回合设置下比较三档密度：PPO 从稀疏的 41% 降到中等密度的 29%，再到最密一档的 58%；RLOO 从 35% 升到 55%，并在两档稠密配置下都停在 55%。从稀疏到中等密度，两种算法的变化方向相反。原文 §7.1 讨论了 PPO 在最密一档的提升及 RLOO 在两档稠密配置下的稳定表现，但没有专门解释 PPO 在中等密度下退化的原因；相关附录也未提供将这次退化归因于裁剪、价值基线偏差或方差变化的消融证据。因此，这组实验支持的结论是奖励密度需与优化策略匹配，尚不能据此确定退化机制。[§7.1、表 11](https://arxiv.org/html/2510.01132v2#S7)

**奖励规定哪些结果值得获得；信用分配决定哪些历史决策因此被强化。** 先看只有终局任务评分的单轮情形。令回答 $y$ 有 $N$ 个 token，生成第 $i$ 个 token 前的上下文为 $h_i=(x,y_{<i})$，整段回报为 $R$。由自回归概率的乘积展开，在暂不计 KL、折扣与基线的简化下，REINFORCE 的一个样本梯度为：

$$
g=R\nabla_\theta\log\pi_\theta(y\mid x)
 =R\sum_{i=1}^{N}\nabla_\theta\log\pi_\theta(y_i\mid h_i).
$$

全段共享的是标量 $R$；每一项对数概率梯度却取决于当时的前缀 $h_i$、所选 token $y_i$ 和模型参数。因此，同一个回报乘在不同梯度向量上，会产生不同的参数更新贡献。“同回报”没有把各 token 的梯度变成相同，也没有识别出究竟哪个 token 导致成功。

PPO 常配一个价值网络 $V_\phi(h_i)$，用参数 $\phi$ 根据题目和已生成前缀预测此后按策略继续生成的期望回报。优势的基本含义是“实际或估计的后续回报减去该前缀的预期回报”。例如，取不折扣的蒙特卡洛回报时，可写成 $\hat A_i=R-V_\phi(h_i)$；即使 $R$ 相同，不同前缀的价值估计也会使优势不同。实际 PPO 常用广义优势估计（GAE），把各步奖励与相邻前缀的价值预测组合起来估计优势，再用于裁剪后的策略更新。它提供了更细的信用估计，也引入价值网络的训练成本与估计误差。**逐 token 优势并不要求逐 token 的任务奖励**，这正是奖励位置与信用粒度必须分开的原因。[RLOO，§2.1–2.3](https://arxiv.org/html/2402.14740v1#S2)

多轮轨迹又多了一层归属：最终结果应归到哪次决策、哪轮调用，再归到其中哪些 token。以一个说明性修复任务为例，前几轮可能正确定位了文件，后面一次写入才破坏了程序；整条失败轨迹共享惩罚，会把有用检索与错误修改混在一起。部分可观测进一步增加了判断难度：同样一段查询结果可能对应不同数据库状态，某步的作用也可能直到后续执行才显现。价值估计于是需要处理历史信息，比较替代动作还可能需要恢复中间状态并重新执行。[Credit Assignment，§2.2、§4](https://arxiv.org/html/2604.09459v1#S4)

信息获取本身也有信用。一次查询可能暂时没有推进任务，却排除了错误路径；事后看似多余的检查，在当时信息不足时可能合理。评价某轮决策，需要把它当时可见的上下文和后续才揭示的信息区分开，才能识别决策失误、信息缺口与必要探索。这也是仅靠终局结果反推步骤质量的难处。[Credit Assignment，§4.2](https://arxiv.org/html/2604.09459v1#S4.SS2)

现有实现对这层困难给出了不同简化。Agent Lightning 图 3 对比了两种组织方式：已有的多轮 GRPO 把整条轨迹拼接为一条训练序列，用损失屏蔽排除外部返回的 token；LightningRL 则把轨迹拆成多次模型调用的 transition，每个训练项包含当次输入、输出和分配到的回报。其当前实现把同一个最终回报赋给每次调用，再交给单轮算法；更细的高层价值估计留作扩展。[Agent Lightning，§3.3、图 3](https://arxiv.org/html/2508.03680v1#S3.SS3)

这一区别可以从对数概率的归属理解。拼接方式在一条长序列上计算模型生成位置的对数概率，检索结果等环境 token 仍是后续生成的条件，只是不作为策略动作计入损失。拆分方式则对每次调用计算“给定当次输入，生成当次输出”的对数概率；输入中的旧消息、摘要和工具结果都是条件，当前训练项只优化这次输出。因而，屏蔽处理的是一条序列中哪些 token 属于策略，拆分处理的是多次调用如何分别成为训练项；二者都还需要另行决定回报或优势怎样归属。

由这种条件概率分解可进一步看出 KL 与上下文代价。若使用相对参考策略的 KL 约束，拼接方式应在模型生成的位置、以相同前缀比较两策略；拆分方式则在每次调用的实际输入下比较输出分布。外部返回文本不应被当作策略生成的动作施加这项约束。若拆分前后条件上下文完全相同，并保持 token 权重与归一化方式一致，拆分本身不必改变这些对数概率项；若改用摘要或不同的调用权重，就改变了条件或训练权重，不能直接视为同一个目标。这里是对两种数据组织方式的机制推导，不是论文报告的等价性实验。

长序列保留完整历史，却要求一次训练容纳累积上下文；拆分允许按调用分批，并灵活构造较短输入，但若每次仍带完整历史，会重复处理前缀，单次输入也可能继续增长。压缩历史可减少长度，同时可能丢失后续决策所需的信息。拆分因此缓解了整条轨迹必须拼成一条训练序列的限制；同一终局回报仍赋给每次调用，则意味着有用检索与错误修改的贡献还未被区分。[Agent Lightning，§3.3.2](https://arxiv.org/html/2508.03680v1#S3.SS3)

## 环境既生产训练数据，也约束探索

上述信用估计依赖采样出的轨迹；若要比较某一步的替代行动，还依赖环境能否恢复到相应状态。这使环境成为训练方法的组成部分。静态偏好数据可用于训练奖励模型或直接做 DPO；进入 PPO、GRPO 阶段后，回答也会随当前策略在线采样。Agentic RL 新增的是环境参与的数据生成：相同初始任务下，策略选择不同动作，就会遇到不同观测、走到不同状态，产生不同后续训练样本。[InstructGPT，§3.2、§3.5](https://arxiv.org/pdf/2203.02155)；[R1，§2.2.1](https://arxiv.org/html/2501.12948v1#S2.SS2.SSS1)

Environment Scaling 用“任务生成—执行—反馈”描述这一循环：环境提供任务与初态，执行动作并返回观测，最后提供训练反馈。数据生产能力因此包含了任务分布、可执行动作和评价器。[§1、附录 A.3](https://arxiv.org/html/2511.09586v3)

软件任务体现了这种约束。SWE-Gym 为问题配套可执行仓库、依赖与测试，任务说明只是其中一部分；OSWorld 用虚拟机隔离桌面操作，并通过快照恢复初态。[SWE-Gym，§3.1](https://arxiv.org/html/2412.21139v2#S3.SS1)；[OSWorld，§2.2](https://arxiv.org/html/2404.07972v2#S2.SS2) 据此，扩大采样量还意味着复制环境、恢复状态和执行检查。同题多次尝试需要保持可比较的起点，失败尝试也消耗运行时间；外部服务限额、初始化速度和重置能力共同约束可承担的探索量。

重置粒度还决定能进行什么比较。从初态重跑，会得到另一整条轨迹；从中间状态分叉，才能比较该处不同后续选择的回报。后一种采样需要恢复相关文件、进程或数据库状态，对话历史只是恢复条件的一部分。环境能否保存这些状态，直接影响可采用的信用估计方法及其成本。[Credit Assignment，§4.1](https://arxiv.org/html/2604.09459v1#S4.SS1)

## 多轮 rollout 把训练变成混合负载

环境需要复制、执行与重置，这些工作会直接进入采样时延。单轮闭环以生成回答、评分、更新为主；多轮 rollout，即执行策略以采集轨迹，需要反复穿过模型生成、环境执行和反馈。RollArt 将负载拆成计算密集的 prefill、受显存带宽约束的 decoding、偏 CPU 的环境执行，以及突发的奖励评估。长历史增加上下文处理量，工具运行与测试又有各自的耗时分布。[RollArt，§2–3](https://arxiv.org/html/2512.22560v2#S2)

同步批次会被最慢的轨迹拖住：别的样本已经完成，仍需等待某个测试或环境返回。按轨迹独立调度、完成即评分，可以减少这类等待；训练与采样进一步异步后，训练器会收到旧策略生成的数据，需要管理权重版本和样本陈旧度。verl 的完全异步实现为此分离 Trainer 与 Rollouter，并提供陈旧度阈值。[RollArt，§4、§6](https://arxiv.org/html/2512.22560v2#S4)；[verl Fully Async](https://verl.readthedocs.io/en/latest/advance/fully_async.html)

这里新增的工程负担来自有状态执行：沙箱保存每条轨迹的文件与进程状态，运行器处理超时和失败，调度器在环境等待与 GPU 工作之间衔接。环境副本、执行日志、奖励结果和策略版本要能对应起来，训练样本才有可解释的来源。[Agent Lightning，§3.4](https://arxiv.org/html/2508.03680v1#S3.SS4)；[RollArt，§6](https://arxiv.org/html/2512.22560v2#S6)

## 成功率要连同完成任务的代价一起读

既然一条轨迹消耗生成与环境执行两类资源，评测就要同时说明完成了什么、花费了多少。单轮偏好对齐关心奖励模型分数与偏好胜率，RLVR 关心答案或测试通过率。交互任务还要验收行动留下的结果：τ-bench 比对回合结束时的数据库状态与标准终态，允许不同操作路径；OSWorld 用执行式评价器检查文件、应用状态等结果。[τ-bench，§3](https://arxiv.org/html/2406.12045v1#S3)；[OSWorld，§2.2.3](https://arxiv.org/html/2404.07972v2#S2.SS2.SSS3)

完成任务需要多少次交互，也会改变成功率的含义。OSWorld 把交互上限定在 15 步，并统计模型的步数分布；τ-bench 用 pass^k 衡量同一任务重复 k 次都成功的概率，gpt-4o 的平均成功率超过 60%，pass^8 降到 25% 以下，其成本分析给出每个任务 0.38 美元的 agent 费用与 0.23 美元的用户模拟费用。由这些评测结构可得，比较对象应是给定环境、工具、尝试次数和交互预算下的任务成功率，同时记录步数、token、时延或费用。失败轨迹与重试同样进入成本；用更多尝试换来的成功，会在这组指标里显现。[OSWorld，§4、附录 C.1、C.5](https://arxiv.org/html/2404.07972v2#A3.SS5)；[τ-bench，§5.1–5.2](https://arxiv.org/html/2406.12045v1#S5.SS1)

沿两条轴重新定位这些工作，关系就更具体了：InstructGPT 和 DeepSeek-R1-Zero 的本文基线都在“生成期间无外部观测、按整条回答评分”这一位置，但可以采用不同的奖励来源与优势估计；加入回答内部的步级奖励或过程监督，会改变反馈粒度，而不自动形成环境交互。Search-R1 则把检索反馈接入多轮决策，同时保留终局任务评分；Practitioner's Guide 在多轮环境中进一步比较奖励密度；Agent Lightning 改变调用的训练组织方式，当前却仍采用跨调用共享终局回报的简化。

这些组合说明，agentic RL 扩展的是行动与外部反馈形成闭环的范围，奖励密度和信用粒度需要另外选择。前一条轴带来查询信息、操作环境、依据执行结果修正行动的能力，也带来动作有效性、环境恢复与混合负载的成本；后一条轴决定能否把长跨度的成败更准确地归给历史决策，细化它可能需要中间评分、价值估计或额外采样。于是，更密的奖励不自动意味着更强的交互能力，更长的轨迹也不自动意味着更精细的信用分配；两者的收益与代价，要在具体组合及其评测预算下理解。
