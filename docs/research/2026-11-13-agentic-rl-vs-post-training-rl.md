# Agentic RL 与一般后训练 RL：从回答评分到交互轨迹

**Agentic RL 把优化对象从一条回答扩展为一段交互轨迹：模型此前的行动，参与决定它下一次会看到什么、还能做什么。** 这让训练能够覆盖查资料、操作软件、依据执行反馈修正行动，也让一次成败穿过模型与环境的多重依赖。[Landscape，§2](https://arxiv.org/html/2509.02547v5#S2)

## 一次决策在哪里结束，决定了训练问题

作为比较基线，一般后训练 RL 取“给定 prompt，生成完整回答，再评分”的设置。偏好对齐中，InstructGPT 先做监督微调，再用人工比较训练奖励模型，最后用 PPO 优化回答；可验证奖励 RL（RLVR）则由规则检查正确性，例如 DeepSeek-R1-Zero 的答案与格式奖励配合 GRPO。两者的评分依据不同，交互边界相同。原始 DPO 直接在离线偏好对上优化策略，省去独立奖励模型和在线 RL 循环，是同一偏好优化问题的另一种训练方法。[InstructGPT，§3](https://arxiv.org/pdf/2203.02155)；[R1，§2.2](https://arxiv.org/html/2501.12948v1#S2.SS2)；[DPO，§4](https://arxiv.org/html/2305.18290v3#S4)

把整条回答视为动作，单轮训练就是上下文 bandit，也可写成回合长度为一的退化 MDP。若把回答展开到 token，前缀又可作为状态，逐 token 生成仍构成序列决策；“单步”指任务与环境交互的粒度。[RLOO，§2.1–2.3](https://arxiv.org/html/2402.14740v1#S2)

在网页、文件系统等任务里，模型只看到截图、查询结果或读出的文件，完整环境状态还包含未观察的信息。因此可用部分可观测马尔可夫决策过程（POMDP）描述：策略依据已有观测与行动历史决策，环境执行后产生下一次观测。[OSWorld，§2.1–2.4](https://arxiv.org/html/2404.07972v2#S2)

| 比较项 | 单轮后训练 RL | 多轮 agentic RL |
| --- | --- | --- |
| 状态与观测 | 当前 prompt；生成中可展开为文本前缀 | 完整环境状态与模型可见观测分开，历史用于保留信息 |
| 动作 | 一条回答，由 token 构成 | 文本、工具调用与环境操作交替出现 |
| 转移 | 回答完成后进入终止态 | 行动触发确定或随机的环境转移，返回观测后继续决策 |
| 奖励 | 回答结束时得到任务评分 | 终局任务奖励，以及按需设置的中间奖励 |

任务目标相应写成：

$$
J_{\mathrm{answer}}(\theta)=\mathbb{E}_{x\sim D,\,y\sim\pi_\theta(\cdot\mid x)}[r(x,y)],\qquad
J_{\mathrm{agent}}(\theta)=\mathbb{E}_{\tau\sim\pi_\theta,P}\left[\sum_{t=0}^{T-1}\gamma^t r_t\right].
$$

这里，$D$ 为题目分布，$x$ 为抽取的题目，$y$ 为参数是 $\theta$ 的策略 $\pi_\theta$ 生成的回答，$r$ 为任务评分；$\tau$ 是策略与环境转移 $P$ 共同产生的轨迹，$T$ 是交互长度，$r_t$ 是第 $t$ 步奖励，$\gamma$ 控制远期奖励的权重，有限回合可取一。公式只展示任务回报，实际优化还可加入 KL 约束。结构上的后果是：一次查询即使没有立即得分，也可能因改善后续决策而有价值。[Landscape，§2](https://arxiv.org/html/2509.02547v5#S2)；[Agent Lightning，§3.2](https://arxiv.org/html/2508.03680v1#S3.SS2)

## 动作执行以后，下一次输入也变了

单轮模型输出一段代码，测试器可以在结束后为它打分；多轮模型则可以运行代码、看到报错、再修改。前者优化一次提交，后者还学习何时测试、如何利用报错及何时停止。执行反馈进入了策略的下一次输入。

这些动作在模型端仍可用 token 表示，区别发生在执行语义。自由文本用于解释与推理，结构化调用经解析后触发查询、写文件或点击。复合动作还可由一串原始动作组成，并递归嵌套；因此一次模型输出、一次工具调用和一个环境原子动作，可能对应不同的计数单位。[Landscape，§2.3](https://arxiv.org/html/2509.02547v5#S2.SS3)

Search-R1 给出了信息获取型循环：模型生成 `<search>` 查询，运行器暂停生成并调用检索器，将结果放回上下文，模型再决定继续搜索还是回答。搜索语料可以固定，轨迹里的可见信息仍随查询而变。训练数据因而交错包含“模型生成”和“外界返回”两类 token；其策略损失屏蔽检索内容，只优化模型生成的部分。[Search-R1，§3.1–3.3](https://arxiv.org/html/2503.09516v5#S3)

工程上，由动作语义产生了新的有效性条件：调用必须能解析，参数必须能执行，返回结果要与对应动作对齐。格式错误会改变下一步可获得的信息，环境超时则可能中断整条轨迹。[Agent Lightning，§3.4](https://arxiv.org/html/2508.03680v1#S3.SS4)

## 奖励出现在哪里，与功劳归给谁，是两件事

单轮训练的任务奖励通常是回答结束时的一个标量，它也可以汇总正确性、格式等多个分量。多轮训练增加了放置奖励的位置：任务完成时给终局奖励，达到子目标时给步级奖励，其余步骤为零。只保留终局评分，早期行动通过最终结果获得学习信号；加入中间评分，可以让部分进展成为学习信号，同时把“什么算进展”的判断写进了目标。若某项子奖励可以反复领取，策略就可能靠重复操作累积回报。因而组合奖励还包含触发次数、权重与终止条件：这些设置会改变什么行为更值得学习。[R1，§2.2.2](https://arxiv.org/html/2501.12948v1#S2.SS2.SSS2)；[Environment Scaling，§4](https://arxiv.org/html/2511.09586v3#S4)

奖励密度是设计选择。Search-R1 的多轮搜索只用最终答案的精确匹配奖励。[Search-R1，§3.4](https://arxiv.org/html/2503.09516v5#S3.SS4) 《Practitioner's Guide》在 TextWorld 的 tw-simple、Qwen-7B、3000 回合设置下比较三档密度：PPO 从稀疏的 41% 降到中等密度的 29%，再到最密一档的 58%；RLOO 从 35% 升到 55%，并在两档稠密配置下都停在 55%。同一份中间信号在两个算法上给出相反方向，论文据此把奖励密度与优化策略的匹配列为结论。[§7.1、表 11](https://arxiv.org/html/2510.01132v2#S7)

**奖励规定哪些结果值得获得；信用分配决定哪些历史决策因此被强化。** 单轮里，整条回答共享终局任务评分。REINFORCE 可以让全段 token 使用同一个回报因子，各 token 的概率梯度仍然不同；PPO 则可利用前缀价值估计形成不同优势。由此，共享奖励与逐 token 更新可以同时成立。[RLOO，§2](https://arxiv.org/html/2402.14740v1#S2)

多轮轨迹又多了一层归属：最终结果应归到哪次决策、哪轮调用，再归到其中哪些 token。以一个说明性修复任务为例，前几轮可能正确定位了文件，后面一次写入才破坏了程序；整条失败轨迹共享惩罚，会把有用检索与错误修改混在一起。部分可观测进一步增加了判断难度：同样一段查询结果可能对应不同数据库状态，某步的作用也可能直到后续执行才显现。价值估计于是需要处理历史信息，比较替代动作还可能需要恢复中间状态并重新执行。[Credit Assignment，§2.2、§4](https://arxiv.org/html/2604.09459v1#S4)

信息获取本身也有信用。一次查询可能暂时没有推进任务，却排除了错误路径；事后看似多余的检查，在当时信息不足时可能合理。评价某轮决策，需要把它当时可见的上下文和后续才揭示的信息区分开，才能识别决策失误、信息缺口与必要探索。这也是仅靠终局结果反推步骤质量的难处。[Credit Assignment，§4.2](https://arxiv.org/html/2604.09459v1#S4.SS2)

现有实现对这层困难给出了不同简化。上一代多轮 GRPO 把整条轨迹拼成一次输入，用损失屏蔽排除环境返回的 token，让一次任务对应一个任务级回报。Agent Lightning 改以 transition 为训练单位：每条轨迹拆成若干次模型调用，当前实现把同一个最终回报赋给每次调用，再交给单轮算法；更细的高层价值估计留作扩展。[§3.3、图 3](https://arxiv.org/html/2508.03680v1#S3.SS3) 屏蔽能区分 token 由谁生成，信用分配要回答的则是某次行动对最终回报贡献多少。

## 环境既生产训练数据，也约束探索

静态偏好数据可用于训练奖励模型或直接做 DPO；进入 PPO、GRPO 阶段后，回答也会随当前策略在线采样。Agentic RL 新增的是环境参与的数据生成：相同初始任务下，策略选择不同动作，就会遇到不同观测、走到不同状态，产生不同后续训练样本。[InstructGPT，§3.2、§3.5](https://arxiv.org/pdf/2203.02155)；[R1，§2.2.1](https://arxiv.org/html/2501.12948v1#S2.SS2.SSS1)

Environment Scaling 用“任务生成—执行—反馈”描述这一循环：环境提供任务与初态，执行动作并返回观测，最后提供训练反馈。数据生产能力因此包含了任务分布、可执行动作和评价器。[§1、附录 A.3](https://arxiv.org/html/2511.09586v3)

软件任务体现了这种约束。SWE-Gym 为问题配套可执行仓库、依赖与测试，任务说明只是其中一部分；OSWorld 用虚拟机隔离桌面操作，并通过快照恢复初态。[SWE-Gym，§3.1](https://arxiv.org/html/2412.21139v2#S3.SS1)；[OSWorld，§2.2](https://arxiv.org/html/2404.07972v2#S2.SS2) 据此，扩大采样量还意味着复制环境、恢复状态和执行检查。同题多次尝试需要保持可比较的起点，失败尝试也消耗运行时间；外部服务限额、初始化速度和重置能力共同约束可承担的探索量。

重置粒度还决定能进行什么比较。从初态重跑，会得到另一整条轨迹；从中间状态分叉，才能比较该处不同后续选择的回报。后一种采样需要恢复相关文件、进程或数据库状态，对话历史只是恢复条件的一部分。环境能否保存这些状态，直接影响可采用的信用估计方法及其成本。[Credit Assignment，§4.1](https://arxiv.org/html/2604.09459v1#S4.SS1)

## 多轮 rollout 把训练变成混合负载

单轮闭环以生成回答、评分、更新为主；多轮 rollout，即执行策略以采集轨迹，需要反复穿过模型生成、环境执行和反馈。RollArt 将负载拆成计算密集的 prefill、受显存带宽约束的 decoding、偏 CPU 的环境执行，以及突发的奖励评估。长历史增加上下文处理量，工具运行与测试又有各自的耗时分布。[RollArt，§2–3](https://arxiv.org/html/2512.22560v2#S2)

同步批次会被最慢的轨迹拖住：别的样本已经完成，仍需等待某个测试或环境返回。按轨迹独立调度、完成即评分，可以减少这类等待；训练与采样进一步异步后，训练器会收到旧策略生成的数据，需要管理权重版本和样本陈旧度。verl 的完全异步实现为此分离 Trainer 与 Rollouter，并提供陈旧度阈值。[RollArt，§4、§6](https://arxiv.org/html/2512.22560v2#S4)；[verl Fully Async](https://verl.readthedocs.io/en/latest/advance/fully_async.html)

这里新增的工程负担来自有状态执行：沙箱保存每条轨迹的文件与进程状态，运行器处理超时和失败，调度器在环境等待与 GPU 工作之间衔接。环境副本、执行日志、奖励结果和策略版本要能对应起来，训练样本才有可解释的来源。[Agent Lightning，§3.4](https://arxiv.org/html/2508.03680v1#S3.SS4)；[RollArt，§6](https://arxiv.org/html/2512.22560v2#S6)

## 成功率要连同完成任务的代价一起读

单轮偏好对齐关心奖励模型分数与偏好胜率，RLVR 关心答案或测试通过率。交互任务还要验收行动留下的结果：τ-bench 比对回合结束时的数据库状态与标准终态，允许不同操作路径；OSWorld 用执行式评价器检查文件、应用状态等结果。[τ-bench，§3](https://arxiv.org/html/2406.12045v1#S3)；[OSWorld，§2.2.3](https://arxiv.org/html/2404.07972v2#S2.SS2.SSS3)

完成任务需要多少次交互，也会改变成功率的含义。OSWorld 把交互上限定在 15 步，并统计模型的步数分布；τ-bench 用 pass^k 衡量同一任务重复 k 次都成功的概率，gpt-4o 的平均成功率超过 60%，pass^8 降到 25% 以下，其成本分析给出每个任务 0.38 美元的 agent 费用与 0.23 美元的用户模拟费用。由这些评测结构可得，比较对象应是给定环境、工具、尝试次数和交互预算下的任务成功率，同时记录步数、token、时延或费用。失败轨迹与重试同样进入成本；用更多尝试换来的成功，会在这组指标里显现。[OSWorld，§4、附录 C.1、C.5](https://arxiv.org/html/2404.07972v2#A3.SS5)；[τ-bench，§5.1–5.2](https://arxiv.org/html/2406.12045v1#S5.SS1)

两者的关系是扩展。Agentic RL 保留后训练 RL 的策略优化工具，把优化对象从一条回答换成一段交互轨迹，让行动、观测和后续决策接成闭环。得到的是利用外部反馈、操作环境和按执行结果修正的能力范围；付出的是跨步信用分配，以及能持续生产轨迹的环境工程。
