# Agentic RL 与一般后训练 RL：从回答评分到交互轨迹

单轮后训练的形状很好记：给一道题，模型把整段回答写完，评分器事后打分，梯度回传，这一局就结束。生成过程中模型不会因为自己"做了什么"而看到新东西，它看到的全部是自己刚写下的 token。

把工具调用、文件操作、网页浏览接进来，这条边界就断了。模型的一次输出被执行，环境状态随之改变，返回的观测成为下一轮的输入。下文讲的一切变化都是从这道断口长出来的：动作多了解析与执行这两层，一个终局分数要摊到更长的轨迹上，训练系统开始等环境，评测也不得不把步数和费用写进结论。

## 单轮的形状：一段回答就是一个动作

把整条回答当作一个动作，单轮训练就是上下文 bandit：策略看到题目这个"上下文"，选出一条回答，得到评分，任务结束。写成回合长度为一的退化马尔可夫决策过程（MDP）也可以。生成内部仍是逐 token 的顺序决策，前缀就是状态，所以"单步"指的是任务与环境交互的粒度，不是模型内部只做了一次选择。[RLOO，§2.1–2.3](https://arxiv.org/html/2402.14740v1#S2)

偏好对齐与可验证奖励都落在这个形状里，区别在评分依据。InstructGPT 先做监督微调，用人工比较训练奖励模型，再用 PPO 优化回答；DeepSeek-R1-Zero 用规则检查答案和格式，配 GRPO 训练；DPO 直接在离线偏好对上优化策略，省掉奖励模型和在线 RL 循环。[InstructGPT，§3](https://arxiv.org/pdf/2203.02155)；[R1，§2.2](https://arxiv.org/html/2501.12948v1#S2.SS2)；[DPO，§4](https://arxiv.org/html/2305.18290v3#S4) 奖励的来源换了三次，交互边界一次没动。

奖励放在哪里、优势按什么粒度估计，在这里已经是两个独立的选择。评分可以在回答结束时给一个标量，也可以汇总推理过程各步骤的评分；优势可以是整段一个数，也可以借前缀价值估计做到逐 token。DeepSeek-R1 的规则奖励只查最终答案与格式，而 PPO 在单轮里同样能用前缀价值算出每个 token 的优势——终局奖励不等于粗粒度信用。[R1，§2.2.2](https://arxiv.org/html/2501.12948v1#S2.SS2.SSS2)

## 工具一被执行，下一次输入就归环境管了

单轮模型输出一段代码，测试器可以在结束后给它打分；多轮模型直接运行代码，看到报错，再改一遍。前者优化一次提交，后者还要学会什么时候测、怎么用报错、何时停手。执行反馈进入了策略的下一次输入。

这些动作在模型侧仍然是 token，区别发生在执行语义：自由文本用于解释和推理，结构化调用经解析后触发查询、写文件或点击。复合动作还能由一串原始动作组成并递归嵌套，所以一次模型输出、一次工具调用、一个环境原子动作，可能是三套计数单位。[Landscape，§2.3](https://arxiv.org/html/2509.02547v5#S2.SS3)

网页和文件系统里，模型只看得到截图、查询结果或读出的文件，完整的环境状态还包含没有呈现给它的部分。这类任务用部分可观测马尔可夫决策过程（POMDP）描述更贴切：策略依据已有观测和行动历史决策，环境执行后给出下一次观测。[OSWorld，§2.1–2.4](https://arxiv.org/html/2404.07972v2#S2)

动作一多，有效性就成了新的门槛。调用必须能解析，参数必须能执行，返回结果要和对应动作对齐。格式错误会改变下一步能拿到的信息，环境超时可能直接把整条轨迹截断。[Agent Lightning，§3.4](https://arxiv.org/html/2508.03680v1#S3.SS4)

Search-R1 是这条循环最干净的样本。模型生成 `<search>` 查询，运行器暂停解码、调用检索器，把结果放回上下文，模型再决定继续查还是作答。语料可以是固定的，轨迹里可见的信息仍随查询而变；训练数据因此交错了"模型生成"和"外界返回"两类 token，策略损失只优化前者。[Search-R1，§3.1–3.3](https://arxiv.org/html/2503.09516v5#S3)

把上述差别归并，会得到两条可以交叉的轴。第一条是**环境交互**：生成过程中是否执行外部动作，让环境转移产生的观测进入后续决策。这里的观测由检索器、程序或界面返回，即使最终也是文本，它不由策略自回归采样。第二条是**优化跨度与信用粒度**：目标覆盖一条回答还是多次调用，奖励放在哪些位置，优势又按整段、按调用还是按 token 估计。[Landscape，§2](https://arxiv.org/html/2509.02547v5#S2)

| 比较层次 | 单轮基线 | 多轮 agentic |
| --- | --- | --- |
| 观测来源 | prompt 与已生成前缀，生成中没有外部观测 | 环境状态与可见观测分开，历史用于决策 |
| 动作与转移 | token 接续成完整回答，提交后本轮结束 | 输出经执行触发转移，返回观测后继续 |
| 优化跨度 | 一条回答，可展开到 token 或推理步骤 | 多次模型调用，各次又能展开到 token |
| 奖励位置 | 可只给终局评分，也可给步骤评分 | 可只给终局评分，也可给中间行动评分 |
| 信用粒度 | 可整段共享，也可估计逐 token 优势 | 跨调用归属加调用内 token 归属，实现常作简化 |

两条轴分开之后，几个常见的归类错误自己就散了。给单轮回答加过程监督或步级奖励，只要生成期间没有引入外部观测，它还在表的左侧；过程标签怎么转成 RL 奖励，是另一道设计题。反过来，Search-R1 明明多轮调用检索器，却只按最终答案给任务奖励，落在"有外部交互、只有终局奖励"这一格。[Search-R1，§3.4](https://arxiv.org/html/2503.09516v5#S3.SS4)

## 终局分数怎样落到每个 token 上

先看只有终局评分的单轮情形，这是理解信用分配的起点。设回答 $y$ 有 $N$ 个 token，生成第 $i$ 个 token 前的上下文为 $h_i=(x,y_{<i})$，整段回报为 $R$。由自回归概率的乘积展开，在暂不计 KL、折扣与基线的简化下，REINFORCE 的一个样本梯度是：

$$
g=R\nabla_\theta\log\pi_\theta(y\mid x)
 =R\sum_{i=1}^{N}\nabla_\theta\log\pi_\theta(y_i\mid h_i).
$$

共享的是标量 $R$，不共享的是每一项对数概率梯度：它取决于当时的前缀 $h_i$、采样到的 token $y_i$ 和模型参数。同一个回报乘在一串不同的梯度向量上，各 token 获得的更新贡献自然不同。但这只是"更新幅度不同"，还没有回答哪个 token 真的导致了成功。[RLOO，§2.1–2.3](https://arxiv.org/html/2402.14740v1#S2)

要回答后者，得减一个基线。PPO 常配价值网络 $V_\phi(h_i)$，用参数 $\phi$ 根据题目和已生成前缀预测此后继续生成的期望回报；优势的基本含义是"实际（或估计的）后续回报减去该前缀的预期回报"。取不折扣的蒙特卡洛回报时，可写成 $\hat A_i=R-V_\phi(h_i)$。$R$ 相同，各前缀的价值估计不同，优势就不同。实际训练多用广义优势估计（GAE），把各步奖励与相邻前缀的价值预测组合起来，再经裁剪更新策略。代价是价值网络本身的训练成本与估计误差，收益是优势终于带上了"这一步之后还有多少余地"的信息。[RLOO，§2.1–2.3](https://arxiv.org/html/2402.14740v1#S2)

关键在于，**逐 token 优势并不要求逐 token 的任务奖励**。奖励位置（结果在哪儿评）与信用粒度（功劳怎么摊）是两件事，这也解释了为什么单轮 RLVR 只用终局对错，照样能做 token 级更新。

多轮把这件事又拧紧一圈。最终结果先要归到哪次决策、哪轮调用，再归到其中哪些 token。设想一个修复任务：前几轮正确找到了文件，最后那次写入才把程序弄坏。整条失败轨迹共享一个惩罚，等于把有用检索和错误修改混在一起罚。部分可观测让判断更难——同一段查询结果在不同数据库状态下含义不同，某步的作用也可能要等后续执行才显形。要比较"当时换个动作会怎样"，还得把中间状态恢复出来重跑。[Credit Assignment，§2.2、§4](https://arxiv.org/html/2604.09459v1#S4)

信息获取本身也有信用问题。一次查询可能没推进任务，却排除了错误路径；事后看着多余的检查，在当时的信息条件下可能是合理的。衡量某轮决策，得把它当时可见的上下文和后来才揭示的信息分开，才分得清是决策失误、信息缺口，还是必要的探索。[Credit Assignment，§4.2](https://arxiv.org/html/2604.09459v1#S4.SS2)

现有系统给出了两种简化。一种把整条轨迹拼成一条训练序列，用损失屏蔽排除外部返回的 token，让一次任务对应一个任务级回报；Agent Lightning 在图 3 里把这两种做法并排摆出来，自己改用 transition 作训练单位：轨迹拆成多次模型调用，每个训练项包含当次输入、输出和分到的回报。它当前的实现把同一个最终回报赋给每次调用，再交给单轮算法，更细的高层价值估计留作扩展。[Agent Lightning，§3.3、图 3](https://arxiv.org/html/2508.03680v1#S3.SS3)

差别可以用对数概率的归属说清。拼接方式在一条长序列上计算模型生成位置的对数概率：检索结果这类环境 token 仍是后续生成的条件，只是不作为策略动作进入损失。拆分方式对每次调用计算"给定当次输入、生成当次输出"的对数概率：输入里的旧消息、摘要、工具结果都是条件，当前训练项只优化这次输出。前者处理一条序列中哪些 token 属于策略，后者处理多次调用如何各自成为一个训练项；回报怎么归属，两边都还要另行决定。

KL 约束也顺着这个分解走。若按参考策略做 KL，拼接方式在模型生成的位置、以相同前缀比较两个策略；拆分方式在每次调用的实际输入下比较输出分布。外部返回的文本不该被当成策略生成的动作去施加这项约束。只要拆分前后条件上下文一致、token 权重与归一化方式不变，拆开本身不改变这些对数概率项；一旦换用摘要或调整调用权重，条件或权重就变了，已经不是同一个目标。

代价落在两处。长序列保留完整历史，却要求一次训练塞下累积上下文；拆分能按调用分批、把输入压短，但每次都带完整历史就会重复处理前缀，单次输入也可能继续增长。压缩历史能减长度，同时可能丢掉后续决策需要的信息。所以拆分缓解的是"整条轨迹必须拼成一条序列"这个限制，没有解决回报粗糙——同一个终局回报仍赋给每次调用，有用检索和错误修改的贡献还是糊在一起。[Agent Lightning，§3.3.2](https://arxiv.org/html/2508.03680v1#S3.SS3)

奖励的疏密也在这个环节起作用，效果还取决于算法。Search-R1 的多轮搜索只用最终答案的精确匹配；《Practitioner's Guide》在 TextWorld 的 tw-simple、Qwen-7B、3000 回合设置下比较了三档密度：RLOO 从稀疏的 35% 升到 55%，在两档稠密配置下都停在 55%；PPO 却先从 41% 掉到 29%，到最密一档才回到 58%（原文没有解释这次下跌）。同一份中间信号在两个算法上方向相反，说明加密奖励能否奏效，取决于它和价值基线、更新裁剪方式怎么配合，而不是单调地越密越好。[Search-R1，§3.4](https://arxiv.org/html/2503.09516v5#S3.SS4)；[§7.1、表 11](https://arxiv.org/html/2510.01132v2#S7)

RLOO 在这个对比里用的是留一基线：对同一输入采样多个输出，更新其中一个时，用其余输出的平均回报作基线，从它的回报里减掉，这样比较的是它相对同组样本的表现，不必另学价值网络。[RLOO，§2.3](https://arxiv.org/html/2402.14740v1#S2.SS3)

## 环境既是数据来源，也是采样瓶颈

信用估计依赖采样出的轨迹，比较替代动作依赖状态恢复，这两件事把环境从"任务场地"变成了训练方法的组成部分。静态偏好数据可以拿去训奖励模型或直接做 DPO；进到 PPO、GRPO 阶段，回答已经随当前策略在线采样。agentic RL 又多了一层：相同初始任务下，策略选不同动作会遇到不同观测、走到不同状态，产生完全不同的后续训练样本。[InstructGPT，§3.2、§3.5](https://arxiv.org/pdf/2203.02155)；[R1，§2.2.1](https://arxiv.org/html/2501.12948v1#S2.SS2.SSS1)

Environment Scaling 把这一循环写成"任务生成—执行—反馈"：环境给任务和初态，执行动作返回观测，最后给出训练反馈。数据生产能力因此包含三样东西：任务分布、可执行动作、评价器。[§1、附录 A.3](https://arxiv.org/html/2511.09586v3)

软件任务把约束显出来。SWE-Gym 为每个问题配好可执行仓库、依赖和测试，任务说明只是其中一部分；OSWorld 用虚拟机隔离桌面操作，靠快照回到初态。[SWE-Gym，§3.1](https://arxiv.org/html/2412.21139v2#S3.SS1)；[OSWorld，§2.2](https://arxiv.org/html/2404.07972v2#S2.SS2) 于是扩大采样量等于复制环境、恢复状态、执行检查三件事一起放大；同题多次尝试要保持可比的起点，失败尝试同样消耗运行时间；外部服务限流、初始化速度、重置能力，共同封住了可承担的探索量。

重置的粒度还决定能做什么比较。从初态重跑，得到的是另一整条轨迹；从中间状态分叉，才能比较该处不同后续选择的回报。后者要恢复文件、进程或数据库状态，对话历史只是恢复条件的一部分。环境存不存得住这些状态，直接决定哪种信用估计方法可用、成本多高。[Credit Assignment，§4.1](https://arxiv.org/html/2604.09459v1#S4.SS1)

落到系统上，多轮 rollout 变成了混合负载。RollArt 把它拆成计算密集的 prefill、受显存带宽约束的 decoding、偏 CPU 的环境执行，以及突发的奖励评估；长历史抬高上下文处理量，工具运行和测试各有各的耗时分布。[RollArt，§2–3](https://arxiv.org/html/2512.22560v2#S2)

同步批次会被最慢的那条轨迹拖住：别的样本早完成了，还得等某个测试或环境返回。按轨迹独立调度、完成即评分可以削掉这段等待；训练与采样再异步，训练器就会收到旧策略生成的数据，于是要管权重版本和样本陈旧度。verl 的完全异步实现把 Trainer 与 Rollouter 拆开，并给出陈旧度阈值。[RollArt，§4、§6](https://arxiv.org/html/2512.22560v2#S4)；[verl Fully Async](https://verl.readthedocs.io/en/latest/advance/fully_async.html)

新增的工程负担来自"有状态执行"：沙箱要保存每条轨迹的文件与进程，运行器要处理超时和失败，调度器要在环境等待与 GPU 工作之间衔接，环境副本、执行日志、奖励结果、策略版本还得对得上，训练样本才有可解释的来源。[Agent Lightning，§3.4](https://arxiv.org/html/2508.03680v1#S3.SS4)；[RollArt，§6](https://arxiv.org/html/2512.22560v2#S6)

## 成功率要连同代价一起读

一条轨迹既烧生成算力又烧环境执行，评测就得同时说清完成了什么、花了多少。单轮偏好对齐看奖励模型分数和偏好胜率，RLVR 看答案或测试通过率；交互任务还要验收行动留下的结果——τ-bench 比对回合结束时的数据库状态与标准终态，允许不同操作路径；OSWorld 用执行式评价器检查文件与应用状态。[τ-bench，§3](https://arxiv.org/html/2406.12045v1#S3)；[OSWorld，§2.2.3](https://arxiv.org/html/2404.07972v2#S2.SS2.SSS3)

需要几次交互才完成，也会改变成功率的含义。OSWorld 把交互上限定在 15 步并统计步数分布；τ-bench 用 pass^k 衡量同一任务重复 k 次都成功的概率，gpt-4o 平均成功率超过 60%，pass^8 掉到 25% 以下，成本分析给出每个任务 0.38 美元的 agent 费用与 0.23 美元的用户模拟费用。[OSWorld，§4、附录 C.1、C.5](https://arxiv.org/html/2404.07972v2#A3.SS5)；[τ-bench，§5.1–5.2](https://arxiv.org/html/2406.12045v1#S5.SS1) 由此，可比的对象是"给定环境、工具、尝试次数和交互预算下的成功率"，同时列出步数、token、时延或费用；失败轨迹与重试也要进账，靠多试几次换来的成功会在这组指标里露出来。

## 两条轴上的位置，比"新旧"更能说明问题

把前面的工作放回两条轴，关系就具体了。InstructGPT 和 DeepSeek-R1-Zero 都站在"生成期间无外部观测、按整条回答评分"的位置，区别只在奖励来源和优势估计；给它们加回答内部的步级奖励或过程监督，改变的是反馈粒度，不会自动长出环境交互。Search-R1 把检索反馈接进多轮决策，却仍然只给终局任务奖励；《Practitioner's Guide》在多轮环境里进一步拿奖励密度做变量；Agent Lightning 改的是调用的训练组织方式，当前仍用跨调用共享终局回报的简化。

第一条轴带来的是能力范围：查资料、操作软件、按执行结果修正行动；代价落在动作有效性、环境恢复和混合负载上。第二条轴决定能否把长跨度的成败更准确地归给历史决策；细化它需要中间评分、价值估计或额外采样，也就要额外付钱。两件事不互为前提——更密的奖励不等于更强的交互能力，更长的轨迹也不等于更精细的信用分配。
