# Hermes 与 Codex 共用的研究工作区

以实际 checkout 根目录为工作目录；下列 `/home/ubuntu/seagull-llm` 仅是既有部署的示例。正文目的、规则强度与质量由 [写作总则](../writing/README.md) 维护；笔记与调研按本次任务选择体例。此文件维护协作、阶段回传、产物路径和权限，适用于 Hermes 委派及 Codex 独立写作。

## 技能与分工

项目自有技能位于 `.agents/skills/`，Hermes 通过 `skills.external_dirs` 读取同一路径。共享规则随仓库维护，第三方安装状态与本机专属技能见 [技能目录与项目适配](skills.md)。新会话读取新文件；已有会话应重新读取被修改的规范，不能只依赖旧摘要。

负责人先说明本次阅读任务：回答什么、读者已经知道什么、关键关系需要解释到哪里。概念解释、比较、证据综合和行动判断可以组合；陈述型或判断型只作目的概括，不限定章节形式。

按实际需要选技能，在方案中标明名称、用途和作用范围。例如：`seagull-research` 用于检索与综合，`humanizer-zh` 用于中文初稿表达修订。仅查阅了某个技能的文档时，写“参考”，不要声称已调用。技能目录、路径或运行工具不可用时，说明具体影响并使用可行方法。

默认先让 Codex 根据原始任务和项目文档独立完成材料判断、结构设计、初稿与修订。Hermes（包括使用 DeepSeek-flash 的路由端）负责保真交接、消息回传、反馈与权限边界，不预先替 Codex 写死章节、结论、语气或每段任务。只有用户指定或实际材料需要时才增加具体限制。

Hermes 可提出少量候选范文或提醒一个具体难点，标明是建议而非要求；不把整个技能展开成更长的执行 prompt。表达修订是可选步骤：有明确问题才改，好的段落可以不动。修改须保留事实、因果、不确定性及作者立场；涉及论证重构时交回写作者，而不是用“润色”悄悄改掉意图。需要多人取材时由最终作者整合，独立写作不强制拆分。

这种分工是待试写验证的默认方案，不是已证明某模型更优的结论。真实 Codex 独立稿、真实 Hermes 路由稿与可选修订稿应分别记录运行条件；没有运行 Hermes 或 DeepSeek 时，不把其他代理的模拟记为对照结果。质量以人工阅读决定，见 [重构试写与审阅](../writing/validation/README.md)。

### 本项目对上游规则的适配

按 [技能目录的项目适配](skills.md#本项目对上游规则的适配) 使用第三方技能。总则中的准确性和任务忠实性要求优先；技能提供方法，不另立全局章节、词表、篇幅或评分门槛。普通调研无需强制串行运行全部技能、建立 JSON 审批文件或启动多个 Agent。

## 阶段回传与反馈

本节是阶段交互的唯一维护位置。2026-11-15 用户确定的默认方式：**方案回传后可继续取材；初稿等反馈后再定稿发布。** 适用于需独立成文交付的笔记、报告、主题调研及影响主要论证的实质改写。即时答疑、校字、单处事实修正或规范维护按任务规模沟通，无需机械套用完整文章流程；用户另有明确要求时从其要求。

### 前期方案

在大规模取材或完整成文前，把可评议的方案返回发起任务的操作者。必要的初步查阅可以先做。方案简要交代原问题与理解、预设读者、范围、拟采用的解释或比较方式、关键待核实处，以及所选技能及用途。提纲、比较轴和预计篇幅是作者的暂定选择，明确区别于用户指定要求；不预填尚未证实的结论。

方案发出后可继续检索、阅读和证据整理；收到纠正时立即调整相关工作。重要范围或组织方式变化应再次说明，不等完成后才通知。方案不要求固定数量的章节、来源或字段，也不需要专门的批准文件。

### 初稿回传

初稿达到可通读状态且完成基本事实核查后，返回**实际初稿**，附简短说明：目前的主要回答、最需操作者判断的组织或深度问题、尚未核实且影响结论的内容。不能只发目录、状态、执行者总结或操作者无法访问的服务器路径。

在微信等渠道，用可读正文、分段消息、附件或操作者可访问的非公开预览交付，并标明同一版本。沿原任务渠道回复；不得为回传擅自向其他联系人或群组发送。初稿默认保存在 `.research/handoffs/<task>/draft.md` 等非公开工作目录，不先把未反馈稿推到公开网站来充当预览。

**回传初稿后停在等待反馈状态，不继续定稿、提交发布稿或部署。** 可以继续核查来源和准备修订依据；保持操作者收到的初稿可追溯，不悄悄覆盖该版本。消息送达、后台任务退出、内部审稿通过、等待时间经过，都不等于操作者已经反馈。

收到修改意见后落实并复读，再完成定稿；用户要求再看修订稿时继续回传等待。反馈已经明确允许继续时，不为每项编辑选择重复索取确认。若只有收件确认、反馈含义不清或要求暂缓，保持等待并说明需要明确的地方。用户明确免除初稿反馈环节时，记录本次例外及范围。

### 定稿与发布

负责人按 [成稿质量与试读](../writing/README.md#成稿质量与试读) 读实际正文，用自己的话回答原问题，再核对这份回答所依赖的前提、机制和证据能否从文章中找到。反馈应指向具体段落与缺失的关系；先核对原稿，再描述错误。把收到的反馈、重要修订、残留缺口及实际检查简记在任务目录即可，不要求另建评分表。

审稿和操作者反馈完成后，按 [发布流程](../writing/publishing.md) 做接入与技术检查。既有“每日调研自动提交推送”的授权继续适用于这一阶段，不能跳过初稿反馈。其他任务按已有授权范围执行，无授权时先准备好可审阅的本地结果。定稿路径、验证结果和实际发布状态如实返回。

## 路径一：Codex 独立执行

独立执行者自行承担方案回传、取材、初稿、等待反馈、修订与试读。例如任务可以是：

> 面向有机器学习基础的读者，比较 agentic RL 与常见单轮后训练设置。先说明拟选的比较范围及解释路线，再取材形成初稿。比较维度可随证据调整，解释共同基础与关键变化，引用靠近主张。初稿返回后等我反馈。本次仅本地交付。

只要求润色给定材料时保留任务范围；需要补证据或改变主张，说明理由与影响。正文组织由解释任务决定。

## 路径二：Hermes 委派给 Codex

使用 [任务模板](task-template.md) 写 `.research/handoffs/<唯一任务名>/task.md`，保留用户原话、后续反馈和适用约束。Hermes 先向操作者回传方案；委派明确本轮只到初稿，或明确这是收到反馈后的修订轮。不能把操作者反馈环节委派给后台 Agent 自行通过。

证据包是起点，明确哪些已阅读、哪些只是线索；执行者可纠正比较轴和结论。要求增加材料时说明待解决的问题，不以多找若干篇代替研究目标。所有交付路径使用绝对路径：初稿、证据摘要、审阅意见与 CLI 最后回复分别命名，不把它们都叫 `result.md`。

启动前用 `codex exec --help` 和 `codex login status` 核对 CLI 可用性。以下为首次初稿轮示例；先建立任务目录并填写 task.md，不覆盖已有日志：

```bash
project_root=/home/ubuntu/seagull-llm
run_dir="$project_root/.research/handoffs/example-task"
codex exec -C "$project_root" --sandbox workspace-write \
  -c 'web_search="live"' --json \
  --output-last-message "$run_dir/last-message.md" - \
  < "$run_dir/task.md" > "$run_dir/events.jsonl" 2> "$run_dir/stderr.log"
```

模型与推理强度沿用本次授权和可用配置，写在命令上时须准确；不修改全局配置。`web_search="live"` 表示请求启用检索，实际联网成功另行验证。默认保留沙箱与审批边界；失败时报告具体操作和错误。

命令结束后确认退出状态并打开正文和必要来源，`last-message.md` 仅为执行者最后回复。Hermes 可先修正明显事实问题，随后回传可读初稿并等反馈。较大的结构或论证修改交回作者，负责人直接编辑时记录重要改动并复读全文。同一文件同一时间只由一个执行者写入。

修订轮带上用户反馈与实际正文中的审读发现。需要续接时，从本任务事件日志取得准确 thread ID，查 `codex exec resume --help` 后恢复；并发任务不使用 `--last`。新一轮日志单独命名，保留已回传版本。任务目录中的交付与证据不要因“不应进入 Git”而删除；先明确文件角色，运行资料保持本地即可。

## 工具环境与执行边界

第三方技能安装和工具环境见 [技能目录](skills.md)。旧结构化任务按 [流水线契约](../.agents/skills/seagull-research/references/task-pipeline.md) 恢复，其内容绑定与程序验收继续有效，但不自动完成操作者反馈。无人值守定时任务只有在用户明确免除相应反馈环节时才可自动定稿发布。

Hermes 账户、网关、会话和运行状态仍位于 `/home/ubuntu/.hermes/`，项目规范维护不涉及凭据或消息服务迁移。本文件、任务模板、技能目录和项目自有技能随仓库版本化；个人状态、运行证据与第三方本机安装继续隔离。
