# 面向阅读目的的调研

任务路由见 [AGENTS.md](../../../AGENTS.md#任务分流)。写作目的、规则强度、证据和成稿标准以 [写作总则](../../../writing/README.md) 为主，组织方法见 [调研体例](../../../writing/research.md)。本技能负责检索、阅读和交接的方法，不另设章节、篇幅、公式或句式配额。

默认交付用户指定的文本或本地 Markdown。需要网站交付时才进入发布流程；轻量任务无需研究状态 JSON、来源计数或自动评分。

## 先确定需要建立的理解

明确本篇回答什么、写给谁、读者已经知道什么、哪些关系需要解释，以及材料与时间范围。用户已给出的要求直接沿用；未知且不影响推进时说明假设，不把合理的编辑选择都交回用户。

“陈述”“判断”可以概括用途，但不规定文章结构。用户要陈述主要差异时，围绕比较建立理解；用户要选型时，再依据目标和约束形成建议。初步分组和结论是可修订的工作假设，阅读发现分类不合适时调整，不为完成清单而保留错误对照。

以下是可组合的取材方向，不作为正文模板：

| 阅读任务 | 取材重点 | 综合工作的重点 |
| --- | --- | --- |
| 文献整理 | 主题范围、种子论文、前后向引用与版本关系 | 说明收录理由、工作联系与继续阅读的路径 |
| 领域知识汇报 | 教材或综述建立坐标，原始工作检验机制与进展 | 解释主要问题、路线及其关系 |
| 概念或机制解释 | 定义、直接出处、关键步骤、适用条件 | 展开最影响理解的关系，选择有作用的实例 |
| 方法比较或选型 | 对象的共同基础、比较层次、版本和实验条件 | 分清主要区别、可选设计与常见后果；选型另交代取舍 |
| 项目、数据集或基准介绍 | 官方资料、真实样本、接口与评价协议 | 按使用或理解需要交代输入、过程和结果 |
| 近期动态 | 原始发布、版本记录、事件时间 | 说明相对此前新增了什么，保留重要分歧 |

用户只要求候选方向或论文清单时，先交付候选及材料依据，不提前完成文章。涉及本站选题时查 `docs/research/catalog.json`，说明与已有文章的关系；必要背景可以复述，已有文章不应成为省略本篇关键推理的理由。用户只给定材料时先在其范围内处理，扩大检索取决于任务需要与授权。

## 阶段回传与技能选择

前期组织方案、初稿回传、反馈处理和发布授权统一按 [协作约定](../../../hermes/README.md#阶段回传与反馈) 执行：方案回传后可以继续取材，初稿须等操作者反馈后再定稿发布。旧自动发布授权与脚本状态不能替代反馈；不能等全部完成才告知操作者。

交接保留原问题、明确要求、当前假设和可修订的组织思路，使用 [任务备忘](../../../hermes/task-template.md)，不复制整套规范为新增硬要求。检索、学术写作与文风技能按 [技能选择与项目适配](../../../hermes/skills.md) 使用。在回传中标注实际使用的技能及用途；已安装、仅读取和实际使用分开陈述。`humanizer-zh`、`unslop-academic-writing` 等表达工具用于改进已有内容，不能替代证据与论证，也不要求串成固定流水线。

## 检索与证据

围绕必须回答的问题检索，边读边调整。综述、学术接口、搜索结果与引用链可用于发现材料；关键技术事实追到原始论文、官方文档、代码或数据。教程可辅助解释，社区原帖可提供有归属的经验；转载同一工作不构成独立验证。

保留关键来源的链接、实际阅读位置与影响结论的版本、日期和条件。标题与搜索摘要只作线索；仅取得摘要时，陈述范围限于其明确披露的内容。阅读记录按可恢复和可核查的需要保存，不要求逐源填 JSON。

遇到冲突，先核对术语、版本、评价对象、统计量和实验设置，再查看正文、表格、附录或勘误；不能预先规定某一种载体永远优先。保留决定趋势或比较结论的中间设置，避免只摘首尾数字掩盖非单调结果。若 HTML 缺失相关部分，改查 PDF 或其他官方版本。

必答内容已有可靠依据、重要分歧和缺口已交代时收束。时间与访问限制应说明其影响；来源篇数、语言比例和引用量不决定材料充分性。按总则如实区分文献结论、作者综合与待验证设想。

## 归纳与试读

按照 [调研体例](../../../writing/research.md) 组织论证，以 [写作总则](../../../writing/README.md) 的成稿标准审读。标题可以标对象、问题或结论；分节可沿概念依赖、机制、比较维度、工作或时间关系安排，取决于本篇需要。介绍材料时说明它对当前问题的作用，必要的连接、范围提醒和局部回顾应保留。

具体审读方法见 [可读的调研](references/readable-survey.md)。发现问题先核对实际正文，再指出位置、缺失的解释及修改目标；不能凭记忆描述稿件，也不因收到批评就把全部内容宣布为错。多人提供的材料须由最终作者统一概念、假设、符号和详略。

表达修订可使用 [affirmative-first-writing](../affirmative-first-writing/SKILL.md) 检查低信息的防御性表达。否定、转折、设问与澄清按语义作用判断，没有次数门槛。篇幅、公式、图表与实例由解释任务决定。

## 复现与测评类请求

先核实官方代码、权重、任务集和环境当前是否可获得，据此区分可完成评测、训练复现或机制验证的范围。计划交代影响结果可比性的版本、采样预算、模型与运行条件；实际执行后才报告结果。用户收窄范围时更新同一任务的目的与输出，不延续已排除的工作。

## 按需使用仓库工具

以下入口以仓库根目录为基准，仅在需要相应能力时读取：

- 持久化任务、结构化交接或恢复已有运行：[任务流水线契约](references/task-pipeline.md)。现有 CLI mode 是实现参数；在 scope/audience/delivery.requirements 记录实际交付目的，不虚构 CLI 模式。
- 已使用流水线的对象卡、样本和验收接口：[交付格式契约](references/delivery-contract.md)。其字段要求不推广为所有调研的正文结构。
- 固定来源订阅、旧日报流水线或站点接入的技术操作：[日报工具](references/daily.md)。普通主题调研不继承订阅来源、时间窗或去重范围。
- 近期论文候选与速览：[近期论文速览](references/paper-survey.md)。数量、分组、展开深度按用户目的和材料选择。
- 可选表达定位：`python3 .agents/skills/seagull-research/scripts/prose-scan.py <文章路径>` 只列标题、字符数和候选句式，命中数及零命中都不能证明内容质量。
- 网站接入与检查：[发布流程](../../../writing/publishing.md)。接入、构建、推送和线上可访问分别报告；已进入流水线的任务继续遵循其完整性检查。
