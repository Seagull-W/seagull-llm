# 论文与材料调研

目标只有一条：**用尽量简洁的篇幅，让读者一眼看懂核心要点。** 读完后，读者应能直接答出：要解决什么问题、核心做法是什么、关键证据支持到哪里。

不要把解读稿写成“防挑刺的审计报告”。做调研时务必核对原文，写文章时务必大刀阔斧做减法。

## 1. 锁定问题与检索选材

- **紧扣用户原话**，不要擅自把具体问题扩写成大综述。
- 用户给了论文或材料，直接深读这些材料及指定关注点；只给方向时，用**英文核心词**检索并选 **1–5 篇**最能解释核心问题或给出关键证据的代表作（原始论文、官方技术博客、源码或文档均可）。
- **检索与取全文入口**（命令行可联网时优先使用仓库统一工具 `python3 scripts/research-fetch.py`，受沙箱限网时用内置检索工具并如实说明阅读范围）：
  - 搜代表作：`search "<english keywords>"`（并行查 HF Papers / arXiv / Crossref / DBLP；配了 `OPENALEX_API_KEY` 或 `S2_API_KEY` 自动补全引用排序）；
  - 顺藤摸瓜：`citations <arxiv_id_or_doi>`（追锚点论文的参考文献与施引工作）；
  - 读论文原文：`read-paper <arxiv_id>` 先看章节目录与表清单，再用 `--section` / `--tables` 定向读；若 arXiv HTML 缺表格、公式或附录，切 `--source latex` 或 `--source pdf`；
  - 读博客/文档：`read-web <url>`；需要中文社区一手讨论时可按需用 `python3 scripts/zhihu-cli.py`。
- 每篇入选材料都要有明确用途，材料足以回答问题就停手。用户明确要求先看清单时，本轮只交付候选列表、出处与入选理由。

## 2. 核对底线与正文减法（内部核对 ≠ 全塞进正文）

**核对底线（调研时必须做）：**
- 摘要只用于筛选。写进正文的关键机制、核心数字与结论，必须定位到实际读过的正文章节、图表、推导或附录；只有摘要可读时如实标明。
- 不编造事实或引用。遇到明显归因漏洞（例如多项改动混在一起）或跨论文口径冲突时，核清原文再下判断。

**正文减法（成文时必须做）：**
- **只保留影响核心理解的内容**。常规超参、卡数/批大小、预印本页数/图表总数、与主线无关的旁支实验，直接删掉。
- **禁止逐段打免责补丁**。只有会**实质改变核心结论**的前提、局限或口径差异才写在结论旁；次要的实验条件、检索过程或版本备注如需留档，统一放进文末 `<details class="supplement">` 折叠块。
- 区分原文结论与作者归纳用自然语言即可，不必反复贴标签。

## 3. 结构编排与图表优先

- **首屏见主旨**：标题直接点破核心问题或核心结论；开篇导语（`.lead`）或首段用 2–4 句话给出直接答案，让读者 10 秒内抓住全文重点。
- **篇幅克制**：单篇精读或聚焦短调研默认控制在 **1,500–3,500 字**（复杂多篇对比可适当放宽，仍以一口气能读完为准）。每段只讲一个意思，避免 300 字以上的密排大段落。
- **先定内容，再用图表替文字省力**：
  - 方法流程、系统架构、思路分岔 → 优先画清晰的内联 SVG 示意图；
  - 多方法、多配置或关键实验对比 → 用紧凑表格（关键条件放表头或 `caption`，不在正文逐格复述）；
  - 核心结论或关键前提 → 全文少量使用 1–2 个 `.callout`，不要满屏加框；
  - 数学公式 → 只放影响理解的核心公式，紧邻解释关键符号。
- 在关键论断旁附角标引用，文末给出可跳转的原文出处。

## 4. HTML 交付与快速自检

- 默认交付可在浏览器直接离线打开的**独立 HTML**（用户另指定格式时按其要求）。
- 复制 [assets/article.html](assets/article.html) 作为底稿（已内置全部响应式与打印样式），改好 `<title>` 和正文内容；需要调用具体排版组件时，按需查阅 [references/research-html-guide.md](references/research-html-guide.md)。排版只服务于清晰呈现，不反过来规定章节数或强塞固定模块。
- **交付前做 4 项自检**：
  1. **10 秒测试**：只看标题、导语和第一张图/表，是否一眼明白核心答案？
  2. **减法通读**：删掉所有不影响理解的细节和重复免责句。
  3. **抽检事实**：抽查 3–5 处核心数字/机制，确认与原文一致、引用链接可跳转。
  4. **浏览器检查**：打开实际 HTML，确认窄屏下 SVG、表格、公式可读且无整页横向溢出。

初稿回传后停下等待用户反馈再定稿，协作与交接边界见 [Hermes/Codex 共用约定](../../../hermes/README.md)。仅在任务明确要求上线到网站时才使用 [发布流程](../../../writing/publishing.md)。
