# 论文与材料调研

核心目标：**用精炼、锋利的论断表达，配合高密度原论文配图与自绘信息图，让读者在浏览器里一眼看懂核心判断、关键机制与决定性消融证据。**

不要写成“防挑刺的审计报告”，也不要写成“把 Markdown 换个壳的平铺文字流”。调研时务必核对一手原文与图表，成文时务必论断先行、图文协同、发挥原生 HTML 的多维排版优势。

## 1. 锁定问题、检索选材与原图提取

- **紧扣用户原话**，不要擅自把具体问题扩写成大综述。
- 用户给了论文或材料，直接深读这些材料及指定关注点；只给方向时，用**英文核心词**检索并选 **1–5 篇**最能解释核心问题或给出决定性消融证据的代表作（原始论文、官方技术博客、源码或文档均可）。
- **检索、取全文与取原图入口**（命令行可联网时优先使用仓库统一工具 `python3 scripts/research-fetch.py`，受沙箱限网时用内置检索工具并如实说明阅读范围）：
  - 搜代表作：`search "<english keywords>"`（并行查 HF Papers / arXiv / Crossref / DBLP；配了 `OPENALEX_API_KEY` 或 `S2_API_KEY` 自动补全引用排序）；
  - 顺藤摸瓜：`citations <arxiv_id_or_doi>`（追锚点论文的参考文献与施引工作）；
  - 读论文原文：`read-paper <arxiv_id>` 先看章节目录与表清单，再用 `--section` / `--tables` 定向读；若 arXiv HTML 缺表格、公式或附录，切 `--source latex` 或 `--source pdf`；
  - **提取原论文关键配图**：`extract-figures <arxiv_id_or_pdf> --list` 索引所有图注与页码 → `--pages <页码> --dpi 180` 渲染整页供目视确认坐标 → `--crop "PAGE:x0,y0,x1,y1:filename.png" --dpi 300` 高精裁切关键实验曲线、相图或消融原图，并目视复核无裁切残缺；
  - 读博客/文档：`read-web <url>`；需要中文社区一手讨论时可按需用 `python3 scripts/zhihu-cli.py`。
- 每篇入选材料都要有明确用途，材料足以回答问题就停手。用户明确要求先看清单时，本轮只交付候选列表、出处与入选理由。

## 2. 核对底线与正文减法（内部核对 ≠ 全塞进正文）

**核对底线（调研时必须做）：**
- 摘要只用于筛选。写进正文的关键机制、核心数字、公式与结论，必须定位到实际读过的正文章节、图表、推导或附录；只有摘要可读时如实标明。
- 不编造事实或引用。遇到跨论文看似矛盾的实验现象（例如某篇蒸馏失败、另一篇剪枝蒸馏大胜），必须追查各自实验口径与前提，在正文中给出统一机制解释。

**正文减法（成文时必须做）：**
- **只保留影响核心判断的内容**。常规超参、卡数/批大小、预印本页数、与主线无关的旁支实验直接删掉。
- **禁止逐段打免责补丁**。只有会**实质改变核心结论**的前提、局限或口径差异才紧贴论断写出；次要实验口径、评测格式差异与未核实空白统一收进文末 `<details class="supplement">` 折叠块。

## 3. 论断驱动写作与原生 HTML 图表优先

摆脱“顺着论文实验线性转述”的 Markdown 思维，让页面结构本身替读者提炼主线：

- **首屏见主旨与判断看板**：
  - 标题直接点破核心问题或核心结论；开篇导语（`.lead`）用 2–4 句话亮明全文总判断；
  - 多问题或多维度调研优先在首屏放置 **2×2 核心论断看板（`.thesis-bento`）**，每个小节开头用 **`.thesis-banner`** 一句话先给判断与成立边界，再展开机制与消融证据。
- **宽画布配图 + 舒适行宽正文**：
  - 正文段落保持约 `70ch` 易读行宽、避免 300 字以上密排大段；图表看板、双图并排、视觉化表格与双栏对照卡则铺满 `920px` 画布，形成清晰的视觉节奏。
- **三类高密度图表协同（多用图省文字）**：
  1. **原论文高精配图 + 旁注精读（`.paper-studio` / `.paper-shot-pair`）**：关键实验曲线、消融阶梯、等高线相图或 Case 截图直接从原文 PDF 300 DPI 裁切，配 2–3 条结构化看图要点（看哪条线、关键拐点数字、机制推论），并挂接 `data-lightbox` 支持点击原图灯箱放大；
  2. **自绘信息图级内联 SVG（`.visual-card`）**：拒绝敷衍的“三个方框加箭头”。用于表达**对数演化光谱、参数/算力占比解剖、硬件缓存机制、条件×预算胜负相图**等跨论文综合洞察；连线文字加不透明底色防穿线，核验文字不超出边框且无重叠；
  3. **视觉化数据表格与轻量原生交互**：对比表使用 `.table-card` + 内嵌比例数据条（`.bar-track`）与涨跌徽章（`.delta-tag`），重要行高亮；正反机制分歧用 `.ab-grid` 双栏对照卡；涉及多场景选型或分步推演时，可按需使用零依赖的原生 `.decision-widget` 标签切换器。
- **数学公式与溯源**：核心公式使用原生 MathML（离线可直显；上线 VitePress 站内原生 HTML 时转为 `data-tex` 由 MathJax 静态编译），紧邻说明符号物理含义；关键论断附双向跳转角标 `<sup id="cite-N"><a href="#ref-N">[N]</a></sup>`。

## 4. HTML 交付与实机自检

- 默认交付可在浏览器直接离线打开的**独立原生 HTML**（配套原图放同目录 `./figures/`）。
- 复制 [assets/article.html](assets/article.html) 作为底稿（已内置全套看板、原图灯箱、信息图卡片、比例条表格、场景切换器、响应式与打印样式），按需查阅 [references/research-html-guide.md](references/research-html-guide.md)。
- **交付前做 4 项硬核自检**：
  1. **10 秒测试**：只看标题、首屏论断看板、每节 `.thesis-banner` 与关键图表，是否立刻明白核心观点与胜负边界？
  2. **事实与口径抽检**：抽查 3–5 处核心数字、曲线读数与公式，确认与原论文表/图完全一致，正反引用锚点零断链、无重复 `id`。
  3. **原图与 SVG 像素检视**：打开实际页面，确认所有裁切原图清晰无截断，自绘 SVG 无文字溢出或重叠。
  4. **桌面 + 390px 窄屏实机检查**：在浏览器确认桌面双栏与 390px 手机端均无横向溢出（`scrollWidth <= clientWidth`），灯箱放大与交互切换无运行时报错。

初稿回传后停下等待用户反馈再定稿。支持单执行者一口气完成，也支持串行分工（Codex 完成第 1–2 节与原图裁切产出 `research-notes.md` 与 `figures/`，再由 Antigravity CLI 完成第 3–4 节写作与 HTML 交付），协作边界见 [Hermes/Codex/Antigravity 协作约定](../../../hermes/README.md)。获得发布授权后，按 [发布流程](../../../writing/publishing.md#新增每日调研) 以站内原生 HTML（`contentFormat: html`）接入 `docs/research/`。
