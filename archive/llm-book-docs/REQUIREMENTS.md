## 1. 项目概述

### 1.1 项目目标

编写一份关于大语言模型（LLM）的介绍文档，以个人主页（网站）形式发布，兼顾可编辑性与美观度。文档旨在帮助零基础读者建立对大模型工作原理的严谨理解，同时为有志于垂类或私有化产品开发的读者提供基础知识储备。

### 1.2 产出物

| 产出物 | 格式 | 说明 |
|---|---|---|
| LLM 介绍文档 | Markdown 源文件 | 内容核心，可独立编辑 |
| 个人主页 | VitePress 生成的静态网站 | 渲染 Markdown，提供美观阅读体验与交互能力 |

### 1.3 设计原则

- **内容与展示解耦**：Markdown 为内容源，SSG 负责渲染，互不绑定
- **渐进式结构**：从直觉到严谨，从理解到实践，分层递进
- **客观严谨表述**：主体语言为教科书式严谨风格，类比作为辅助理解工具，不作为主体
- **公式可用**：在需要的地方使用数学公式，配文字解释，不裸抛公式
- **可扩展**：站点架构支持未来添加不同领域的笔记

## 4. 叙事风格规范

### 4.1 语言基调

- **客观严谨**：使用"本节介绍……""其工作方式如下……"等教科书式表述
- **避免口语化**：不使用"嘿""你知道吗""说白了"等聊天式语气
- **类比作为辅助**：类比出现在概念首次引入时，帮助建立直觉，但概念的定义和解释必须严谨独立

### 4.2 公式使用规范

- 公式出现在需要数学精确性的地方（如注意力机制、损失函数）
- 每个公式必须配文字解释：每个符号的含义、公式的直觉理解
- 公式使用 LaTeX 语法（VitePress 通过 KaTeX/MathJax 渲染）
- 不连续堆砌多个公式，每个公式之间用文字过渡

### 4.3 类比使用规范

- 一个概念最多用一个类比，避免类比堆叠造成混乱
- 类比使用后必须回到严谨表述："简而言之，注意力机制的核心操作是……"
- 不用类比替代定义

## 7. 部署与运维

### 7.1 部署流程

```
本地编写 Markdown → git push 到 GitHub → Cloudflare Pages 自动构建部署 → 线上更新
```

### 7.2 域名

- 初期使用 Cloudflare Pages 默认域名（`xxx.pages.dev`）
- 后续可绑定自定义域名

### 7.3 更新方式

- 内容更新：编辑 Markdown 文件 → git push → 自动部署
- 样式更新：修改 VitePress 配置/主题 → git push → 自动部署
- 新增笔记：添加 .md 文件 + 侧边栏配置 → git push → 自动部署
