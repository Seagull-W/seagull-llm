# 写作入口：目标、参考与作者判断

写作服务于具体的阅读目的：建立理解、查阅复用、综合证据或支持判断。
正文应使具备预设知识的人理解问题，追踪关键结论如何成立，并辨认适用条件与证据边界。
先确定本篇要回答什么、可以假定哪些知识、需要补足什么理解，再选择组织方式。
栏目提供内容背景与存放位置，不决定体裁；章节、篇幅、公式、图表和文风由本次阅读任务决定。

建立理解可以面向已有专业基础的读者。基础定义可以简略，支撑本篇主要结论的推理仍需展开。
数学解释交代条件与变形，工程解释交代过程与状态，文献分析交代证据与关系。

## 规则的强度与范围

| 性质 | 内容 | 执行方式 |
| --- | --- | --- |
| 跨类硬约束 | 任务忠实、准确性、证据与记录真实性、关键解释完整 | 所有正文遵守，见下节 |
| 默认写法 | 中性语气、标题与段落组织、例子与图表的使用、体例中的组织建议 | 根据阅读目的选择和调整，调整本身无需审批 |
| 任务专属要求 | 用户指定的读者、范围、长度、推导路线、布局、交付与回传方式 | 标明来源及适用任务，在该范围内执行 |

委派者提出的候选结构、比较轴和初步结论属于工作假设，核实后可以调整。
将一次任务的要求写入长期规范时，先核对其来源与适用范围。
参考资料的篇数、语言比例、公式密度、章节数和句式次数不作为通用质量门槛。

## 跨类硬规则

1. **忠实于原问题。** 保持比较对象、范围与交付目的清楚。必要的范围调整说明理由；
   将用户的明确要求与作者为完成任务作出的选择区分开。
2. **关键主张可追溯。** 基础理论优先教材和原始文献，技术接口优先官方文档，研究结论优先原始论文。
   引用靠近它支持的论断；自行推导给出可复核的步骤，作者综合与资料原有结论保持可辨认。
3. **对象、条件与符号明确。** 记号首次出现时定义，含义或作用域改变时重述。
   连续推导可共用定义，每式符号应能从邻近上下文确定；关键公式说明作用、条件和结果含义。
4. **数字附带比较条件。** 交代影响结论的任务、样本、版本、指标与评测方式。
   比较结果时核对口径；条件不同的结果保留差别。
5. **记录如实。** 数据、引用、命令、实验、阅读范围和检查结果据实际记录表述。
   未核实且影响结论的内容明确标出，说明缺口影响什么判断；说明性构造与真实实验区分。
6. **完成核心解释并实际试读。** 主要结论的依据与关键中间关系应足以追踪。
   按下文“成稿质量与试读”检查真实正文，修复影响任务完成的缺失和误解。

## 默认表达与篇幅

采用严肃、中性、精确的表达，以具体对象、过程和关系推进正文。
保留研究动机、步骤目的、概念引入理由、必要回扣与论证连接；它们可以使用完整的解释性段落。
删除空泛学习收益、无内容的导读、重复免责和虚构反方。人称、设问、转折或否定句按实际作用判断，
必要的事实更正、反证、方法对比与证据限制正常表达。

篇幅用于完成核心解释、推导或查阅任务。详略随难点分配，公式、代码、实例和图表按表达需要选择。

鼓励在有助于理解和查阅时多用图表和分层结构。数据比较、趋势和流程可以用表格、曲线图或流程图。
观点、论据和细节较多时，可以用分级标题或列表呈现主次与从属关系。按内容和阅读目的选用，纯文字讲得清楚时也可以直接写。

长文先检查层次与依赖，再决定拆篇；拆分后各篇有明确目的，并指出必要前置材料。

## 成稿质量与试读

这是各体例与技能共用的内容标准。负责人对照原始问题读实际成稿，用自己的话回答核心问题，
再检查这份回答是否能从正文及其证据中得到。以下是审阅问题，按本篇需要使用，不转成正文目录：

- 正文回答了什么，范围与比较对象是否前后一致？
- 关键结论依赖哪些前提，中间关系是否解释充分？
- 术语、公式和表格在出现处是否可理解，关键记号是否一致？
- 已使用的例子是否完成了它承担的说明，输入、过程与结果是否相连？
- 文献分别支持什么，事实、综合推断与设想是否可辨，条件和缺口是否清楚？
- 各节为何相邻，是否有重复、矛盾或游离于主线的材料？

发现问题时指出正文位置、具体缺失或错误及修订目标，并在修改后重读受影响的论证。
反馈和自检也须对照实际版本；不能凭印象声称稿件写过某项内容。
构建、引用数量、篇幅统计和文风扫描各有用途，内容是否成立仍由上述试读判断。

## 工作过程与正文

任务拆分、检索记录、证据清单、协作日志与检查记录服务于执行和追溯。
正文保留有助于理解、核实或复用的研究方法、来源范围与验证情况，按读者的问题组织。
多人材料由最终作者统一概念、符号、详略和顺序，处理重复、矛盾与缺失的连接。
面向操作者的前期组织方案、初稿回传和反馈处理，按 [阶段回传与反馈](../hermes/README.md#阶段回传与反馈) 执行。

## 按阅读困难选择方法

不要先把任务塞进“笔记/调研”二选一。先理解作者想让读者理解、记住、验证或决定什么，再选择有帮助的组织方式。科普、随笔、教程、论文解读、实验记录、评论和综述可以混合；栏目名只决定存放位置。

- 读者缺少直觉：可从现象、问题或具体对象进入，再逐步建立模型。
- 读者卡在推导：固定约定，展开关键变形，用小例子核对结果。
- 读者需要操作：围绕任务、状态变化和可观察结果安排步骤。
- 读者需要比较：按真实差异并列，或追踪争议与证据；不强造因果链。
- 作者要表达判断：让主张、理由和反例相互回应，不替作者制造中立姿态或行动建议。
- 读者需要查阅或选择资料：目录、卡片、表格和简短注释本身可以是完整交付。

短任务可以直接写。复杂稿件可按需参考[笔记方法](note.md)及[范文与方法](references/README.md)，借鉴适合本篇的解释方式。围绕论文选材成文时使用[仓库的论文调研入口](../AGENTS.md#论文调研)。

组织与文风由写作者掌握。用户原话优先于路由器的归纳；提纲、篇幅、比喻、起笔方式和候选范文都可以随材料调整。严肃中性是本站技术文的默认语气，不限制用户需要的口语、叙事、评论或其他声音。

## 冲突按职责仲裁

先核对用户当前明确要求及其范围，再按规则强度和职责定位。
总则维护跨类约束，体例提供特定对象的写作方法；格式或视觉示例中的文案不决定正文结构。
技能中的默认模板、配额或评分不能覆盖本项目的阅读目的与内容标准。
重复规定改为指针，独有细节保留在负责该问题的文件中。
