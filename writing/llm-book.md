# 科普书与入门教程体例

适用于面向零基础读者、供连续阅读的科普书与入门教程；类型判定见 [写作总则](./README.md)。
本书当前整体撤下公开站，由 `srcExclude` 排除构建；恢复发布需维护者明确决定。
学习地图、证据与论断、图与动画资源仍以 [LLM_BOOK_PLAN.md](../LLM_BOOK_PLAN.md) 为准。
本文件规定语气与组织；正文文件、公式、图注和组件按 [HTML_FORMATS.md](../HTML_FORMATS.md)。
跨类硬规则见 [写作总则](./README.md#跨类硬规则)，发布流程见 [发布指南](./publishing.md)。

## 1. 文风总纲

本书面向零基础的文科、医学等学科学生，写作目标是让外行听懂且理解准确。
文风以“严谨且亲和”为准：事实准确、逻辑自洽，用熟悉的事物切入，用“你”对话。
先解释具体机制，再给概念命名；用正常对话承载信息，保留必要的专业术语。

每段同时通过两项检查：

- 专业人士能够核对事实、逻辑和适用条件。
- 零基础读者能够跟随解释抓住核心，数学细节有清楚的选读入口。

## 2. 语气规范

### 2.1 用“你”对话，保持信息密度

直接进入有内容的交流，省去寒暄、故作神秘和夸张赞叹。

| 可采用 | 需要改写 |
|---|---|
| 如果你用过 ChatGPT、DeepSeek 或类似工具，可以从一次提问开始观察。 | 嘿，你知道 ChatGPT 吗？让我来告诉你一个神奇的东西。 |
| 把每一步说人话：先切成小块（Token），再把编号送入模型。 | 下面笔者将为您阐述 Token 化之要义。 |

### 2.2 适度口语，具体解释

“说人话”“泼一盆冷水”“嘴快”“光杆司令”等口语可以承载具体意思；使用后接事实与机制。
“泼一盆冷水”适用于确有证据的纠正，“嘴快”须说明所指的生成错误，避免拟人化替代解释。

| 可采用 | 需要改写 |
|---|---|
| 判断这个 agent 是否可靠，可以检查它调用了哪些工具、结果经过了哪些核验。 | 综上所述，吾人不可不对 agent 之局限性保持审慎之态度。 |
| harness（外部运行框架）接收模型的工具调用请求，执行工具并返回结果。 | 原生模型只能“说”，harness 让它能“做”。 |

### 2.3 明确框架，公平呈现争议

可以用“把它当研究助理”建立心智模型，并交代这个比喻对应的工作方式。
呈现开放争议时说明各方主张、证据和条件；框架可以有取舍，争议需要准确呈现。

## 3. 结构规范

### 3.1 先给地图，再逐层展开

每个主题先用一两段高层预览说明它在学习地图中的位置，再解释各部分关系。
每章以“本章导引”交代高层预览与学习所得；每节开头一句点明所解决的问题。

### 3.2 体验先行

优先从 ChatGPT、DeepSeek、体检报告、看病等熟悉的体验切入，随后用定义把直觉说精确。
涉及产品行为的例子写清观察对象；虚构的教学情境明确标注。

| 可采用 | 需要改写 |
|---|---|
| 使用流式显示时，你会看到回答逐步出现。接下来可以拆开看模型生成与界面显示各自做了什么。 | 开头直接给出语言模型的条件概率定义。 |

### 3.3 章节骨架

1. 第 N 章标题。
2. 本章导引：高层预览与学习所得。
3. N.1 等正文小节：体验切入，逐层解释。
4. N.x〔深入·可选〕：形式化、公式及必要前提。
5. 本章小结：3–5 条要点。
6. 参考文献：支持本章论断的资料与进一步阅读。

导引与选读提示的呈现形式按正文格式规范处理。

## 4. 概念展开：四段式模板

重要概念采用“直觉解释 → 严谨定义 → 常见误解 → 你可以试试”的展开顺序。
四段按教学需要选用；直觉在定义之前。常见误解只在确有澄清价值时出现。
这套模板沿用旧稿中的 AI First Aid Kit 借鉴记录；具体借鉴出处尚未核实。

以“预测下一个词”为例，实际讲解时将“词”精确到 Token：

1. **直觉解释**：请你把“今天天气很___”补完整，可以接“好”。这个补全情境用于引出后续片段的预测。
2. **严谨定义**：对自回归文本模型，下一 Token 分布写作 `P(w_t | w_1,…,w_{t-1})`。其中 `w_t` 是第 `t` 个 Token，前面的 Token 构成条件，`P` 表示条件概率。
3. **常见误解**：区分“下一 Token”的计算单位与界面上的字；两者的对应取决于分词和显示方式。
4. **你可以试试**：观察所用产品的流式显示，并记录它按字、词还是较大片段刷新；生成机制再结合教材或实现文档核对。

## 5. 公式与类比规范

### 5.1 直觉在先，形式化在后

公式用于把已有直觉说精确。含公式的小节标题标注 `〔深入·可选〕`，开头说明“跳过不影响主线”。

| 可采用 | 需要改写 |
|---|---|
| 前面用补全解释了下一 Token 预测；选读部分进一步给出它的条件概率形式。 | 开篇直接列条件概率公式及推导。 |

### 5.2 类比建立直觉，定义收束含义

每个概念用一到两个类比，用完立即回到严谨表述。
给 Token 编号可比作发“身份证”；harness 可比作“外壳／脚手架”，随后解释对应的编号或运行职责。
类比的使用范围写在具体解释中，保证后续推理使用已经给出的定义。

### 5.3 用文字连接公式

按总则逐符号解释公式；连续两个公式之间用文字说明代入、变形或推导的关系。
主线保留直觉，选读部分提供形式化细节和返回主线的位置。

## 6. 规模感与阅读预期

### 6.1 用可感知的参照物说明量级

抽象量级可以换算为熟悉的参照物，换算同时列出原始量、单位和假设。
旧稿“4990 亿 token ≈ 86 万本《西游记》；每天读一本要 28.6 辈子”保留为待核验的换算素材。
使用前须核实 token 数的来源与统计口径，列出所用版本的字数、字与 token 的换算和“一辈子”的年数；核实前不作为正文事实。

### 6.2 每章说明阅读前提与选读范围

在合适处明确主线所需知识与可以跳过的部分，帮助读者安排阅读。

> 你可以先沿主线理解一次回答的生成过程。公式集中在选读部分，前面会先用日常语言解释它要表达的关系。

## 7. 图表与表格规范

- **Mermaid 流程图**：用于全景、数据流与决策流程；节点文字 ≤8 字，用日常语言，必要术语配简短解释。
- **节点示例**：“切成小块 Token”；“送入大脑 Transformer”应具体改写为“进入模型”，在图旁解释 Transformer。
- **表格**：用于短板与解法、评测与方向、开源与闭源等并列对照，比较条件写在对应项中。
- **图先于字**：适合用全景图呈现的关系先给图，再逐站解释；图与动画的资源选择按内容计划处理。

## 8. 一组完整对照

主题为“大模型为什么会出错（幻觉）”。下表中的病历情境是虚构教学例子。

| 维度 | 需要改写 | 本书风格 |
|---|---|---|
| 切入 | 幻觉源于自回归生成机制与训练目标的不一致。 | 假设你让它写一份病历，它列出一篇查不到的参考文献。核查这篇文献，就能观察一种生成错误。 |
| 解释 | 它本质在“猜下一个最可能的词”，不是在“查最正确的事实”。 | 自回归文本模型逐步计算下一 Token 的分布，再按解码规则选择输出；事实核验需要结合来源和任务另行检查。 |
| 类比 | 只给术语与公式，缺少可操作的理解方式。 | 把它当作可能犯错的研究助理：先看它提供了什么资料，再核对关键判断与来源是否相符。 |
| 收尾 | 幻觉为固有缺陷，难以根除；harness 管不住它的“嘴快”。 | harness 可以接入检索和校验工具；具体是否有效，要检查检索结果、引用对应关系和任务评测。 |

## 9. 交付检查与禁止事项

1. 体验和直觉先于定义与公式；含公式的小节有选读标记。
2. 用正常对话替换“笔者”“吾人”“综上所述”“之”等刻意书面腔，删去寒暄。
3. 每个类比之后有严谨表述，概念使用与定义一致。
4. 禁止事实错误与夸大，尤其是无条件的“大模型能理解世界”“已接近 AGI”等断言；证据按总则及内容计划核对。
5. 术语首次出现解释为日常语言，确保主线可连续阅读。
6. “本章导引”和“本章小结”齐全；全文按总则所链接的正面陈述技能完成修订。
