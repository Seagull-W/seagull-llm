# 知识笔记体例

适用于数学笔记、课程讲义、论文精读、工具与系统笔记。
使用对象是自己与同行，目标是回查定义、复用规则、核对推导和执行条件。
科普书与每日调研分别使用其体例；类型判定与跨类硬规则见 [写作总则](./README.md)。

## 1. 人称与元话语

正文采用无人称的陈述体，以概念、对象、条件和结论作句子主语。
正文不出现「你」「读者」「本节带你」「读完你能做到」「我们先来看看」。
直接陈述所研究的对象、采用的约定和适用范围。
开头不写导读钩子，也不解释「为什么这对你重要」。

确有提醒价值的内容写成条件式规范句，说明条件及其数学或工程后果。

| 教程式表达 | 笔记式表达 |
| --- | --- |
| 读者最容易记错的是矩阵转置。 | 当 `A` 非对称时，`(A+Aᵀ)` 不能化简为 `2A`。其中 `A` 为方阵，`Aᵀ` 为其转置。 |
| 我们先来看看这个算法怎么工作。 | 算法输入为样本与初始参数，以下按一次迭代给出更新顺序。 |

标题标明对象或结论；提醒放在对应条件旁，便于单独查用。

## 2. 组织顺序

正文按以下顺序展开，开头先钉死约定。

1. **符号与约定**：范围、对象类型、维度、布局、记号及依赖条件。
2. **定义**：所讨论对象的精确定义，与后续结论所需的假设。
3. **结论或规则**：先列可查用的结果，并紧邻写明适用条件与出处。
4. **推导或验证**：沿选定路线解释结果如何得到，标明每步所用性质。
5. **算例**：把规则用到一个完整的标准问题，给出最终结果。
6. **速查表**：在文末集中列出规则、条件和关键记号。
7. **参考文献**：列出正文使用的教材、原始论文、官方文档与其他来源。

工具与系统笔记中的「符号与约定」同时交代版本、环境、输入和状态。
其算例可用完整的标准操作说明输入、过程与结果；只有实际验证的结果才写成已验证。
论文精读、课程讲义和数学笔记共用这套顺序，不另设体例。

### 各类对象的材料

- 论文与项目：标题与来源、问题、方法、证据与结果、工程分析、适用边界及引用。
- RL：课程学习目标落实为所记录的对象和规则，保留算法与公式、配置和命令、实验结果与分析。
- 西湖 RL 与 CS336：保留概念、假设、推导、算法与课程资料；作业和实验记录实现、运行条件与结果。
- Rust：记录问题、概念和 API、代码示例、行为解释与速查；易错点清单按第 5 节作为可选材料处理。
- Linux：记录机制总览、基础概念、机制图、命令与限制、组合边界及速查表。

机制、比较、公式和图片紧邻相关解释；比较关系按并列关系表达，因果流水线须有相应依据。
由讲义导入时保留原有教材插图；源稿未附的插图不补造。

## 3. 方法路线

动笔前先检索同主题的成熟笔记两到三篇，中英文各半。
选两篇时各一篇；选三篇时两种语言都要覆盖，并说明多选一篇的用途。
只归纳材料的章节结构、定义顺序、推导路线和算例选择，不搬用句子。
记录来源，选定一条方法路线后全篇沿用，不并列教学两条路线。

矩阵求导可按下表安排检索，并据实际找到的材料确定整篇采用的方法。

| 检索对象 | 候选路线 | 结构检查 |
| --- | --- | --- |
| 中文笔记 | 微分法加迹技巧 | 是否先声明布局，再把微分整理为标准形并反读梯度 |
| 英文笔记 | 逐元素求导加雅可比 | 是否先定义分量、索引与雅可比布局，再建立链式法则 |

例如选定微分法后，把微分整理为 `df = tr(GᵀdX)`，据此反读 `G`。
其中 `f` 为标量函数，`X` 为矩阵变量，`dX` 为其微分，`G` 为与 `X` 同形的梯度，`tr` 表示迹，`ᵀ` 表示转置。
后续规则、推导和算例均沿用这一约定；其他路线仅在确有必要时以文献指针交代。

## 4. 公式与记号

开篇声明标量、向量、矩阵的写法，以及是否采用列向量约定。
矩阵和向量标注维度；首次出现的自定义记号立即定义。
会改变结果的布局约定必须在开篇固定，包括雅可比布局、梯度形状和批次所在轴。
一篇笔记中同一记号保持同一含义，换对象时另取记号或明确限定作用域。

每个公式后必须有一句符号说明，覆盖该式中的变量、算子和必要条件。
连续公式之间用文字说明所用性质、代入关系或变形目的。
推导中的转置、求和范围、维度变化和常数因子要能逐步核对。
结果式规则紧邻给出处；自行推导的规则给出可复核的推导。

## 5. 算例

算例选标准问题，例如最小二乘、softmax 交叉熵、两线性层。
每个算例先声明输入、参数、维度、目标函数与所用约定。
从问题定义起推到参数梯度，逐步展示规则如何应用。
若有多个参数，各参数的最终梯度都要给出，并核对其形状。

算例采用前文选定的路线与记号，不在中途切换布局或推导方法。
不造叙事型玩具模型，不设置「练习」或把核心推导留作练习。
数值自检脚本、常见错误清单属于可选的练习册内容，需要加入时先询问。

## 6. 篇幅与密度

单篇 3000–5000 字，保持较高的公式密度。
篇幅用于定义、条件、推导和完整算例；公式之间保留必要的解释。
主题超过单篇容量时，按独立查用对象拆篇，各篇写全所需约定。

图少而准，一般只留布局对照表与速查表。
确需机制图时，图用于表达正文难以简洁交代的关系，并与相关解释相邻。
速查表放在文末、参考文献之前，列出适用条件和所用布局。
表中的规则应能在正文找到定义、推导或来源。

## 7. 正文格式入口

正文落到 `name.html`，相邻 `name.md` 保存元数据，设置 `contentFormat: html` 并 include 对应 HTML。
数学使用 `data-tex`：行内为 `<span class="math-inline" data-tex="…">`，块级为 `<div class="math-block" data-tex="…">`。
HTML 正文不写裸 `$…$`，不贴公式图片。
上述文件对与公式标记的完整写法、转义、标题、图注和组件以 [HTML 正文格式](../HTML_FORMATS.md) 为准。
入口登记与验证步骤见 [发布流程](./publishing.md)。

## 8. 禁止项

- 教程腔、第二人称、学习收益承诺和带路式元话语。
- 设问句；需要说明的条件或结论直接写成陈述句。
- 「不是 X 而是 Y」式堆叠，以及为制造转折而设置的假想误解。
- 未经询问，将数值自检脚本、常见错误清单等练习册内容默认塞进正文。

必要的事实更正、数学反证和证据限制保留，并写清具体条件。
成稿按 [正面陈述检查](../.agents/skills/affirmative-first-writing/SKILL.md) 通读修订。

## 9. 交付自检

- [ ] 开头是符号、对象与约定，能直接定位适用范围。
- [ ] 布局、记号、维度和列向量约定已固定，全文一致。
- [ ] 每条结论都有出处或可复核的推导，适用条件完整。
- [ ] 算例从问题定义推到最终结果；求导算例已给齐参数梯度。
- [ ] 正文已清除第二人称、教程腔和带路式元话语。
- [ ] 文末速查表齐全，每个公式后的符号说明齐全。
